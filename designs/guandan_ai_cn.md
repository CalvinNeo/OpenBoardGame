# 掼蛋 AI 总体思路（中文）

## 1. 整体结构

当前这套掼蛋 AI 不是单一算法，而是一个分层系统：

- `game/guandan.py`
  负责规则、状态流转、出牌合法性、房间配置，以及 Bot 决策总入口。
- `game/guandan_ai.py`
  负责策略层，包括候选动作生成后的排序、启发式评分、MCTS、MiniMax、解释信息。
- `game/guandan_nn_train.py`
  负责神经网络训练、checkpoint 读写、bootstrap、自对弈与轻量搜索。

核心思想是：

1. 先生成一组“合法且尽量有意义”的候选动作。
2. 再根据不同模式，用启发式 / MCTS / MiniMax / NN 对这些候选动作打分。
3. 最后统一做合法性兜底和解释输出。

也就是说，AI 的强弱很大程度上先取决于“候选集质量”，然后才是“排序器质量”。


## 2. 当前支持的 Bot 模式

房间里目前支持三种模式：

- `auto`
  默认模式。中前期以启发式为底座，必要时用 MCTS 覆盖；残局切到 MiniMax。
- `heuristic`
  只使用启发式打分，适合调试和做策略对照。
- `nn`
  使用训练好的神经网络 checkpoint 对候选动作打分；如果 checkpoint 加载失败，则退回启发式。

当前 `auto` 仍然是主力模式。`nn` 更像实验路径，已经能用，但还没有完全接管整套搜索。


## 3. 运行时决策流程

Bot 每次出牌时，大致按下面流程工作：

1. 先处理强制动作。
   例如进贡、还供、下一局等，这些不是策略问题，而是规则动作。
2. 生成 `heuristic_action`。
   无论最终是不是用启发式，这一步都会先算出来，作为基线和兜底。
3. 根据模式选路径。
   - `nn`：让神经网络给候选动作打分。
   - `auto`：如果进入残局，优先用 MiniMax；否则在值得搜索时使用 MCTS。
   - `heuristic`：直接用启发式结果。
4. 对最终动作做合法化。
   如果某个搜索结果因为隐藏信息、候选变化或状态变化导致不合法，会自动回退到其他合法候选，而不是让 Bot 卡死。
5. 写入 `bot_explain`。
   UI 里看到的 “Bot Play Explanation” 就来自这里。

这个结构的意图很明确：先保证稳定，再争取强度。


## 4. 候选动作层是整套 AI 的基础

### 4.1 候选动作怎么来

Bot 不是在所有合法组合上暴力搜索，而是先构造一个较小的候选集：

- 单牌
- 对子 / 三张
- 葫芦
- 顺子
- 三连对
- 钢板
- 炸弹 / 同花顺 / 天王炸
- 特殊规则动作

如果当前手牌可以“一手出完”，也会把这个动作放进候选集。

### 4.2 候选层会做哪些筛选

候选生成以后，不会原样直接交给后续算法，而会再做一层“策略过滤”：

- 回牌时优先保留材料成本低的应对。
- 首发时优先保留结构更完整、后续更好走的出法。
- 在没有必要时，尽量过滤“纯炸压回去”这种过度动作。
- 对明显更差、且被同类动作支配的选项做裁剪。

最近修过的一个重要问题就是：`full_house` 的候选以前只会给每个三张主体配“最低对子”，导致很多合法更优的葫芦动作根本不会进入候选集。现在已经修复，候选集会枚举多个对子选择。

这件事很关键，因为：

- `heuristic` 依赖候选集；
- `auto` 里的 MCTS / MiniMax 也依赖候选集；
- `nn` 也是在候选集上做排序。

候选集缺动作，会同时污染三条路径。


## 5. 启发式层的总体思路

启发式不是简单地“牌大就出”，而是围绕以下几个目标打分：

- 团队名次目标
- 尽快出完手牌
- 尽量少破坏已有结构
- 保留关键控制牌
- 不要轻易浪费炸弹、王、百搭
- 在合适时机抢回主动权
- 尽量避免压队友、炸队友

### 5.1 状态价值

AI 会先评估“这手牌整体值多少钱”，主要包括：

- `team_finish`
  预测本队最终名次质量。当前倾向是：
  `1/2 > 1/3 > 1/4 > 2/3 > 2/4 > 3/4`
- `turn_efficiency`
  估计这手牌还需要多少轮能走完。
- `structure_credit`
  当前结构有多完整。
- `hand_strength`
  手牌本身的控制力与强度。
- `hand_pressure`
  手牌越多，压力越大。
- `control_stock`
  控制牌库存，如大单张、炸弹等。

### 5.2 动作增量价值

在某个具体动作上，再额外计算“这一步对结构和局势的影响”，常见项包括：

- `play_cards`
  一次走牌越多，一般越好。
- `shape_value`
  这手牌打出去后，整体牌型是否更顺。
- `plan_alignment`
  是否符合当前这手牌最合理的出完路径。
- `control_break_penalty`
  是否拆掉关键控制组。
- `response_material`
  这次应对用了多少材料。
- `special_response_overuse`
  是否过早使用王、百搭、特殊材料。
- `wild_penalty`
  百搭使用惩罚。
- `opp_block` / `opp_risk`
  对手被卡住的可能性，以及对手仍能接住的风险。
- `avoid_overtrick`
  队友领先时，避免无意义地压队友。
- `seize_tempo`
  是否能有效抢回主动权。

### 5.3 启发式的一个核心理念

它不是只看“当前能不能压住”，而是看“压住以后，整手牌是不是更好走”。

所以它会显式惩罚这些行为：

- 拆高价值对子、三张、炸弹去出低收益单牌
- 用百搭去凑本来没必要凑的结构
- 过早炸回主动权，但炸回来以后只能出弱单牌
- 队友已经领出或有机会控住时，自己硬去压队友


## 6. 团队协作与记牌信息

这套 AI 不是完全把掼蛋当单机博弈，而是显式考虑团队。

### 6.1 团队目标

它会通过 `team_finish_score` 评估“本队最终两名的组合名次”，而不是只追求自己个人名次。

### 6.2 队友协作

当前已经有一些显式机制：

- 队友领先时，避免无意义 overtrick
- 队友可能控住时，某些低价值接牌会让给队友
- 若对手在队友前面还要行动，会额外考虑“给对手让路”的风险

### 6.3 记牌与推断

当前状态里会持续记录：

- `seen_cards`
  已经明牌出现过的牌
- `pass_limits`
  某个玩家在某种牌型上已经 Pass 过，因此其上限可被部分推断

这些信息会被用于：

- 概率估计
- MCTS 的隐藏信息采样
- 判断对手是否大概率接不住

这还不是完整的贝叶斯记牌系统，但已经不是“完全无记忆”。


## 7. MCTS 的思路

### 7.1 什么时候用 MCTS

`auto` 模式不会每一步都跑 MCTS，而是先过门控：

- 当前是否处于中前期
- 候选数量是否在可控范围内
- 这一步是否真的值得搜索

原因很实际：掼蛋是隐藏信息游戏，分支太大，强行每步深搜会非常慢，而且收益不稳定。

### 7.2 MCTS 不是纯树搜，而是“轻量根部搜索”

当前实现更接近：

- 先取有限个 root candidate
- 对每个 candidate 做若干次 determinization 采样
- 每次采样后模拟对手回复与后续局面
- 用统计值 + 根节点启发式值混合打分

最终常见指标包括：

- `mcts_avg`
  采样平均值
- `mcts_std`
  波动
- `mcts_win_rate`
  采样中正收益比例
- `mcts_min` / `mcts_max`
  最差 / 最好样本
- `mcts_root_heuristic`
  根节点启发式评分
- `mcts_adjusted`
  把平均值、风险项、启发式混合后的最终分数

### 7.3 MCTS 如何处理隐藏信息

因为看不到别人手牌，所以不会直接在真实状态上搜，而是先做 `determinize`：

- 保留自己已知手牌
- 保留 `seen_cards`
- 利用 `pass_limits`
- 根据未知牌池与手牌数，把其余牌随机分配给其他玩家

因此当前 MCTS 更准确的理解是：

- “在若干个合理补全世界里，对候选动作做 Monte Carlo 评估”

而不是：

- “在完整真值世界里精确搜索”

### 7.4 MCTS 的一些工程优化

为了控制时延，当前实现还有这些优化：

- 只有一个候选时直接走 fast path
- 某些“显而易见应对”会直接提前返回
- 对高牌单张 + 炸弹这种典型场景有特殊快捷逻辑
- 当最佳动作分数领先优势持续稳定时，会 early stop

所以它不是一个学术上很“纯”的 MCTS，而是偏工程化、偏实时性的版本。


## 8. MiniMax 的思路

残局阶段，`auto` 会优先切到 MiniMax。

原因是：

- 总牌数变少时，隐藏信息影响减弱
- 分支宽度明显下降
- “谁先走完”比“长远结构经营”更重要

当前实现是：

- 先对隐藏信息做一次 determinization
- 在这个补全后的世界里进行 Alpha-Beta 剪枝的 MiniMax
- 候选动作数量受宽度限制
- 超时会回退到静态估值

换句话说，MiniMax 是残局里的“更硬”的求解器。


## 9. NN 模式的思路

### 9.1 运行时的 NN 模式

当前 `nn` 模式的工作方式比较直接：

1. 从 `assets/guandan/checkpoints` 里加载 checkpoint
2. 生成候选动作
3. 对每个候选动作打分
4. 默认取最高分动作
5. 如果配置了温度，也可以按概率采样

因此当前 `nn` 模式本质上是：

- “NN 排序器”

而不是：

- “NN 直接替代整套搜索”

### 9.2 当前 NN 还没有完全接管搜索

运行时的 `auto` 模式，主力仍是：

- 启发式
- MCTS
- MiniMax

神经网络目前更多是：

- 独立 `nn` 模式下的动作打分器
- 训练时自对弈搜索中的先验和价值模型


## 10. 神经网络训练的总体思路

当前训练脚本不是纯监督学习，也不是完整版 AlphaZero，而是一个折中方案。

### 10.1 训练分两段

第一段：bootstrap

- 用 `bot` / `heuristic` / `random` 作为 teacher 生成初始样本
- 这一步的目标是让模型先学会一个“能出牌”的基础版本

第二段：self-play

- 用当前模型继续自对弈
- 默认不是纯 greedy model，而是 `model_search`
- 即：用模型提供先验和叶子估值，再做轻量搜索

### 10.2 当前训练更像什么

更准确地说，当前训练属于：

- teacher bootstrap
- + search-reanalysis
- + NN-guided self-play

它已经具备“自我迭代增强”的框架，但还没到完整 AlphaZero 的程度。

### 10.3 当前模型学什么

模型同时学两件事：

- policy
  候选动作里应该偏向哪一个
- value
  当前状态从本方视角大概值多少钱

输入目前还是手工特征为主：

- `state_features`
- `action_features`

网络本体是一个小型 policy-value MLP，不是 Transformer，也不是卡牌 token 编码器。

### 10.4 训练标签从哪里来

当前标签来源不只是一条：

- teacher 选择
- 启发式候选分数
- 小规模搜索得到的 soft target
- 自对弈结果对应的 value target

自对弈阶段如果使用 `model_search`，policy target 更接近“搜索访问分布”，而不只是“最后选中的单个动作”。


## 11. 为什么当前系统不是“纯 NN”

原因主要有三个：

1. 掼蛋是强结构、强隐藏信息、强协作游戏。
   单靠一个小 MLP，很难立刻学到稳定高质量策略。
2. 现有启发式里已经有很多规则知识。
   这些规则虽然碎，但在很多局面里比弱模型更靠谱。
3. 工程上需要可解释、可控、可回退。
   纯 NN 一旦学偏，问题会更难定位。

所以当前路线是：

- 先让规则与搜索兜住底线
- 再逐步让 NN 在训练和搜索中占更大比重


## 12. 当前系统的优点

- 运行稳定，有统一合法化兜底
- 有显式的团队协作目标，不是单人贪心
- 有显式的理牌 / 结构保留思想
- MCTS 和 MiniMax 都做了时延控制
- 有 `bot_explain`，方便复盘错误 case
- 训练管线已经支持 cache、checkpoint、自对弈和 search target


## 13. 当前系统的主要局限

### 13.1 启发式仍然很碎

它现在已经积累了很多局部规则，能解决很多具体 case，但也意味着：

- 容易继续膨胀
- 不同规则之间可能相互打架
- 很难保证全局最优

### 13.2 MCTS 仍然受限于候选层和估值函数

如果候选集漏掉关键动作，MCTS 再搜也没用。
另外它的 leaf / root 混合评分，仍然高度依赖启发式价值函数。

### 13.3 NN 目前还偏弱

当前网络还存在这些问题：

- 输入表示偏手工
- teacher bias 仍然明显
- value target 还比较粗
- 还没有形成稳定 benchmark league

### 13.4 仍然不是完整 AlphaZero

当前训练已经有“自我对弈 + 搜索改进标签”的味道，但还没有做到：

- 更强的 card-aware 编码
- 运行时全面用 NN prior/value 驱动搜索
- 稳定的 checkpoint 对战评测体系


## 14. 一句话总结

当前这套掼蛋 AI 的核心思想可以概括成一句话：

先用高质量候选动作层缩小搜索空间，再用“启发式为底座、MCTS/MiniMax 做增强、NN 逐步接管”的方式，在实时性、稳定性和强度之间做工程折中。

如果继续往前走，最自然的方向不是继续无限加规则，而是：

- 保持候选层质量
- 用 benchmark 固化坏例子
- 提升 value / policy target 质量
- 逐步把 NN 真正接进搜索闭环
