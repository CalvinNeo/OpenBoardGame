# Gold Rush (gold_rush) Final Design Spec

## 1. Overview
Gold Rush is a turn-based card game about investing in mines (companies). Players place miner cards to gain investment tokens and place gold cards to grow mine value. At game end, each mine's gold value is divided among investors by token weight.

This spec finalizes implementation details for the backend and UI, including hand vs classic modes, 2-player mine reduction, scoring/tie-breakers, bot heuristics, and highlight rules.

## 2. Game Modes
- Modes: `hand` and `classic`.
- Default: `hand`.
- Hand Mode:
  - Each player starts with 3 cards in hand.
  - On turn: play 1 card, resolve, then draw 1 (if deck not empty).
- Classic Mode:
  - No hand. On turn: draw top card and resolve immediately.

Config:
- `mode`: string enum `"hand" | "classic"` (default `"hand"`).

## 3. Player Count
- Supported: 2-6 players.
- 2-player variant: use 3 mines only (remove Elephant and Donkey).
- 3-6 players: use all 5 mines.

## 4. Mines
Fixed mine order (IDs):
0. Lion (red)
1. Bear (brown)
2. Horse (blue)
3. Elephant (gray)
4. Donkey (green)

Each mine has:
- `miners`: list of miner cards placed (left side).
- `gold`: list of gold cards placed (right side).
- `tokens`: map of `player_id -> invested token count`.
- `max_gold_cards`: 6

For 2-player games, only mines with IDs 0,1,2 are created and used. Miner cards for removed mines are not included in the deck.

## 5. Deck Composition
Standard deck for 5 mines (100 cards total):
- Miner cards (50): 10 per mine suit.
- Gold cards (50):
  - $0 x10
  - $1 x10
  - $2 x10
  - $3 x8
  - $4 x6
  - $5 x4
  - $6 x2

For 2-player games (3 mines):
- Miner cards: 10 per remaining mine suit (30 total).
- Gold cards: same 50-card distribution.
- Total deck size: 80.

Card model:
- Miner: `{ type: "miner", mine_id: int }`
- Gold: `{ type: "gold", value: int }`

## 6. Tokens
- Each player starts with 3 ownership tokens (`tokens_available: 3`).
- Tokens can be stacked in the same mine (no per-mine limit).
- Tokens are spent permanently until scoring.

## 7. Turn Flow and Phases
Phases:
- `turn`: player selects/draws a card.
- `awaiting_invest`: miner was placed; player decides to invest or skip (if tokens available).
- `awaiting_gold_placement`: gold card must be placed into a non-full mine.
- `game_over`: scoring complete.

### 7.1 Hand Mode Flow
1. Player selects a card from hand (`play_card`).
2. Resolve the card:
   - Miner: place in mine's miners area; if tokens available, enter `awaiting_invest`.
   - Gold: if any mine has space, enter `awaiting_gold_placement`; otherwise burn the card and end turn.
3. If turn completes, draw 1 from deck (if deck not empty).
4. Advance to next player.
5. Endgame: after deck is empty, players keep taking turns until all hands are empty.

### 7.2 Classic Mode Flow
1. Player draws top card (`draw_card`).
2. Resolve the card as above.
3. No hand, no draw at end of turn.
4. Endgame: after last card is drawn and resolved, game ends immediately.

### 7.3 Full Mine Handling
If a gold card must be placed but all mines are full (6/6), the gold card is burned (removed from the game). Turn ends with no placement.

## 8. Actions and Legal Actions
Action types:
- `play_card` (hand mode)
  - `hand_index: int`
- `draw_card` (classic mode)
- `invest`
  - `invest: bool` (true to place token, false to decline)
- `place_gold`
  - `mine_id: int`
- `play_again` (when `game_over`)

Legal actions by phase:
- `turn`:
  - Hand mode: `play_card` for current player if hand not empty.
  - Classic mode: `draw_card` for current player if deck not empty.
- `awaiting_invest`:
  - `invest` for current player.
- `awaiting_gold_placement`:
  - `place_gold` for current player.
- `game_over`:
  - `play_again` for any player (optional UI control).

Notes:
- `play_card` and `draw_card` set `pending_card` and transition to the appropriate next phase.
- `invest` should only be offered if the player has available tokens.
- `place_gold` requires target mine with gold count < 6.

## 9. Scoring and Tie-Breaker
For each mine:
1. `Total_Gold = sum(gold.value)`
2. `Total_Tokens = sum(tokens_by_player)`
3. If `Total_Tokens == 0`: no one scores.
4. Otherwise: `Share = floor(Total_Gold / Total_Tokens)`
5. Each player gains `Share * tokens_in_mine`.
6. Remainder is discarded.

Tie-breaker:
1. Highest total score wins.
2. If tied, player with most unused tokens (`tokens_available`) wins.
3. If still tied, shared victory (multiple winners).

Endgame summary should include per-mine breakdown (total pot, token counts, share calculation, and player gains).

## 10. Bot Heuristics
### 10.1 Invest Decision (after miner)
Invest if:
- `tokens_available > 0` AND
- (`mine_total >= 4` OR `deck_count < 10`)

### 10.2 Gold Placement
Let `G` be gold value.
- If `G >= 3`:
  1. Prefer mine where bot has most tokens and is not full.
  2. Else prefer neutral (no tokens) non-full mine.
  3. Else any non-full mine.
- If `G < 3`:
  1. Prefer opponent-majority mine with gold count >= 4 (near full).
  2. Else prefer neutral non-full mine.
  3. Else any non-full mine.

### 10.3 Hand Card Selection (hand mode)
Heuristic order (best available):
1. High-value gold (>=3) if bot has a majority mine not full.
2. Miner card that satisfies the invest rule (Section 10.1).
3. Low-value gold (<3) that can be used to block an opponent-majority mine with gold count >= 4.
4. Otherwise, lowest-value gold; if none, any miner.

If multiple cards tie, pick the one with higher immediate mine total impact.

## 11. UI/UX
### 11.1 Layout
- Horizontal list of mines (ID order left to right).
- Each mine shows:
  - Miner count (left).
  - Token stacks by player (center).
  - Gold cards (right) with count (x/6) and total pot value.

### 11.2 Highlights (Gold Placement)
When player must place gold, highlight each non-full mine:
- Green (Safe): player has majority or exclusive tokens.
- Red (Danger): opponent has majority or exclusive tokens.
- Yellow (Contested): equal token counts.
- Gray (Neutral): no tokens.

Include an icon for color-blind support:
- Safe: "OK"
- Danger: "X"
- Contested: "="
- Neutral: "-"

### 11.3 Visibility
- Players only see their own hand cards.
- Others are shown as card backs or counts.
- Deck count is public.

### 11.4 Scoring Display
- In-game: show mine total pot only (no share math).
- Endgame: show detailed breakdown per mine (see Section 9).

## 12. Suggested Public View Payload
Recommended fields for `get_public_view`:
- `game_id`, `you`, `phase`, `current_turn`, `mode`, `deck_count`, `max_gold_cards`
- `players`: list of player meta + score + tokens_available + hand (only for viewer) + hand_count
- `mines`: list of mines with `id`, `name`, `miners_count`, `gold_count`, `gold_total`, `tokens_by_player`
- `pending_card` (if awaiting placement/invest)
- `legal_actions`
- `game_over`, `winner`, `score_breakdown`
