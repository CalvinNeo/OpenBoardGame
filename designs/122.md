# 122 · 奥地利大饭店（Grand Austria Hotel）

## 实现范围与依据

实现 2021 修订基础版、2–4 人、七轮完整对局，支持真人和机器人混合、观战、断线重连及现有房间存档。使用相同的标准酒店面与随机六张员工起手；日间非对称酒店、员工轮抽及 Let's Waltz 扩展不在本次范围。

规则依据：[Lookout 官方规则书](https://www.lookout-spiele.de/upload/en_grandaustriahotel.html_GAH_Retail21_Rules_152_EN_WEB.pdf)，并交叉核对 [Yucata 规则及卡牌参考](https://www.yucata.de/en/Rules/GrandAustria)。只录入卡牌的机制数据，界面使用原创 CSS 和 Emoji，不分发商业卡面、插画、字体。

## 规则与状态机

- 开局每人 10 克朗、四种餐点各一份、六张秘密员工牌。逆起始顺序免费选择一名客人，然后从左下角起按正交相邻规则准备三间房，支付各楼层费用。
- 每轮按人数投 10／12／14 颗共享骰，按点数分六组。每人两个回合，顺序为正序后倒序；轮末起始玩家顺移。
- 回合可先招揽至多一名客人（市场费用从左至右为 3／2／1／0／0），再取一颗骰执行主行动。行动强度为取走前的该组骰数；可付 1 克朗提升 1 点。六点骰付 1 克朗模拟其他行动，使用六点组的数量。
- ① 苹果卷／蛋糕（蛋糕不多于苹果卷）；② 葡萄酒／咖啡（咖啡不多于葡萄酒）；③ 按强度准备房间；④ 分配克朗与皇帝轨进度；⑤ 打出一名员工，强度抵扣费用。
- 新获得餐点可逐个免费分配给任意客人或留在厨房；已有厨房餐点每付 1 克朗最多送三份。明确区分新餐点与厨房存量，不自动消耗玩家储备。
- 附加行动可在招客及主行动前后进行：付费送餐、让已满足订单的客人入住、使用每轮员工、认领公共目标。红／蓝／黄客人须同色空房；绿客人可住任意颜色。
- 客人入住后得卡面分数及奖励；奖励选择逐项进入待处理队列，支持准备房间、额外入住、员工折扣、抽三选一、免费招客、追加骰子行动。奖励不可被跳过回合吞掉，也不能重复领取。
- Gizia 的追加行动在其他入住收益到账之后执行，不移走骰子、不允许付费强化，也不触发「取走特定骰子」员工。Operator 按皇帝轨位置的两倍计终局分；Staff Manager 可在三点主行动之前或之后雇用。这些采用官方修订版附录，避免混用旧版说明。
- 全组房间入住触发颜色奖励：蓝色按 1／2／3／4 间得 2／5／9／15 分；红色得 1／3／6／10 克朗；黄色前进 1／3／6／10 格。皇帝超出 13 的进度转分，克朗最多 20。
- Pass 仅可在尚未做任何行动时执行：保留未用回合，暂时退出当前轮转；其他人均完成或通过后，弃一骰并重投剩余骰，继续未完成顺序，直至用完回合或无骰。
- 第 3／5／7 轮依皇帝轨得分，再退 3／5／7 格；退后 ≥3 得奖励、1–2 中立、0 受惩罚。修订版先执行实物惩罚，无法足额执行才扣分。包含十二种皇帝事件与十二种公共目标。
- 每轮处理完所有事件进入 `round_end`，显示分数变化和日志；所有席位各自 Next Round 后继续。AI 自动确认，真人与掉线席位均不可被跳过。
- 第七轮结算后计算楼层入住分、员工终局分、剩余金币及厨房餐点分、每位未入住客人 −5 分。平分比较金币与厨房餐点总数，仍同分则共同获胜。

## 后端组织

- `game/grand_austria_hotel_data.py`：标准酒店房格／分组、皇帝轨、56 位客人、48 位员工、12 个目标、12 个皇帝事件、动作和配置 schema。
- `game/grand_austria_hotel.py`：规则权威端。`setup_guest → setup_rooms → turn → emperor → round_end → game_over`；`pending` 队列作为任意阶段内的奖励选择子状态。
- 兼容项目标准 `init_game / apply_action / get_legal_actions / get_public_view / bot_move / serialize / deserialize`。动作先验证后提交；非法动作不得改变状态。所有随机状态随存档保存，公开视图不包含种子、牌库顺序、其他人的员工手牌或私有选择。
- 注册目录、游戏标签、开发顺序、按需加载资源及游戏状态分发。公共改动只增加必要注册与隐私过滤，保留其他游戏的在途改动。

## AI

独立 `game/grand_austria_hotel_ai.py`，只接收自身公开视图，不读取内部牌库或对手手牌。分阶段决策：开局客人／房间匹配，优先完成订单与入住，计算相邻房间与组奖励，按下一次皇帝结算的时间安排进度，维持金币储备，考虑公共目标竞速和员工剩余回报轮数。处理所有奖励与惩罚选择，必要时 Pass；每次决策都返回当前合法动作，完整模拟验证 2／3／4 人七轮无卡死。

## 前端交互

遵守 `FRONTEND.md` 和 `designs/task40.md`。

- 独立 JS／CSS／HTML 模板，注册在 `static/game_assets.js`；首页只有空主容器与对话框占位。JS 使用 IIFE，公开接口加 `GrandAustria` 前缀。
- 暖米色纸面、酒红与黄铜色，公共骰池及客人队列置顶；个人酒店与三席咖啡厅紧邻，员工手牌可折叠。用 🍰 蛋糕、🥐 苹果卷、🍷 葡萄酒、☕ 咖啡、💰 克朗、👑 皇帝、⭐ 分数，以及 🔴／🔵／🟡／🟢 色标。
- 行动采用点选与确认；选客、员工、骰子、房间和奖励选择，在原区域显示半透明蒙版及 Recruit／Hire／Confirm 等确认按钮与 Cancel。卡片尺寸不足时覆盖所在卡牌区，蒙版自动撑开容器，避免压住相邻区域。点空白或 Esc 取消，不发送动作。
- 信息展示后的 Next Round 直接提交已读，不再二次确认。固定位置的 Pass、End Turn、送餐、Skip、收入厨房、Claim 和工具栏每轮员工按钮也直接执行；保留发送中的防重复点击和 Explain 拦截。需要选择具体卡牌、房间、餐点分配或骰子参数的操作才使用确认蒙版。
- 公共区显示 0–13 格声望／皇帝轨、各格结算分及所有玩家的编号棋子；桌面一行，手机两行。营业时底色预测下一次退格后的奖励／中立／惩罚，结算中不预测，轮末显示结算后区域。当前事件明确分列奖励与惩罚，另外两次事件可展开查看。
- 第 3／5／7 轮的回顾逐人显示原位置、退后位置、轨道得分、触发结果及实际资源增减；优惠、上限、付费免罚及连锁奖励均按真实结果记录，皇帝事件与终局计分分开。需要玩家选择时显示惩罚原因，选择全部完成后才生成最终结果。报告随存档保存，只包含公开资源数量，不暴露员工手牌身份。
- Help／Explain 使用项目共享的 `HelpBtn`／`ExplainBtn` ID 后缀，显示问号与放大镜图标，提供英文可访问名称；移动端 Explain 接入公共停靠栏。Help 集中讲规则；Explain 通过捕获事件禁用常规操作，并可解释 disabled 控件和具体卡牌，显示后退出，Esc 可取消。非交互图标支持 hover 和移动端点击三秒浮动提示。
- 员工手牌、已雇用员工、抽三选一及确认蒙版均显示彩色时机标签：每轮一次(🔁)、立即一次(⚡)、永久生效(∞)、终局计分(🏁)。每轮员工额外显示「本轮已用」，时机标签支持简短浮动说明；Help 与具体卡牌 Explain 同步说明生效时机。
- 点空白或 Esc 清除选择；弹窗支持 Esc／遮罩关闭，非游戏内容 UI 使用英文。手机采用自适应列和紧凑按钮，不横向溢出；日志限制高度并滚动。
- 已加载脚本应同步当前房间状态，切换游戏清理选择、提示和 Explain 模式。

## 验证计划

1. 单元测试覆盖骰组强度、六点与强化、餐点分配、房间相邻和颜色、员工触发、奖励队列、公共目标、重投与顺序、皇帝事件、七轮终局、私密视图、存档重放和非法动作原子性。
2. 固定种子 AI 自对弈，覆盖 2–4 人；验证每个动作合法、回合有界并能完成结算，改变不可见牌不改变当前 AI 决策。
3. 房间集成：注册、开局、机器人、观战及全员轮末确认。公共注册改动运行现有相关全局检查，并重新生成 `game/dev_order.json`。
4. 浏览器实际加载并检查桌面及手机布局、核心操作、Help／Explain、键盘退出与资源按需加载；保留截图用于复核。

## 实现与运行记录

已完成以上范围，游戏 ID 为 `grand_austria_hotel`，大厅名称为「奥地利大饭店」。进入房间后可添加机器人，与真人混合进行 2–4 人对局。

服务请使用 Python 3.9 以上版本，本次集成验证使用 Python 3.12。现有公共机器人调度使用 `asyncio.to_thread`，本机默认的 Python 3.8 无法执行该公共调度；游戏规则模块本身仍兼容 Python 3.8。

规则、卡牌奖励、皇帝事件及 AI 自对弈测试位于 `tests/test_grand_austria_hotel.py`；房间注册、私密视图、异步机器人调度与断线确认测试位于 `tests/test_grand_austria_hotel_integration.py`。固定种子覆盖 2／3／4 人各三局，从开局到七轮终局与存档恢复。

浏览器检查脚本为 `tests/grand_austria_hotel.browser.cjs`，使用本地 `8872` 端口，也可由 `ROOM_TEST_URL` 指定地址。检查真实双人开局和骰子操作、1280／768／393／320px 布局、Help、disabled 控件 Explain、Esc、奖励选择、轮末回顾、观战与触屏三秒提示。新增固定按钮单击提交与防重、四人同格声望轨、全部皇帝事件、实际奖励／惩罚／中立／免罚和待处理惩罚原因的验证。截图保存于忽略目录 `build/grand-austria-hotel/`。

本轮验证通过：28 项规则与 AI 测试、4 项房间集成测试，以及上述浏览器检查。皇帝报告测试覆盖上限后的实际收益、扣分替代、免罚、选择中途存档恢复、旧存档兼容及与终局分数分离。
