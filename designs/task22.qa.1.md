# 得分沙拉 (Point Salad) - 进阶实现细则与数据清单

## 1. 卡牌清单与数据分布 (Card Data Distribution)

全游戏共 **108** 张卡牌。
为了方便程序生成，我们不需要手动录入 108 行数据，而是理解**由“蔬菜背面”决定的“得分正面”分布逻辑**。
游戏中有 6 种蔬菜，每种蔬菜对应的 18 张卡牌，其正面（得分面）的分布模型是完全一致且对称的。

### 1.1 数据结构映射
你可以建立一个 ID `1-108` 的数据库，或者用 `(VeggieType, Index 0-17)` 来生成。
**每种蔬菜（例如：生菜 Lettuce）背面的 18 张卡，正面必定包含以下计分规则：**

| 数量 | 计分类型 | 逻辑描述 (伪代码) | 举例 (假设背面是生菜) |
| :--- | :--- | :--- | :--- |
| **3张** | **单类蔬菜权重** | `+2 / -1` 组合 | +2 生菜, -1 胡萝卜 <br> +2 生菜, -1 甜椒 <br> +2 生菜, -1 卷心菜 |
| **2张** | **双蔬菜组合** | `Sum(A, B)` | 每张生菜+1 & 每张番茄+1 <br> 每张生菜+1 & 每张洋葱+1 |
| **1张** | **三蔬菜组合** | `Sum(A, B, C)` | 生菜+1, 胡萝卜+1, 甜椒+1 |
| **2张** | **纯数量阈值** | `Flat Points` | 每 2 个生菜得 5 分 <br> 每 3 个生菜得 8 分 |
| **1张** | **成套收集** | `Set Collection` | 每套 (生菜+番茄+卷心菜) 得 8 分 |
| **2张** | **种类多样性** | `Variety` | 拥有 >=3 种蔬菜得 5 分 <br> 全套 6 种蔬菜得 12 分 |
| **2张** | **奇偶校验** | `Parity` | 生菜为偶数得 7 分 (奇数3分) <br> 生菜为奇数得 7 分 (偶数3分) |
| **1张** | **最少比较** | `Comparison (Fewest)` | 生菜最少得 7 分 (平局都得) |
| **1张** | **最多比较** | `Comparison (Most)` | 生菜最多得 10 分 (平局都得) |
| **3张** | **其他蔬菜相关** | `Cross-Veggie` | (这3张通常不涉及生菜本身，而是涉及其他蔬菜的计分，但在生菜牌组里平衡总数) <br> 例如：每2个胡萝卜5分 |

> **开发建议**：
> 不要试图寻找实体卡牌的精确一一对应（那个太乱且无必要），只需保证**每种蔬菜的 18 张牌覆盖了上述逻辑的平衡性**即可。
> 重要的是：**背面是 A 蔬菜的卡，正面通常会有关于 A 蔬菜的加分项（约占 70%），也会混杂一些通用分。**

## 2. 游戏初始化与抽牌 (Setup & Deck Construction)

### Q: 按人数抽牌的逻辑？
**A: 必须是“盲抽移除”。点数面不可控。**

* **规则**: 根据人数，从每种蔬菜的 18 张中，**随机**抽出 N 张（例如 4 人局抽 12 张）。
* **实现逻辑**:
    1.  创建 6 个临时列表，每个列表包含该种蔬菜的 18 张完整卡牌对象。
    2.  对每个列表进行 `Shuffle`。
    3.  从每个列表中 `Pop` 出 N 张卡。
    4.  将这 `6 * N` 张卡放入主牌堆。
    5.  **再次洗混主牌堆**。
    6.  将剩余的卡牌移出游戏（玩家不可见，这增加了游戏的推算难度）。

> **关键点**: 这意味着某局游戏中，可能“生菜最多得10分”这张卡根本就不在牌堆里。这保证了每局策略不同。

### Q: 初始 3 堆的拆分？
**A: 尽量均分，不要求严格顺序。**
* 将洗好的主牌堆切成大致相等的 3 份（例如 72 张牌切成 24, 24, 24）。
* 如果有余数（通常没有，因为 6 的倍数通常能被 3 整除），随意分配即可。
* **电子版实现**: 直接用 `Index 0-23`, `24-47`, `48-end` 切分数组即可。

## 3. 游戏动作细节 (Action B: Drafting Veggies)

### Q: 选牌限制（同行/同列）？
**A: 无限制。任意两张。**
* 玩家可以在 2x3 的网格（共 6 张）中，选取**任意 2 张**。
* 不需要相邻，不需要同行，不需要同列。
* **除了**: 如果该列对应的上方牌堆已空，且无法从其他牌堆补充（极端后期），导致该列空缺。

### Q: 某列只剩 1 张时的处理？
这是一个关键的逻辑陷阱。我们需要厘清**补充机制**和**拿取机制**。

1.  **正常情况**: 市场永远有 6 张卡。你拿走一张，立即从上面补充一张。你拿走两张，补充两张。
2.  **牌堆耗尽**: 当某列上方的牌堆 A 空了，该列出现空缺时，会从**最大的那个牌堆**拿牌来填补这个空缺。
3.  **游戏终局 (End Game)**:
    * 当所有 3 个牌堆都空了，无法再补充蔬菜市场。
    * 此时市场上的卡牌会越来越少（只减不增）。
    * **规则**: 玩家依然必须拿 **2 张**。
    * **例外**: 如果整个蔬菜市场（6个格子）总共**只剩下 1 张**卡牌。玩家只能拿这 **1 张**，然后回合结束（实际上游戏也随之结束）。

> **结论**: 只要市场上还有 >= 2 张牌，玩家就可以（且必须）拿任意 2 张。不存在“某列剩1张只能拿这1张”的规则，除非整个桌上只剩这一张。

## 4. 翻转得分卡 (Flipping Cards)

### Q: 翻转数量限制？
**A: 无限制 (Unlimited)。**
* **时机**: 在玩家自己的回合内（拿牌前、拿牌后均可）。
* **对象**: 必须是自己**之前回合**拿到手中的得分卡，或者是**本回合刚刚**拿到的得分卡。
* **操作**: 玩家可以将任意数量的得分卡翻转为蔬菜面。
* **策略**: 这是为了修正错误的策略。比如你拿了“最少洋葱”，结果发现拿不到洋葱了，就把它翻成洋葱蔬菜来凑数。

## 5. “最多/最少”类计分与平局 (Tie Breakers)

### Q: 平局怎么算？
**A: 所有并列第一/倒数第一的玩家都得满分。**

* **Most (最多)**:
    * 如果你是最多（或并列最多），得 10 分。
    * **特殊情况 (2人局/多人局)**: 如果你的数量是 **0**，你能参与“最多”的比较吗？
        * **官方FAQ**: 是的。如果所有人都是 0，所有人都得 10 分。（虽然这在策略上很蠢，但逻辑上成立）。
        * *注：有些房规要求 >0，但标准电子版通常实现为简单的 `Max()` 比较。建议实现为：`if my_count == max_count_of_all_players: score = 10`。*

* **Fewest (最少)**:
    * 如果你是最少（或并列最少），得 7 分。
    * **特殊情况**: 如果大家都有蔬菜，只有你是 0 个。你是最少吗？**是**，你得 7 分。
    * **特殊情况**: 如果所有人都是 0 个。所有人都得 7 分。

## 6. 电子版数据结构示例 (JSON Example)

为了更清晰地说明卡牌数据，以下是一个推荐的卡牌对象结构：

```typescript
type VeggieType = 'Lettuce' | 'Pepper' | 'Tomato' | 'Carrot' | 'Onion' | 'Cabbage';

interface Card {
  id: number;
  veggieSide: VeggieType; // 背面
  pointSide: ScoringRule; // 正面
}

interface ScoringRule {
  type: 'SIMPLE_WEIGHT' | 'SET' | 'VARIETY' | 'PARITY' | 'MOST' | 'FEWEST' | 'THRESHOLD';
  
  // 简单权重参数
  weights?: { [key in VeggieType]?: number }; // e.g., { Lettuce: 2, Carrot: -1 }
  
  // 成套/种类参数
  requiredSet?: VeggieType[]; // e.g., ['Lettuce', 'Tomato']
  pointsPerSet?: number;      // e.g., 5
  
  // 阈值/奇偶参数
  targetVeggie?: VeggieType;
  threshold?: number;         // e.g., 2 (for every 2 items)
  parityType?: 'EVEN' | 'ODD';
  
  // 比较类参数
  compareType?: 'MOST' | 'FEWEST';
  compareVeggie?: VeggieType;
  winPoints?: number;         // 10 or 7
}
```

### 计分函数伪代码 (Scoring Function)
```python
def calculate_score(player_hand, all_players_hands):
    total_score = 0
    
    # 1. 统计玩家的蔬菜 (包括翻转过来的)
    my_veggies = count_veggies(player_hand.veggie_cards)
    
    # 2. 遍历每一张得分卡
    for card in player_hand.point_cards:
        rule = card.pointSide
        
        if rule.type == 'SIMPLE_WEIGHT':
            for veg, weight in rule.weights.items():
                total_score += my_veggies[veg] * weight
                
        elif rule.type == 'MOST':
            my_count = my_veggies[rule.compareVeggie]
            max_val = max(p.veggie_counts[rule.compareVeggie] for p in all_players_hands)
            if my_count == max_val:
                total_score += rule.winPoints
                
        # ... 其他类型以此类推
        
    return total_score
```
