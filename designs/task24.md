# Game Design Document: Cyber-Pictures (Web Edition)

## 1. 游戏概述 (Game Overview)
**Cyber-Pictures** 是一款基于经典桌游机制改编的多人在线网页游戏。
* **核心体验**：玩家利用系统分配的**受限数字工具**（如像素点、字符、简单的线条）来重构一张复杂的照片，并猜测其他玩家的作品对应哪张照片。
* **平台**：Web (Desktop/Mobile)。
* **人数**：3 - 5 人。
* **时长**：约 15-20 分钟 (固定 5 轮)。

---

## 2. 游戏核心资产 (Core Assets)

### 2.1 图片矩阵 (The Matrix)
* **结构**：4行 x 4列 的网格。
* **坐标体系**：
    * 行：A, B, C, D
    * 列：1, 2, 3, 4
* **内容生成**：每局游戏开始时，系统从图库（如 Unsplash API）随机抽取 **16 张** 高清、内容差异化明显的照片填入网格。

### 2.2 工具池 (Tool Pool)
游戏包含 **5 种** 固定的数字工具。无论有多少玩家，这 5 种工具始终存在于系统中，并在玩家之间（或闲置区）轮转。

---

## 3. 数字工具组详细规格 (Digital Toolsets Specs)
*这是开发时的核心交互模块，每种工具对应不同的前端组件逻辑。*

### 🛠️ 工具 A：路径绘图器 (The Shoelaces)
* **组件类型**：`CanvasPath`
* **交互逻辑**：
    * **画布**：空白背景。
    * **输入**：鼠标点击或拖拽绘制线条。
    * **限制**：
        * 最多允许绘制 **2 条** 独立的路径（可以是直线或贝塞尔曲线）。
        * 线条必须是单色的（通常为黑色或白色）。
        * **不支持填充**，仅限线条勾勒轮廓。

### 🛠️ 工具 B：像素网格 (The Pixel Grid)
* **组件类型**：`GridSelector`
* **交互逻辑**：
    * **画布**：**3x3** 的固定网格。
    * **调色板**：9 种固定颜色（红、橙、黄、绿、蓝、紫、黑、白、褐）。
    * **输入**：点击网格中的格子，循环切换颜色或选中颜色后填充。
    * **限制**：
        * 必须填满所有 9 个格子，不能留空。
        * 极其低像素化的表达方式。

### 🛠️ 工具 C：图标组合 (The Icon Set)
* **组件类型**：`EmojiPicker`
* **交互逻辑**：
    * **资源库**：系统预设一组通用 Emoji 库（约 50-60 个基础图标，涵盖自然、物品、符号等）。
    * **输入**：拖拽图标到画布上，支持简单的位置摆放。
    * **限制**：
        * 画布上最少 **2 个**，最多 **5 个** 图标。
        * **不支持**旋转或缩放。
        * 侧重于通过“概念组合”来暗示图像内容。

### 🛠️ 工具 D：字母拼贴 (The AEIOU Collage)
* **组件类型**：`TextRotator`
* **交互逻辑**：
    * **资源库**：无限供应的 **A, E, I, O, U** 五个大写字母。
    * **输入**：
        * **拖拽**：将字母拖入画布。
        * **旋转**：点击字母可进行 **90度** 离散旋转（改变字母的几何语义，如 `A` -> `>`）。
        * **堆叠**：支持层级遮挡 (Z-index)。
    * **限制**：
        * 画布上最多存在 **10 个** 字母图元。
        * 利用字母的几何形状而非语言含义作画。

### 🛠️ 工具 E：几何堆叠 (The Shape Stacker)
* **组件类型**：`ShapeBuilder`
* **交互逻辑**：
    * **资源库**：6 种基础几何块（正方形、长方形、三角形、圆形、拱形、圆柱体俯视图）。
    * **输入**：
        * 拖拽形状到画布。
        * 支持 **360度** 自由旋转。
        * 支持位移和堆叠。
    * **限制**：
        * 只能使用这 6 种形状进行拼凑。
        * 模拟俯视角的物体构建。

## 4. 游戏流程逻辑 (Game Loop Logic)

### 阶段 0：初始化 (Setup)
1.  加载 16 张图片资源。
2.  建立玩家列表 `Players`。
3.  初始化工具分配状态 `Tool_Assignment = [0, 1, 2, 3, 4]`。

### 阶段 1：发牌 (Deal)
* **系统行为**：为每一位**活跃玩家**随机分配一个秘密坐标 `(Row, Col)`。
* **数据可见性**：
    * **Server**：记录所有人的目标 `Target_Map = { p1: "A1", p2: "C3", ... }`。
    * **Player Client**：只能看到自己的目标（例如 "你的目标是 B-3"）。
* **闲置处理**：如果玩家人数 < 5，未被玩家持有的工具**不分配**目标坐标。

### 阶段 2：创作 (Crafting Phase)
* **状态**：所有玩家同时进行。
* **玩家行为**：在 UI 上使用当前分配到的工具，针对目标图片进行创作。
* **数据提交**：玩家点击“完成”后，客户端将画布状态序列化为 JSON 发送给服务器。

### 阶段 3：竞猜 (Guessing Phase)
* **展示**：屏幕显示所有已提交的作品（隐藏作者名，仅标记为作品 #1, #2...）。
* **输入**：
    * 每位玩家必须为**除自己以外**的所有作品猜测坐标。
    * UI 提供下拉选择框或矩阵点击：范围 [A1] - [D4]。
* **同步**：等待所有玩家提交猜测后，自动进入下一阶段。

### 阶段 4：结算 (Scoring Phase)
* **计分算法**：
    1.  **猜测分 (Guess Points)**：玩家每猜对一副别人的图 -> **+1 分**。
    2.  **艺术家分 (Artist Points)**：玩家的图被别人猜对 -> **+1 分**（每有一个人猜对就加一分）。
* **展示**：公布本轮答案（Who drew What），展示本轮得分及总分榜。

### 阶段 5：轮换 (Rotation Phase)
* **核心逻辑**：
    * 工具池相对于玩家进行顺时针移动。
    * `Next_Tool_Index = (Current_Tool_Index + 1) % 5`
* **视觉效果**：前端显示工具图标发生移动，新工具入场。
* **循环检查**：
    * `Current_Round += 1`
    * 如果 `Current_Round <= 5`，回到 **阶段 1**。
    * 否则进入 **游戏结束**，展示最终胜者。

## 6. 特殊规则：人数不足 (Less than 5 Players)
* **场景**：例如 3 人局 (Player A, B, C)。
* **工具池**：依然维持 5 个工具 `[T0, T1, T2, T3, T4]`。
* **分配**：
    * Round 1: A->T0, B->T1, C->T2. (T3, T4 闲置)
    * Round 2: A->T4 (上轮闲置的), B->T0 (A传来的), C->T1 (B传来的).
* **处理**：闲置的工具在 UI 上不显示，也不参与创作和评分，仅在后台逻辑中参与轮换计算。
