# Design 14.1: AI 画物语 (AiDixit)

## 目标与范围
- 实现 3-8 人 AI 画物语（Dixit 变体）的完整回合流程、计分与胜负判定。
- 支持本地牌库目录 `.aidixit/` 的多牌库选择与组合；每局可勾选参与牌库。
- 前端提供：讲述者出题 + 手牌选择、出牌、投票、计分板、实时投票进度与回合结果回顾。
- 后端提供：牌库扫描、发牌/弃牌/补牌、轮换讲述者、bot 基础随机行为。

## 规则摘要（默认规则）
- P 人（3-8），每人起始手牌 6 张；讲述者按座位顺序轮换。
- 讲述者选择一张手牌并输入线索；其他玩家选一张最符合线索的牌。
- 全部出牌后混洗展示，非讲述者投票猜讲述者的牌；不能投自己出的牌。
- 计分：
  - **全对**：讲述者 0 分，其他玩家各 +2。
  - **全错**：讲述者 0 分，其他玩家各 +2；其出牌被投中则每票 +1。
  - **部分正确**：讲述者 +3；猜对者 +3；其出牌被投中则每票 +1。
- 清理：本轮用过的牌弃置；玩家补牌至 6 张（若牌堆耗尽则洗回弃牌，默认允许重洗）；轮换讲述者。
- 胜利：任意玩家达到 30 分；平分即平局。

## 配置与资源
- 牌库根目录：默认 `.aidixit/`（位于服务器）；每个子目录是一套牌库。
- 牌库文件：支持 `.png/.jpg/.jpeg/.webp`（MVP 可先支持前 3 种）。
- 新增 `game/assets/aidixit.json`（建议）：
  - `deck_root` (string, 默认 `.aidixit`)
  - `selected_decks` (string[])
  - `hand_size` (int, 默认 6)
  - `target_score` (int, 默认 30)
  - `reshuffle_discard` (bool, 默认 true)
  - `player_colors` (string[]，默认一组 8 色)
- 新增接口：`GET /api/aidixit/decks` 返回 `{decks:[{id,name,count}]}` 供大厅勾选。
- 卡图资源（必须对前端可访问）：
  - 采用 card API：`GET /api/aidixit/card?deck=...&file=...` 返回图片文件（需做路径白名单校验）。

## 数据模型

### CardRef
```
{
  "card_id": "deck_name/filename.jpg",
  "image_url": "/api/aidixit/card?deck=deck_name&file=filename.jpg"
}
```
`image_url` 必须指向服务端可访问的图片路径（card API）。

### Game State
- `players`: {player_id -> {score:int, hand:[card_id], color:str}}
- `player_meta`: {player_id -> {name, seat, is_bot}}
- `turn_order`: list[player_id]
- `storyteller_index`: int
- `round`: int
- `phase`: "story" | "submit" | "vote" | "game_over"
- `clue`: Optional[str]
- `story_card`: Optional[card_id]
- `submissions`: {player_id -> card_id}（含讲述者）
- `pool_cards`: list[card_id]（混洗后顺序固定）
- `votes`: {voter_id -> card_id}
- `deck`: list[card_id]
- `discard`: list[card_id]
- `last_result`: {case, correct_voters, vote_counts, scores_delta}
- `config`, `game_over`, `winner`

### last_result 示例
```
{
  "case": "partial",
  "storyteller_id": "...",
  "story_card": "deck/card_01.jpg",
  "correct_voters": ["p2", "p4"],
  "vote_counts": {"deck/card_01.jpg": 2, "deck/card_09.jpg": 1},
  "scores_delta": {"p1": 3, "p2": 4, "p3": 2}
}
```

## 回合流程
1. **初始化**：
   - 扫描牌库并按 `selected_decks` 组牌堆、洗牌；若卡数不足以发初始手牌则报错。
   - 每人发 `hand_size` 张，`storyteller_index=0`，`phase="story"`。
2. **讲述 (story)**：
   - 讲述者提交 `card_id + clue`。
   - 记录 `story_card`、`clue`，进入 `submit`。
3. **出牌 (submit)**：
   - 其他玩家各提交 1 张牌。
   - 全员提交后 `pool_cards = shuffle(submissions)`，进入 `vote`。
4. **投票 (vote)**：
   - 非讲述者投票；不能投自己出的牌。
   - 全员投票后计分、写入 `last_result`，并执行清理。
5. **清理 & 轮换**：
   - 弃掉 `pool_cards`，每人补牌到 `hand_size`（若 deck 为空，洗回 discard；默认允许重洗）。
   - 讲述者顺时针轮换，`round += 1`。
   - 若达到 `target_score` 则 `game_over`（平分即平局）。

## 计分算法（核心）
- 设 `Correct_Votes` = 投中讲述者牌的票数，`Total_Guessers = P-1`。
- **全对**：
  - 讲述者 +0；其余玩家 +2；不额外计混淆票。
- **全错**：
  - 讲述者 +0；其余玩家 +2；非讲述者的牌每得 1 票，额外 +1。
- **部分正确**：
  - 讲述者 +3；猜对者 +3；非讲述者的牌每得 1 票，额外 +1。

## Actions & 校验
- `submit_story {card_id, clue}`：
  - 仅讲述者、仅 `phase=story`；`card_id` 必须在其手牌中；`clue` 非空。
- `submit_card {card_id}`：
  - 仅非讲述者、仅 `phase=submit`；`card_id` 在手牌中。
- `submit_vote {card_id}`：
  - 仅非讲述者、仅 `phase=vote`；`card_id` 在 `pool_cards` 中；且不等于自己提交的 `card_id`。

## Public View
- 公共字段：`phase`, `round`, `storyteller_id`, `storyteller_name`, `clue`, `scores`, `target_score`, `deck_count`, `discard_count`, `last_result`。
- 个人可见：`hand`（CardRef 列表）、`submitted`/`voted` 状态。
- 投票阶段：`pool_cards`（CardRef 列表）与 `votes_by_card`（card_id -> voter list，含颜色）。

## 前端实现方案
- **大厅**：新增牌库勾选行，调用 `/api/aidixit/decks` 拉取牌库；至少选 1 个。
- **主面板**：
  - 顶部计分板：显示玩家名称、颜色与分数；突出当前讲述者。
  - 讲述阶段：讲述者可输入线索并点击手牌出牌；其他人显示等待。
  - 出牌阶段：玩家点击手牌选择并提交；提交后禁用。
  - 投票阶段：展示混洗牌池，按钮投票；显示实时投票圆点（按玩家颜色）。
  - 回合结果：展示 `last_result`（得分变化、正确票数、各牌得票）。

## 后端实现方案
- 新增 `game/ai_dixit.py`：
  - `init_game`：加载牌库、发牌、初始化状态。
  - `apply_action`：处理出题/出牌/投票、计分与轮换。
  - `get_public_view`：按视角裁剪信息。
  - `bot_move`：随机选牌 + 简单线索（如 "mystery"），随机投票。
- 在 `game/definitions.py` 注册游戏与 schema；`game/__init__.py` 导出。
- `app.py` 增加 `/api/aidixit/decks` 与 `/api/aidixit/card`（白名单校验、仅允许配置目录内文件）。
- 前端新增面板、渲染逻辑与 `room:start` 的 `config.selected_decks` 传递。

## 测试建议
- 牌库扫描：仅列出子目录，忽略非法文件；计数准确。
- init_game：手牌数量正确，讲述者为 seat0，分数为 0。
- submit_story：非讲述者提交应失败；讲述者可提交并进入 submit。
- submit_card：必须在手牌；全部提交后进入 vote。
- submit_vote：讲述者不可投；不得投自己牌；全部投票后计分。
- 计分三种情况覆盖；混淆票加分正确。
- 轮换讲述者与回合推进；达到 `target_score` 触发 game_over（平分即平局）。
- 牌堆耗尽时洗回弃牌继续补牌。
- 初始牌库卡数不足时 `init_game` 报错。

## 屏幕填充改版（2026-11-09）

第一版重做后仍然违反 DEV_GUIDE「紧凑并不意味着要缩成一团，应该尽量用满手机的一屏」：
390px 下 6 张手牌被压成 3 列约 115px 的小卡，桌面端 1440px 面板只占 790/950 高度。
这一版把卡牌尺寸从「写死的列数」改成「由可用屏幕高度反推」。

### 运行时排版算法 `fitAidixitStage()`

1. 先量出真实余量，而不是估算：舞台顶部的视口坐标、每个区块标题与线索输入框占的高度、
   舞台下方还剩什么（结算面板、窄屏时的元信息页脚）、面板自身的下内边距。
2. 余量按卡牌数量在牌池与手牌之间按比例分配。
3. 对每个牌区遍历 1..N 列，算出该列数下的自然高度（4:3）与拉伸后的行高，
   取**卡面面积最大**的那一组，且单牌宽度锁在 112–420px。
4. 剩余高度再按各牌区的拉伸余量二次分配，行高写进 `grid-auto-rows`，
   卡面用 `flex: 1` 撑满，`object-fit: cover` 负责裁切。
5. 末行没排满时把多出来的牌居中，避免出现「缺角」的半行。

容差 `AIDIXIT_FIT_SLACK = 1.06`：只差几像素就放弃一列会让每张牌直接小一半，
因此允许轻微超出。

### 结构变化

- **桌面 ≥1080px 改双栏**：左栏是提示条、线索条、舞台、上一轮结算；
  右栏是常驻的计分板与元信息，`position: sticky`。牌面因此拿到整块宽度与高度。
- **手机单栏**用 `display: contents` 把两个包裹层摊平，再按重要性 `order` 排序，
  计分板回到舞台上方。
- **舞台去掉外框**，不再在面板里再套一层。
- **投票期手牌默认折叠**：牌池 `order: -1` 置顶并吃掉全部高度，手牌收成一行
  「🖐️ Your Hand · 6 cards · tap to open」，点标题展开。
- **窄屏上「上一轮」默认折叠**，标题右侧常驻一行摘要（结算类型 + 讲述者），
  牌面藏在一次点击之后。

### 实测结果（3 人局，6 张手牌 / 4 张牌池）

| 宽度 | 手牌列数 × 单牌宽 | 屏幕占用 |
| --- | --- | --- |
| 320 | 2 × 144px | 87–89%，不滚动 |
| 390 | 2 × 179px | 88–90%，不滚动 |
| 1024 | 3 × 314px | 88–91% |
| 1440 | 3 × 349px | 88–91% |

## 结算面板票点改版（2026-11-09）

原实现把 `Story` 标记 absolutely 定位在卡牌左下角，而投票者彩点 `.aidixit-votes`
是卡牌底部的一条普通流内容，两者直接重叠，票点被金色标签压住看不见。
同时只有彩点无法分辨谁投了票。

- 卡牌内部新增 `.aidixit-card-frame` 图片框，`Story(👑)`、`Yours(🔹)`、
  票数徽章与 `Zoom(🔍)` 全部锚在图片框内，投票者列表成为它的兄弟节点，
  结构上不可能再互相遮挡。
- `Story(👑)` 从左下角移到左上角，票数徽章留在右上角，
  `Yours(🔹)` 同样在左上角（两者互斥，另加一条防御性偏移规则）。
- 投票者从纯色点改成姓名胶囊：`● 玩家名`，点保留玩家专属颜色，
  名字过长省略号截断，自己的那一票描金边。
- Explain 键 `vote_dots` 改名为 `voters`，Help 的投票章节与
  `result_card` 说明同步改写。
- 牌池排版的 `chrome` 预留从 32px 提到 48px，因为姓名胶囊可能换到两行。

验收新增：展开 Last Round 后逐张牌断言 `Story` 标记与投票者列表矩形不相交、
投票者列表不溢出卡牌、每个投票者都渲染出非空名字，四种宽度各截一张
`lastround-<宽度>px.png`。
