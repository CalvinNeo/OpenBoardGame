# 121 · 昆虫棋（Hive）设计与实现方案

## 范围与规则依据

实现可直接在现有房间中游玩的双人基础版 Hive，支持真人对战、真人对 AI、旁观、断线重连与现有存档机制。使用原创 CSS / SVG 六角棋子、Emoji 和文字，不使用商业棋子图片。本次不包含蚊子、瓢虫、鼠妇扩展。

规则依据：[Gen42 官方基础版规则书](https://www.gen42.com/wp-content/uploads/Hive-rules.pdf)。默认使用经典开局（首手可放蜂后）；房间可选择 Tournament Opening（双方首手不能放蜂后）。棋局是一个连续对弈过程，双方各走一步不是需要确认的结算轮；终局保留完整棋盘和结果，再开局使用现有房间重开流程，不自动清空棋盘。

## 游戏规则

- 每方 11 枚：蜂后 Queen Bee（🐝）1、甲虫 Beetle（🐞）2、蚱蜢 Grasshopper（🦗）3、蜘蛛 Spider（🕷️）2、兵蚁 Soldier Ant（🐜）3。
- 每回合放置一枚库存棋子或移动一枚己方已落地棋子。双方首枚须相邻；之后放置须接触己方且不能接触敌方，颜色以叠层最顶棋子为准。放置不能叠放，但不受滑入通道限制。
- 蜂后最迟在自己的第四回合放置，放置前禁止移动任何棋子。若到了期限仍无合法落点，只有无合法行动时才能 Pass。
- 任意移动提起棋子后，余下棋群必须仍为一个连通整体；移动过程持续接触蜂群。只可移动最上层己方棋子。
- 地面滑动不能穿过两侧均有棋子的夹缝，也不能跨过没有共同接触棋子的空隙。
- 蜂后沿边滑动一步；蜘蛛恰好滑动三步且不重访格子；兵蚁沿蜂群边缘滑动任意正步数；蚱蜢沿六方向跨过至少一个连续占用格，落在首个空格；甲虫一步，可爬上、爬下或横越叠层，按移动高度检查两侧通道。
- 每次合法行动后检查双方蜂后周围六格（被甲虫覆盖的蜂后仍须检查）。敌后被围则胜，己后被围则负，同时被围则平局。无合法行动才允许 Pass。
- 增加在线对弈的明确和棋机制：双方确认 Offer Draw / Accept Draw；同一局面第三次出现自动判和，连续双方无子可放亦判和。三次重复以棋种、所属方、坐标、叠放顺序、行棋方、库存及蜂后期限为依据，忽略同种棋子的编号。Help 明确标示自动判和为线上约定。

## 后端与协议

- `game/hive.py`：纯规则引擎，稀疏轴坐标 `(q, r)` 棋盘，不设置有限棋盘边界。持久状态只使用 JSON 原生类型；每格存从底到顶的棋子 ID。
- 同一个合法行动生成器用于服务端校验、公开落点提示与 AI，避免客户端各自重算产生分歧。严格拒绝非法坐标、越权、未落蜂后移动、非法 Pass、覆盖棋子移动和结束后的落子，拒绝时不改变状态。
- `HiveGame` 接入 `init_game / get_legal_actions / apply_action / get_public_view / bot_move / serialize / deserialize`。公开视图包含双方库存、完整叠层、当前行动方、己方合法落子列表、蜂后被围数量、最后一步、结果与最多 100 条历史记录；旁观者没有可执行动作。
- 注册 `hive`，中文名“昆虫棋”，英文名“Hive”，人数固定为 2，分类 Abstract；运行 `scripts/gen_dev_order.py`。

## AI

- `game/hive_ai.py`：确定性的局面评价与有预算的迭代加深 negamax / alpha-beta 搜索，支持 Easy / Normal / Hard，默认 Normal。不依赖模型下载或额外服务。
- 评价考虑双方蜂后周围空位与逃生、甲虫压制、可移动棋子、已部署棋子和进攻距离。优先完成一手胜利，搜索对手立即取胜的威胁。
- 按战术评价排序，使用置换表和节点／时间预算；高分支时限制深层候选宽度，根节点的一手胜负检查覆盖所有候选。超时返回已经完整评估的合法候选；机器人不修改真实局面。
- 与现有房间机器人调度和进度回调兼容，只有自己的回合才行动，无路可走返回 Pass；对手提出和棋时按局面判断，绝不依赖未公开信息。

## 前端（遵守 FRONTEND.md 与 designs/task40.md）

- 在 `static/games/hive.html / hive.js / hive.css` 实现，资源注册到 `GAME_ASSETS` 并按需加载。首页只新增空面板、模板入口和必要配置占位；公共 JS 仅加分发、配置同步接口。游戏脚本封装 IIFE，对外接口全部带 Hive 名称。
- 主体是六角棋盘，旁边紧凑展示双方库存、蜂后状态、当前选择和可滚动记录。手机上棋盘和自己的库存相邻，宽度适配 320px，不出现页面横向滚动。
- 点库存或己方顶层棋子，显示服务器提供的合法落点；点落点形成预览，Confirm 提交，点空白或 Esc 取消。用轮廓、文字和黑白阵营同时区分颜色；显示堆叠层数并可查看底层。棋盘支持 Fit、缩放、鼠标／触摸平移，棋盘内 `touch-action: none`，指针捕获处理移出、抬起、取消，拖动后不触发落子。
- Help 弹窗集中说明所有规则、图标及线上判和约定。Explain 模式捕获交互，仅可解释对象显示虚线和问号光标，禁用按钮也可解释；其他动作被拦截；查看后自动退出，Esc 关闭。
- 非操作性图标／状态在桌面悬停、手机点击时给出浮动说明，手机 3 秒消失，连续点击更新最新说明。全部游戏外 UI 使用英文。
- 完成对局保留终局棋盘、胜者或和棋原因。重连恢复选择可用性与落点，加载后同步已有房间／游戏状态，切换游戏清理弹窗、提示、拖拽和计时器。

## 验证与交付

- 确定性单元测试：开局、蜂后期限、五种移动、滑动缺口与断链、蜘蛛路径、跳跃落点、甲虫高度与颜色、覆盖蜂后、胜负与和棋、非法请求不变性、旁观和 JSON 往返。
- AI 战术与自弈验证：必胜一步、拦截必败一步、始终合法、只读状态、不同难度、无动作时 Pass。
- 房间集成：注册／人数、真人加 Bot 开始、动作广播、存档重载。全局注册与公共分发受影响，运行对应共享检查及完整 Python 测试；浏览器验证真实加载、桌面／手机布局、选择／提交、Help／Explain、触摸与终局。
- 交付设计文件、规则与 AI 模块、游戏前端、测试及必要注册改动。保留当前工作区其他游戏的既有改动。
