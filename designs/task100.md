# Task 100 — 庞氏骗局 / Ponzi Scheme

## 目标与规则依据

在现有 FastAPI / Socket.IO 房间中新增 `ponzi_scheme`，支持 3–5 个席位、真人和机器人、保存恢复、基础与进阶规则，从募资完整进行到破产结算。

规则交叉核对：[发行商中文介绍](https://www.zhiyanjia.com/ponzischeme/)、[英文规则书](https://cdn.1j1ju.com/medias/0c/7f/67-ponzi-scheme-rulebook.pdf)、[规则图解](https://www.ultraboardgames.com/ponzi-scheme/game-rules.php)、[FAQ](https://www.ultraboardgames.com/ponzi-scheme/faq.php)。不使用商业卡面、美术或 UI 素材；只把机制和组件数值转换为独立数据与原创界面。

牌表独立放在 `game/ponzi_scheme_data.py`。已取得有 MIT 许可的完整 72 张数值表，与规则书公开示例一致；采用作者勘误确认的 9 张起始／47 张普通／16 张熊牌。数据来源、版本和许可保存在 [ponzi_scheme_card_data.md](ponzi_scheme_card_data.md)。未逐张核验实体卡，但不使用自拟或估算牌表。

## 规则与状态机

版本选择：行业各 15 个；默认采用作者补充的首轮跳过交易，房间可开启 `First-round trading` 使用英文规则书的首轮完整流程。

- 开局没有现金或产业。9 张起始资金牌按本金升序组成三行三列；其余 63 张洗成牌库。四种行业分别计数，行业、资金牌、利息、周期公开，现金隐藏。
- `funding`：从起始玩家依次选择募资或 Pass。募资必须一起取得一个行业和一张资金牌；取得后该行业共 1／2／3 个时，只能取第 1／2／3 行。已有三个或更多同类行业时不能再通过募资取得，但交易可以超过三个。立即获得本金，按周期登记债务；市场即时补牌并重新排序。
- `trading` → `trade_response`：每人依次可以发起一次暗盘交易或 Pass。双方必须拥有选中的同类行业；发起者以自己现有现金给出秘密整数报价（允许零）。接收者必须选择收钱卖出一个行业，或支付同价反向买入一个行业，不能拒绝或改价。报价锁定在信封中，避免重复支出；买回时退还原报价并另付同额。公开记录双方和行业流向，金额只给参与双方。
- 进阶模式在发起暗盘的机会可改为购买一件尚存奢侈品：💍 30／1 分、🚘 56／2 分、🛥️ 78／3 分、🏙️ 96／4 分。每件唯一，不能交易；基础模式只在结束时按现金档位计分。
- `market_remove`：起始标记移给下一位，由新起始玩家移除市场任意一张资金牌并补齐排序。被移除的蓝色起始牌永久出局，普通／熊牌进弃牌堆。
- 若市场熊牌数达到人数，触发一次崩盘：所有市场熊牌与弃牌堆、剩余牌库混洗后补牌；不递归触发本轮第二次崩盘。`crash_discard` 从新起始玩家开始，依次归还一个自己最多的行业；并列由本人选，无行业则跳过。
- 时间推进一格，崩盘推进两格；越过到期点的牌本轮同样付息一次。全部玩家同时核算到期债务，有钱者支付全部利息并把债务重置到原周期；债务永久保留，不再收到本金。任何无法全额支付的人破产，所有当轮破产者都失去胜利资格。
- 无人破产进入 `round_end`，展示本轮交易流向、崩盘弃置和付息结果；所有席位分别点击 `Next Round` 才开始下一轮。机器人只确认自己，断线不会代确认；不得跳过回顾。
- `game_over`：存活者各行业按 `n(n+1)/2` 得分。基础财富分为 0–29 → 0、30–55 → 1、56–77 → 2、78–95 → 3、96+ → 4；进阶只计算已购买的奢侈品。同分比较持有资金牌的最大本金；再同则并列。全员破产则无人获胜。游戏不设任意轮数截断。

## 服务端、隐私和机器人

实现仓库接口 `init_game`、`get_legal_actions`、`apply_action`、`get_public_view`、`bot_move`、`serialize`、`deserialize`。使用严格动作 Schema，并在模块内验证阶段、当前玩家、现金、行业、目标及卡牌 ID；任何非法动作不修改状态。JSON 保存恢复深拷贝，记录可复现洗牌状态但不向客户端暴露 seed 或牌库顺序。

公共视图白名单输出：别人的现金不可见；报价和私密交易记录仅参与者可见；日志、事件、机器人广播和房间配置均不得泄露金额或随机种子。完整资金牌与到期表公开；不能根据另一人的余额向第三方泄露其可执行动作。机器人仅基于与真人相同的裁剪视图决策，评估近期付息压力、募资成本和行业分数，并完成所有等待阶段。

## 前端（FRONTEND.md 与 task40.md）

- 新建 `static/games/ponzi_scheme.js`，IIFE 私有作用域，仅导出 PonziScheme 前缀接口；新建独立 CSS。`app.js` 只做面板显示及渲染接入。
- 原创深绿、米白、铜金金融桌面。用 🚂／🏠／📻／🌾 行业标记、💵 现金、🐻 熊市、⏳ 债务；颜色辅以文字，不仅依赖色觉。
- 三行资金市场保持清楚的行号和本金／利息／周期；右侧显示本人现金、近期到期压力和当前操作，下方紧凑显示各玩家行业及可展开的公开债务。手机改为单列，市场每行三张收缩适配，所有内容可换行，禁止横向溢出和重叠。
- 点行业、资金牌、交易对象后确认；报价使用数值输入与快捷调整，不要求 JSON。空白／Esc 取消选择，不添加 Clear Selection。对话框可用 Esc、Close、遮罩关闭；输入与标签同行。游戏无关 UI 使用英文。
- Help 包含完整规则、计分与实际牌表边界；Explain 捕获操作，所有普通按钮原功能都被阻止，仅可解释控件显示虚线及问号，disabled 按钮也支持坐标命中；解释一次自动退出或 Esc 退出。
- 图标、颜色、资源、数值徽标均提供即时说明，包含名称、用途和单位。桌面悬停／键盘聚焦显示 tooltip，触摸轻点显示三秒 banner，再点重新计时；滑动不触发。卡牌和行动按钮旁独立的 ⓘ 始终可用，包括禁用状态。查看说明不提交操作、不取消选择；进入对话框、Explain 或切换游戏时清理浮层。
- 本轮结算在桌面内展示并列出尚未确认玩家。游戏日志及交易记录限制高度、内部滚动；长名字和长数字保持容器内换行。
