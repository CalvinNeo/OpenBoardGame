# Design 2.1: Skull and Multi-Game Support

## Rule Sources
- https://en.wikipedia.org/wiki/Skull_(card_game)

## Skull Rules Summary (from source)
- Each player starts with four cards: three roses and one skull.
- Players take turns placing a face-down card to their personal pile until someone starts a bid.
- After a bid is made, players pass or raise until only one bidder remains.
- The bidder reveals all of their own pile first, then reveals other piles in any order.
- If the bidder reveals the number of roses equal to the bid without a skull, they win the round.
- If a skull is revealed, the bidder loses a card chosen at random by the skull owner.
- Players with no cards are eliminated; the game ends when someone wins two rounds or only one player remains.

## Skull State and Actions
### State (SkullGame)
- players: {player_id -> {hand, pile, rounds_won, eliminated}}
- turn_order / current_turn
- phase: playing | bidding | reveal | game_over
- current_bid / bidder / passed
- reveal: {roses_revealed, last_card}
- round, last_round_summary, winner, game_over
- config: {target_wins}

### Actions
- play_card {card_type: rose|skull}
- start_bid {bid}
- raise_bid {bid}
- pass_bid
- reveal_card {target_player_id}

### Key Mechanics
- Bidding is only allowed after every active player has played at least one card.
- Reveal phase must finish the bidder's pile before other piles.
- On failure, a random card is removed from the bidder (matches the real-world random pick).
- Next round starts with the bidder on success, or the next active player after the bidder on failure.

## Multi-Game Module Interface and Registry
- Add GameDefinition metadata: game_id, name, min/max players, turn_mode, action_schema, config_schema.
- Add a registry to look up game modules by game_id.
- Games expose init_game / apply_action / get_public_view / bot_move / serialize / deserialize.
- Cabo and Skull are registered as selectable games.

## Room and Frontend Updates
- Room creation allows selecting game_type; join/add bot/start validate min/max players per game.
- game:state includes game_type so the frontend can switch views.
- Frontend adds Leave Room and clears local UI state on exit.
- Skull-specific UI added: play, bid, reveal, target selection, and player status.

## Bot Behavior (MVP)
- play_card: random from hand.
- bidding: low chance to start a bid, random raise vs pass.
- reveal: flip own pile first, then random pile.
