# Design 6.1: 退出/重连机制（Token-Based）

## Goals
- 提供房间列表面板，显示当前所有房间与状态。
- 支持掉线重连（恢复到原玩家身份和手牌信息）。
- 已开始的游戏禁止新玩家加入，但允许原玩家重连。
- 防止同名/恶意冒充导致的“撞号”。

## 核心改进
- 不再依赖“同名”作为重连凭证，改为 **player_id + reconnect_token**。
- reconnect_token 由服务端生成（随机不可猜），客户端持久化保存，用于重连认证。

## 数据结构调整
### Player
- player_id: string
- name: string
- seat: int
- socket_id: string | null
- connected: bool
- reconnect_token: string
- last_seen: timestamp

### Room List Item
- room_id
- game_type
- status (lobby | in_game | game_over)
- player_count / max_players
- players: [{name, connected}]

## 客户端流程
1. room:create / room:join 成功后，服务端返回 {room_id, player_id, reconnect_token}。
2. 客户端保存到 localStorage（按 room_id 归档）。
3. 断线后重连：客户端发送 room:reconnect {room_id, player_id, reconnect_token}。
4. 若重连成功，服务端重新绑定 socket_id 并推送最新 game:state。

## 服务端流程
### disconnect
- 标记 player.connected=false，socket_id=null，last_seen=now。
- 广播 room:state / game:state 更新。

### room:reconnect
- 验证 room_id 存在。
- 验证 player_id 与 reconnect_token 匹配。
- 若该 player 仍 connected=true，返回错误（避免多端占用）。
- 通过后：设置 socket_id、connected=true，加入 room，并推送 state。

### room:join
- 若 room.status == in_game：
  - 仅允许带有效 reconnect_token 的重连（否则拒绝新加入）。
- 若房间内已有同名玩家且 connected=true，则拒绝。

## Room 列表面板
- 新事件：room:list -> 返回所有房间概要信息。
- 服务端在 room:create / room:state 变更后广播 room:list_update（可选）。
- 前端左侧显示房间列表，支持点击进入/重连。

## 边界处理
- 多标签页重连：若同一 player_id 再次重连，默认拒绝新连接（或配置为踢掉旧连接）。
- reconnect_token 丢失：允许在 lobby 时用 name 重新加入；在 in_game 时拒绝（避免冒充）。
- 长时间离线：可选择保留玩家直到 round_end，或超时清理（配置项）。
