# Task 103 — 诡影寻踪 / Cryptid

## 1. 目标与范围

在现有 FastAPI / Socket.IO 房间系统中新增 `cryptid`，名称为 `Cryptid · 诡影寻踪`。实现 3–5 人竞争推理：每位玩家持有一条秘密线索，通过公开询问、搜索和标记，抢先找到唯一符合全部线索的六边形格子。

首版包含普通／进阶模式、真人与机器人混合对局、完整胜负流程、私人笔记、断线重连及保存恢复。游戏类型使用现有 `puzzle` 标签。暂不包含独立游戏《Cryptid: Urban Legends》，也不把官方双人变体直接当成“减少到两人的普通模式”；首版房间拒绝两人开局。

下文记录实现方案；实际实现范围和已通过的检查见文末“实施记录”。

### 规则来源

- [Osprey 官方英文规则书](https://www.ospreypublishing.com/media/xjhnf54a/cryptid-rulebook-english.pdf)：开局、询问、搜索、六类线索和提示规则，以此为主要规则依据。

## 2. 规则模型

### 地图与距离

- 地图由六块板块组成，每块 18 格，拼成 12 列、9 行，共 108 个六边形格。以稳定格子 ID 标识位置，显示坐标采用 `A1`–`L9`。
- 每格恰有一种地形：森林、沙漠、水域、山地、沼泽；可叠加熊／美洲狮领地及结构物。动物领地不是第六、第七种地形。
- 结构物分为立石与废弃小屋，每类各有白、绿、蓝、黑四种颜色。普通模式使用白、绿、蓝两类共六个结构物；进阶增加两个黑色结构物。
- 使用统一的 offset → axial/cube 坐标转换计算六边形距离。距离包括起点本身：`within N` 为距离 `<= N`。不能使用矩形格曼哈顿距离；跨板块接缝同样相邻，地形、动物及建筑不阻断距离。
- 线索涉及某类元素时，到该类所有格子的距离取最小值，不能只测最近一个图标中心或某个结构物实例。

### 线索目录

每条线索都是可单独求值的谓词。目录和中文说明独立于界面，服务端为唯一判定依据。

| 类别 | 条件 | 普通模式数量 |
| --- | --- | ---: |
| 两种地形 | 位于指定两种地形之一，使用 OR | 10 |
| 地形附近 | 距指定地形不超过 1 格 | 5 |
| 任意动物附近 | 距熊或美洲狮领地不超过 1 格 | 1 |
| 结构物类型附近 | 距立石／废弃小屋不超过 2 格，忽略颜色 | 2 |
| 指定动物附近 | 距熊／美洲狮领地不超过 2 格 | 2 |
| 结构物颜色附近 | 距指定颜色结构物不超过 3 格，忽略类型 | 3 |

普通模式共 23 条正向线索。进阶增加黑色结构物这一条，形成 24 条正向线索，再提供其逻辑否定，共 48 条。否定作用于完整谓词，例如“不在森林或水域”表示既非森林也非水域；“不在 2 格内”表示距离大于 2。

同局不发完全相同的线索。每人的线索只交给本人，其他人通过公开圆片／方块推断。仅仅得出唯一候选位置不算获胜，必须实际执行成功搜索。

### 开局与标记

随机确定起始席位，按固定席位顺序轮转。每位玩家依据自己的线索放一个方块，完成一圈后再进行第二圈，因此每人总共放两个开局方块；不能由一个人一次放完两个。

- 圆片 `●`：此格符合放置者的线索，不保证符合其他人的线索。
- 方块 `■`：此格不符合放置者的线索，因此不可能是共同答案。
- 同一玩家不能在同一格重复放标记。不同玩家的圆片可以共存。
- 每格至多一个方块。已有其他玩家圆片的格子允许首次放方块；此前的圆片保留，因为各人的线索不同。
- 有方块的格子立即封锁，之后不能被询问、搜索或再放任何标记。
- 标记永久保留。服务端强制诚实，因此线上版不开放任意移动／删除标记的纠错入口。

### 询问

当前玩家选择一个没有方块的格子和另一位玩家。目标玩家在此格尚无圆片；已有回答的组合不能重复询问。询问位置可以不符合提问者本人的线索。

回答由服务端按被问者的线索计算：符合放圆片，不符合放方块。若出现方块，提问者必须在另一合法格放置自己的方块，作为信息补偿。补偿完成后才结束该回合。

### 搜索

搜索位置必须没有方块，且符合搜索者自己的线索。

1. 搜索者先在该格放自己的圆片；若该格已有其圆片，必须先在另一符合自身线索、无方块、无自身标记的格子补放圆片。
2. 从搜索者下一席开始，按顺序核对其他人的线索。已有该玩家圆片时跳过该玩家，不重复放置。
3. 符合则放该玩家圆片；第一位不符合者放方块，搜索立即停止，后续玩家不得继续回答或泄露结果。
4. 搜索失败后，搜索者在其他合法格补放一个方块，随后照常轮到下一席。**搜索失败不会淘汰玩家，也不扣分。**
5. 全部玩家通过时，搜索者立即获胜。终局展示答案格、获胜者、所有人的线索和本次搜索过程。

回答没有策略选择，线上版可自动执行强制回答；首版采用这一方式。询问一次提交后公开一个结果；搜索一次提交后按席位计算并返回有序结果，遇到方块立即终止。界面保留完整结果供回顾，不能为播放动画而把尚不应公开的回答一起下发。

### 提示与极端情况

- 提示使用表决：三人局全部同意，四／五人局至少 `人数 - 1` 同意。每局最多公开一条“本局未使用某类线索”的信息；不能直接给出答案、特定玩家的线索或候选格。
- 提示由生成器根据实际线索预先校验，不能沿用与当前开局无关的实体卡提示编号。投票通过后若没有适用提示，公开说明没有可用提示；投票前不通过按钮可用性泄露本局隐藏线索是否覆盖全部类别。
- 官方规则书未明确描述“需要补放圆片／方块，但已经没有合法新位置”的处理。实现前应继续核实设计者勘误；不得偷偷允许重复标记或把玩家判负。
- 如未找到明确勘误，采用并明确标注线上约定：仅当服务端证明该类合法新位置集合为空时免除这一次补放，公开记录原因后继续。玩家不能主动选择免除，不能因此提前结束搜索；有合法位置时必须正常补放。Help 中单列此约定和来源边界。

## 3. 地图数据与唯一解开局

### 数据边界

`game/cryptid_data.py` 保存地形、动物、结构物、板块朝向和线索目录，渲染文件只消费这些逻辑数据。

实施时先逐格核对六块官方板块的地形与动物分布，并记录来源和校验方式；只转录逻辑信息，不打包商业图片或官方辅助程序。实际已根据官方辅助站六张板块图片完成 108 格地形／动物转录，来源记录在 [cryptid_data_sources.md](cryptid_data_sources.md)。

若无法核实完整板块数据，则用明确标注为 `Original map` 的原创六块地图完成兼容玩法，并在房间配置、Help 和地图来源字段标明；不能将原创地形伪称为实体原版。正式版和原创版的数据不得混在同一无来源标识的地图池中。

### 生成与校验

服务端本地生成开局，不请求外部服务，不向浏览器交付题库答案。

1. 随机排列六块板块并选择允许的朝向，转换成规范的 108 格坐标；摆放对应模式的结构物。
2. 对当前地图计算全部候选线索的满足集合，推荐用 Python 整数 bitset 表示 108 格。
3. 选择与人数一致、互不相同的线索，要求全部集合的交集**恰好为一个格子**；拒绝零解或多解组合。
4. 排除单条线索已经唯一定位、恒真或恒假的组合。作为生成质量要求，每条线索应有贡献：去掉任意一条后的交集至少两个格子；此项是线上题目质量控制，不宣称为实体规则。
5. 开局每条线索须有足够可排除位置，保证任何合法开局放置顺序都能完成两圈方块；例如每条线索的排除集合至少有 `2 × 人数` 格。
6. 随机分配线索与起始席位。题目生成顺序不得固定对应玩家颜色或席位。
7. 使用独立校验器重新求交集，检查地图连通、结构物合法性、线索数量与模式、开局可执行性后，才接受题目。

生成过程设置候选搜索上限。达到上限则重试另一地图；持续失败时清楚返回可重试的开局错误，不能发布未验证题目或无限阻塞 Socket.IO。如需后台生成，应放入工作线程并在房间状态中显示 `Preparing game…`；不能修改已开始的对局。

生产使用服务端随机源；确定性 seed 仅供服务端测试与存档。公开房间配置、`game:state`、URL、日志、题目 ID 均不得携带可还原秘密线索的 seed。公开 `game_instance_id` 独立随机生成，不能是种子或题库答案索引。

## 4. 状态机与动作

| 阶段 | 可执行操作 | 后续阶段 |
| --- | --- | --- |
| `initial_clues` | 当前席位放开局方块 | 下一席；每圈结束进入 `round_end` |
| `turn` | 当前席位询问或搜索 | `compensate_cube`、`search_extra_disc`、下一席或 `game_over` |
| `search_extra_disc` | 搜索者补放合法圆片 | 执行原搜索的有序核对 |
| `compensate_cube` | 回合发起者补放合法方块 | 下一席或 `round_end` |
| `round_end` | 每位玩家各自确认 `Next Round` | 保存的下一阶段／下一圈 |
| `game_over` | 查看终局与私人笔记 | 保持终局，另由房间流程重新开局 |

保留 `turn_owner`、当前操作人、搜索格、搜索结果序列、开局圈数及回顾后的恢复点。搜索补圆片与补偿方块是同一回合的子步骤，不重新计算起始玩家，也不能被另一动作打断。

“一轮”定义为所有席位各完成一次正常回合；开局两圈也各有回顾。每轮结束后进入 `round_end`，展示新增标记、询问／搜索结果和待确认名单，所有席位分别确认后才继续。机器人只确认自己；真人断线不视为确认；不设置自动倒计时跳过。最终成功搜索立即进入持续展示的终局，不等待凑齐一轮。

建议动作 Schema：

- `place_initial_cube(cell_id)`。
- `question(cell_id, target_player_id)`。
- `search(cell_id)`。
- `place_extra_disc(cell_id)`。
- `place_compensation_cube(cell_id)`。
- `vote_hint(agree)`：只在开局完成后的 `turn`／`round_end` 开放，不消耗回合。
- `update_notes(...)`：仅更新本人的受限笔记字段，不推进游戏。
- `next_round`。

每种动作使用严格 Schema，拒绝额外字段、非法类型、伪造 ID、越权玩家及错阶段操作。先校验再修改；错误必须保持原状态完全不变。复用房间的状态版本广播和机器人版本检查；客户端发送中锁定，服务端按当前阶段／标记重新验证请求，重复回顾确认幂等。补偿尚未完成、全员尚未确认时，正常主动作不可执行。

## 5. 服务端接口与信息隔离

实现仓库标准接口：`init_game`、`get_legal_actions`、`apply_action`、`get_public_view`、`bot_move`、`serialize`、`deserialize`。状态容器与公共辅助函数保持类型标注，采用四空格缩进。

内部状态包括：地图、全部秘密线索、唯一解、席位、每格标记、当前阶段、待补放动作、有序搜索记录、每轮回顾、确认集合、提示表决、私人笔记、日志、胜者、数据版本和内部随机状态。

公共视图采用字段白名单，禁止把完整状态深拷贝后只删除几个字段：

- 所有人可见地图、结构物、公开标记、行动顺序、阶段、搜索已公开结果、表决状态及回顾确认情况。
- 本人额外可见自己的线索、自己的合法落点和私人笔记；旁观／未知身份无任何玩家的私密字段及可执行动作。
- 查询目标是否可选，只能依赖公开标记和席位，不能用对方隐藏线索筛选“可能回答是”的玩家。
- 对手的合法搜索格／补偿格、线索 ID、候选数量和求解器缓存都不得下发。不能通过 disabled 状态、DOM 属性、错误提示或日志泄露秘密。
- 游戏结束时才统一公开全部线索与答案。搜索未完成或正在补偿时仍不能揭示全局解。
- `events` 只含已经公开的动作及结果；不能附带完整线索对象、校验候选或秘密笔记。机器人动作广播采用最少信息，不发送候选排名或内部推理。
- `serialize` / `deserialize` 深拷贝完整服务端状态；恢复时验证版本、地图与线索一致性、阶段和待完成动作。重连不重新分配线索、重新洗地图或清空本轮确认。

存档沿用项目现有服务器权限；完整秘密存档不得因新增下载／调试功能暴露给对局客户端。审查房间配置与机器人广播这两条全局通路，不能只验证 `get_public_view`。

## 6. 机器人

`bot_move(state, bot_id)` 的第一步生成该机器人的玩家视图，此后的决策辅助函数只接收这个视图。不得读取真实答案、其他玩家线索、生成 seed 或题目内部索引。

机器人按公开线索目录和该玩家已公开标记，为每名对手维护仍可能成立的线索集合；仅使用自己线索与公开信息判断候选位置。询问优先选择能区分对手候选线索且尚未回答的组合；搜索优先选择通过概率高的位置。补放标记在合法位置内尽量减少额外泄露，平分时稳定选择，便于回归测试。

机器人覆盖两个开局圈、询问、搜索、补圆片、补方块和全员回顾，不能因特殊阶段返回空动作而卡住。真人发起提示投票后，机器人同意提示；不会主动发起提示或替真人投票。测试不同人数与两种模式的完整对局；不通过读取答案或设置任意轮数胜利来保证结束。加入保密回归：在机器人视图完全相同时，替换不属于它的秘密线索，机器人决策必须保持一致。

## 7. 前端布局与交互

### 页面结构

- 新建 `static/games/cryptid.js`，以 IIFE 或模块私有作用域承载全部游戏状态与事件处理，仅导出带 `Cryptid` 前缀的渲染／显示／重置接口。
- 新建 `static/cryptid.css`，样式限定于 `cryptid-` 容器。`static/app.js` 只接面板切换、渲染分发等必要全局入口，不塞入地图、笔记、推理或规则逻辑。
- 桌面为左侧地图、右侧公开提示／结果／日志，顶部紧凑显示席位、轮次及阶段。当前步骤紧贴地图工具栏，所选格详情和确认操作位于地图蒙版内。日志与回顾放在限高区域，必要时内部滚动。
- 手机端在地图上层容器显示选格蒙版，详情、询问对象和 Confirm／Cancel 同处，减少反复上下滚动。`Your clue` 与 `Notes` 默认关闭，从地图工具栏打开右侧抽屉；采用明确的对话框模式，支持 Close、Esc 和点击抽屉外关闭。
- 主界面只显示当前步骤的一句提示。完整规则、例子、特殊约定放进 Help。通用 UI 使用英文，例如 `Help`、`Explain`、`Notes`、`Confirm`、`Cancel`、`Close`、`Next Round`；游戏内容和线索可用中文。

### 图形编码

| 信息 | 显示方案 |
| --- | --- |
| 地形 | 森林(🌲)、沙漠(🏜️)、水域(🌊)、山地(⛰️)、沼泽(🌿)，辅以清晰底色／纹理 |
| 动物领地 | 熊(🐻)、美洲狮(🐾)，使用不同边线样式和文字说明 |
| 结构物 | 立石(🗿)、废弃小屋(🏚️)，白／绿／蓝／黑底色加颜色名称 |
| 玩家标记 | 可能(●)、排除(■)，按席位着色并带座位编号；颜色不是唯一识别手段 |
| 操作 | 询问(❓)、搜索(🔍)、笔记(📝)、胜利(🏆) |

Help、Explain 和即时提示必须同时出现名称与图标，例如“森林(🌲)”“可能(●)”，不单独解释未关联的抽象符号。结构物颜色与玩家颜色分开呈现，避免误认建筑属于某人。

地图不能把最多五名玩家的标记直接盖在地形或建筑文字上。格内固定划分地形／结构物区与标记轨道；细节过密时显示标记数量和状态，在所选格详情中完整列出所有玩家结果。缩放较小时隐藏次要格内文字，用详情补足，不把文字缩到无法辨认。

### 地图操作

- 用 SVG 绘制六边形，可缩放和平移；地图外容器宽度随页面收缩，不能通过扩大页面宽度容纳地图。
- 手机地图区域设置 `touch-action: none`，区域外保留页面滚动。使用 Pointer Events 和 pointer capture，在 `pointerup`、`pointercancel`、`lostpointercapture` 及离开页面时可靠清理手势。
- 移动超过阈值或发生双指缩放后视为拖拽，结束时不得误选格子或提交动作。手指移出地图区域后仍能正确结束拖动。
- 提供紧凑的 `+`、`−`、`Fit`；限制缩放范围和平移边界，避免把整张地图拖到看不见。
- 单击格子只进行选择，不直接询问、放标记或搜索。地图蒙版内展示坐标、地形、领地、建筑和已有标记，并提供行动切换、询问对象、Confirm／Cancel；选定合法格子及必要对象后才能确认。
- 六边形不足以容纳操作时，将半透明蒙版放在足够大的地图上层容器；底层地图暂停交互，工具栏仍可打开私人线索或笔记。详情过长时内部滚动，确认／取消始终保留在底部。Cancel、蒙版空白或 Esc 取消未提交选择，不增加 `Clear Selection`。
- 正在补圆片／补方块时区分原搜索格与待补放格，取消临时选择不撤销服务器已经接受的搜索。
- 所有输入标签与对应组件尽量同行，按钮适当两列并保留间距。长玩家名、中文、坐标和数量均可换行；使用 `min-width: 0`、合理断词及布局重排解决溢出，不能仅用隐藏溢出来遮掉操作内容。

### 私人笔记

提供两类手动记录：地图格的“候选／排除／未标记”个人标记，以及按玩家划分的候选线索清单。笔记样式与公开圆片／方块明显不同，点击笔记不会发起游戏动作。

笔记仅本人可见，保存随本人恢复；使用独立 `game_instance_id` 防止串局。首版不自动替玩家排除对手线索、不提供全局答案按钮。私人线索放入与 Notes 同样的右侧 `Your clue` 抽屉，抽屉内的 `Highlight on map` 开关只可视化本人已知线索范围；收起后保留该开关状态，同局更新不丢失当前选格，新局重置。

### 即时提示、Help 与 Explain

- 没有自身交互功能的图标、缩写、颜色和计数提供简短即时说明。桌面悬停／键盘聚焦显示；手机轻点显示浮动提示，3 秒后消失，连续点击更换为最新内容并重置计时。拖拽不弹提示。
- 严禁在板块、卡牌、区域或动作旁增设 `i`／`ⓘ` 信息按钮。先点击统一的 `Explain`，再点原有控件或区域查看说明；查看说明不能触发提交、投票或切换选项。即时提示直接绑定已有图标／文字，定位须限制在视口内，不能遮住当前确认控件；关闭对话框、离开游戏或切换 Explain 时清理浮层和计时器。
- `Help` 打开可滚动规则对话框，包含目标、开局、两种行动、六类线索、进阶否定、提示投票、圆片与方块区别、线上回顾与极端情况约定。支持 Esc、Close、焦点进入和返回。
- `Explain` 按 task40.md 采用捕获阶段拦截操作：所有普通按钮／棋格的原功能都停止；只有有说明的控件显示虚线和问号光标；无说明的控件不改变外观，也不能执行。
- disabled 按钮仍能通过 pointerdown 坐标命中获取解释；解释包含禁用原因。显示一次解释后自动退出，或按 Esc 主动退出。
- 退出 Explain 的那次指针事件及后续合成 click 都必须被消费，防止“看完说明顺手提交”。按钮移动／界面重绘后重新使用当前边界命中，不能缓存过期位置。
