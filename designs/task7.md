# 实现《出包魔法师》

## Subgoal 1

- 搜索互联网，找到《出包魔法师》（Abraca...what?）基础版的游戏规则。你不需要包含任何 DLC。你需要将规则输出到 7.rule.md。
- 规则需明确：游戏人数/时长/目标、组件清单与数量、8 种法术的名称/数量/效果、骰子点数范围、生命上限、回合流程（喊招、连招限制、反噬、补牌）、回合结束与计分/胜利条件、平手处理、回合结束后的重置逻辑（魔法石回收/洗牌、生命值恢复、猫头鹰结算等）、玩家数差异（如有）。
- 你需要设计：
    + 公开区域：计分塔/层数、弃牌区（按法术分类或统一）、牌堆剩余、备用猫头鹰/特殊区域
    + 玩家区域：生命值、分数指示物、面前可见魔法石、自己不可见信息的展示方式、已获得的猫头鹰魔法石
    + 行动区域：选择法术喊招、是否继续连招、掷骰/结算提示
- 你需要明确隐藏信息与视角规则：玩家只能看到他人手牌，自己的手牌应为未知/背面；服务端与前端如何区分。
- 如果无法找到法术图片素材，需要用简化图标/文字版样式占位。

你的设计在 7.1.md，请在实现前让我 review。

## 专用 AI 与游戏目录标记

- `game/abraca_what_ai.py` 只接收当前座位的 `get_public_view`：利用其他玩家公开手牌、弃牌计数和自己的秘密卡扣除已知牌，不读取自己的暗牌、牌堆顺序、公共秘密池内容或他人的秘密卡。
- 根据不放回抽样的超几何分布推断施法成功率。本回合成功施放的公开记录 `turn_spells` 作为条件，通过组合数动态规划计算连续施法的后验概率，避免把成功出牌后剩余手牌误当成全新的随机抽样。记录在换人、轮末和新一轮重置；旧存档没有记录时兼容使用最近一次公开成功记录。
- 在当前回合内搜索最多五次后续施法，与主动停手比较：遵循法术编号不递减的限制，计算所有法术效果、巨龙反噬及治疗的三个骰面、邻座伤害、击杀、打空手牌、猫头鹰存活奖励和达到目标分后的本轮得分平手规则。
- 非终局评价兼顾生命、秘密卡收益、对手领先程度和补牌机会；这是有界回合内期望搜索，不是全局最优求解。搜索中的未来猫头鹰只估算得分，实际拿到秘密卡后用新的合法视图重新推断。
- 策略确定性运行，不修改游戏状态或全局随机数状态；支持掷骰、查看秘密卡、补牌结束回合和下一轮等阶段。
- 复用现有 `/api/games` 的 `has_strategic_ai` 与 Select Game 的 🤖 展示，将 Abraca What 和漏标的 Six Nimmt 加入 `game/ai_metadata.py`，并补齐 Isle of Skye、Moshimo Yusha、Spirit Island、Tacta、Turing Machine 已有的内置估值/推断策略。随机、首个合法行动和简单固定阈值 Bot 仍不标记。
- `tests/test_abraca_what_ai.py` 覆盖组合概率、重复施法条件、策略选择、隐藏牌置换不变性和 2–5 人完整对局；`tests/test_ai_metadata.py` 防止专用策略模块漏标；`tests/game_ai_catalog.browser.cjs` 检查 320/390/1024/1440px 下目录标记、无障碍名称、布局和筛选/选游戏交互，以及真人与 Bot 的联机行动、暗牌隔离和重连。
- 验证：相关 Python 测试与上述四种宽度的 Chrome 自动化均通过，并人工复核 320px/1440px 截图；未进行 iOS/Windows 真机验证。额外对比 48 局轮换座位的固定种子对局，面对仅按成功概率和固定停手阈值决策的基线 Bot，2/3/4/5 人局各 12 局的胜局份额分别为 10/10/4/6（共享胜利按人数平分）；该小样本仅作策略冒烟检查，不代表可靠胜率。
