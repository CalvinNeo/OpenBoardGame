# Task 25.1 — Download Memories (Consolidated Spec)

## Goal
Provide a **Room-level** “Download Memories” button that lets players download a **single, human‑readable HTML file** summarizing game content (prompts, drawings, guesses, etc.) for these games:
- `draw_guess`
- `impression_flower`
- `cyber_pictures`
- `decrypto`

This file is intended for humans to read and view drawings. Keep generation lightweight (avoid heavy CPU/memory usage).

---

## Button Behavior (Room UI)
- The Room page has **one unified button**.
- The button is **always clickable**.
  - If the current game does **not** support memories, show “not supported”.
  - If the current game **does** support memories, generate content **based on the game’s current progress** (not required to be game_over).
- **All players** can download (no permissions).

---

## Output File Format
- **Single HTML file only** (no zip, no multiple files).
- Human‑readable layout with **English UI labels**.
- Include images **inline** (e.g., `data:` URLs or client‑side rendering within the HTML). The file should remain self‑contained and open offline.
- For **Cyber Pictures target photos**, include them as images but you may **reduce resolution/quality** if large.
- For **all drawings created by players**, preserve the **original image** (no downscale required unless absolutely necessary).

### File Name
`{game_id}-{YYYYMMDD-hhmmss}-{roomId}.html`
- `game_id` is the **internal English id**.
- Time uses **local server time**.
- Preferred: record `game_start_time` at `init_game` and use it.
- If start time is missing, the **click time** is acceptable.

---

## Content Principles
- Include **system prompts** + **player creations**.
- Include **hidden info** if it helps to reconstruct the full story (e.g., Decrypto keywords, codes, intercept/decrypt guesses).
- When uncertain, include **more context** (player name/seat, round number, author ids, etc.).

---

## Game‑Specific Content

### 1) Draw & Guess (`draw_guess`)
Include:
- Player list (id, name, seat, bot flag).
- Config: language, guess method, answer‑length option, prompt pool if relevant.
- **Books** (per owner):
  - Initial prompt (round 0).
  - Each round entry in order: type (`drawing` / `guess`), author, round number.
  - For drawings: **image data** (original).
  - For guesses: **text**.
- Final guess vs original prompt (match or not).
- If game is in progress, include entries up to current round and mark “in progress”.

### 2) Impression Flower (`impression_flower`)
Include per round:
- Guesser id/name.
- Assignments: setter_id → prompt word.
- Drawings: setter_id → **image data** (original).
- Word bank displayed to guesser.
- Guesser’s matches: drawing_id → chosen word.
- Correct list and score delta.
- Review votes if enabled (who voted, target, vote value).
- Round score table + total scores.

### 3) Cyber Pictures (`cyber_pictures`)
Include per round:
- Matrix: 16 targets with id/filename/url **and** embedded image (can be downscaled/compressed).
- Each player’s tool + target coordinate.
- Submissions: raw submission JSON **and** a rendered image (so humans can see it).
- Guesses: each player’s guess map (work_id → coordinate).
- Reveal: who drew what, correct/incorrect guess list.
- Round scores and total scores.

### 4) Decrypto (`decrypto`)
Include:
- Player list with team info.
- Team keywords (hidden info included), intercept/miscommunication counters.
- Per round:
  - Each team’s **code**.
  - Encryptor identity.
  - Clues submitted.
  - Decrypt guess (and who submitted).
  - Intercept guess (and who submitted).
  - Correctness result and token changes.
- Final winner / draw state.

---

## Integration / API Notes (Room‑level)
- Implement a generic `download_memories` capability per game.
- If a game lacks support, return “not supported”.
- Content reflects **current state at click time** (not required to wait for game end).

---

## UI Language
- All **HTML labels, headings, and UI text must be in English**.
- Game data (prompts, guesses, player names) remain as originally entered.
