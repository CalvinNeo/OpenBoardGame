# Design 5.1: Splendor (Classic)

## Rule Summary (MVP)
- Goal: reach 15+ prestige points; points come from development cards and nobles.
- On your turn choose exactly one action: take 3 different gems, take 2 same gems (if 4+ in supply), reserve a card (+1 gold if available), or buy a card (from market or reserve).
- Cards give permanent gem discounts (bonus gems) and sometimes points.
- End of turn: if you meet any noble requirements, you must take one (choose if multiple).
- Endgame: when a player reaches 15+ at end of their turn, finish the round; highest score wins, tiebreaker by fewest purchased cards.
- Full rules + complete card list are captured in `designs/5.rule.md`.

## Data Model

### Card (Development)
- id: string (e.g., L1-01)
- tier: 1 | 2 | 3
- points: int
- bonus_color: white | blue | green | red | black
- cost: {white:int, blue:int, green:int, red:int, black:int}
- image_key: string (for generated SVG or external asset lookup)

### Noble
- id: string (e.g., N-01)
- points: 3
- requirement: {white:int, blue:int, green:int, red:int, black:int}
- image_key: string

### Player
- tokens: {white:int, blue:int, green:int, red:int, black:int, gold:int}
- bonuses: {white:int, blue:int, green:int, red:int, black:int}
- reserved: list[Card] (max 3, private to owner)
- purchased: list[Card]
- nobles: list[Noble]
- score: int

### Game State (SplendorGame)
- players: {player_id -> Player}
- turn_order: list[player_id]
- current_turn: player_id
- phase: turn | discard_tokens | choose_noble | game_over
- market: {
  tier1: list[Card], tier2: list[Card], tier3: list[Card]
}
- decks: {
  tier1: list[Card], tier2: list[Card], tier3: list[Card]
}
- tokens_supply: {white:int, blue:int, green:int, red:int, black:int, gold:int}
- nobles: list[Noble] (available on table)
- final_round: {active: bool, triggered_by: player_id | null}
- winner: player_id | null
- game_over: bool
- config: {target_score:int}

## Actions
- take_tokens {colors:[white|blue|green|red|black]} (3 distinct)
- take_tokens_same {color} (2 same, requires supply >= 4)
- reserve_market {tier, index}
- reserve_deck {tier} (top card, hidden from others)
- buy_market {tier, index, payment}
- buy_reserved {reserved_index, payment}
- discard_tokens {tokens:{color->count}} (only when >10)
- choose_noble {noble_id} (only when multiple eligible)

### Validation Notes
- Cannot reserve if already have 3 reserved.
- After any action, if tokens > 10 -> phase = discard_tokens.
- Payment: effective_cost = max(0, cost - bonuses); player must cover with tokens + gold.
- When buying, move tokens to supply; add card to purchased and update bonuses + score.
- At end of turn, auto-claim a noble if exactly one eligible; if multiple, phase = choose_noble.

## Turn Flow
1. Player takes one action.
2. If tokens > 10: enter discard_tokens until <= 10.
3. Resolve nobles: auto-claim or choose.
4. If score >= target and final_round.active is false, set final_round.active = true and triggered_by = current_turn.
5. Advance turn. When final_round.active and the turn cycles back to triggered_by, set game_over and winner by scoring + tiebreak.

## Public View
- Public: market cards, nobles on table, token supply, current turn/phase, final_round status.
- Per player (public): score, bonuses by color, tokens count, reserved count, purchased card count, purchased card list, nobles list.
- Viewer private: full details of their reserved cards and token counts.

## UI (MVP)
- Public area: token supply, market (3 rows of 4), nobles row.
- Private area: your reserved cards, purchased cards grouped by bonus color, token tray.
- Scoreboard: for each player show score, total tokens, bonus summary, nobles, reserved count, and a compact list of purchased cards.
- Action panel: buttons for take tokens / reserve / buy, with inline validation and payment helper.

## Asset Plan
- Use generated SVG card faces based on card data (points, bonus gem, cost gems).
- Noble cards use a crown icon + requirement gems.
- External reference for official art exists but is optional (see `designs/5.rule.md`).

## Bot Behavior (MVP)
- Prefer buying affordable cards with points.
- Otherwise reserve a high-point card if close to affordable.
- Else take tokens toward the cheapest market card by effective cost.
