# OpenBoardGame Design (Compacted)

本文件整合 design.1 + design.2，明确 MVP 实现约束，并保留可扩展方向。

## 目标与范围
- 目标：构建可扩展的桌游平台，支持多人联机对战与 Bot；首个落地游戏为 CABO。
- MVP 范围：单进程、内存态、Socket.IO 实时同步、单页 UI、单游戏 CABO、随机 Bot。

## 技术选型
- 后端：Python + FastAPI + python-socketio（ASGI）
- 前端：HTML + CSS + 原生 JS（Socket.IO 客户端）
- 数据：纯内存（不持久化）
- 部署：单进程运行（后续可按 room 分片到多进程）

## 总体架构
- Lobby/Rooms：创建、加入、离开、准备、开始。
- Game Engine：服务器权威状态机（只接受 action，校验后更新状态）。
- Game Modules：可插拔游戏实现（CABO 作为首个模块）。
- Bot Service：Bot 调度与执行（策略由游戏模块提供）。

## 一致性与安全
- 服务器权威：客户端仅发送 action；服务端校验合法性。
- 状态版本号：每次状态变化 state_version +1；用于同步、防乱序与重连。
- 可见性：仅发送 public view；私密信息按玩家视角过滤。
- 事件流：提供 events 列表；MVP 以 game:state 的 view 为权威。

## 数据模型

### Room
- room_id: string
- game_type: "cabo"
- status: "lobby" | "in_game" | "game_over"
- players: list[Player]
- state_version: int
- game_state: CABO state (in_game 时存在)

### Player
- player_id: string
- name: string
- seat: int (0..n-1)
- socket_id: string
- ready: bool
- connected: bool
- is_bot: bool

### Card
- value: int (0-13)
- choice: null | "peek" | "spy" | "swap"

### Session
- socket_id -> {player_id, room_id}

### CABO state
- deck: list[Card]
- discard: list[Card]
- players: map[player_id] -> {
  hand: list[Card | null] (length 4)
  known: list[bool] (length 4, only for owner)
  public_known: list[bool] (length 4, known to all)
  score: int
  score_reset_used: bool
  initial_peek_done: bool
}
- turn_order: list[player_id]
- current_turn: player_id
- phase: "initial_peek" | "turn" | "drawn" | "choice_pending" | "round_end"
- last_drawn: Card | null
- pending_choice: null | {type: "peek" | "spy" | "swap"}
- cabo_called_by: player_id | null
- cabo_turns_left: int
- config: {
  target_score: int (default 100)
  shooting_moon: bool (default false)
  score_reset: bool (default false)
  double_swap: bool (default false)
  deck_counts: map[value] -> count (default 4 each 0-13)
}

Knowledge 规则（MVP）：知识绑定在 slot 上，slot 被替换或交换时清空 known/public_known。

## 通信协议（Socket.IO）

### Client -> Server
- room:create {name, game_type}
- room:join {room_id, name}
- room:leave {room_id}
- room:ready {room_id, ready}
- room:start {room_id}
- room:add_bot {room_id, name?}
- game:action {room_id, action}

### Server -> Client
- system:error {message}
- system:info {message}
- room:state {room_id, players, status, game_type}
- game:state {room_id, state_version, view, events}

### 事件模型（扩展预留）
- 通用封装字段：event_id, type, payload, visibility(public|private), caused_by(action_id), state_version。
- MVP：events 可为空，view 为权威状态；逐步补齐完整事件封装。

## 通用游戏模块接口（设计约束）
- GameDefinition：game_id, name, min_players/max_players, turn_mode, action_schema, config_schema。
- init_game(config, players) -> state
- get_legal_actions(state, actor) -> actions
- apply_action(state, action, actor) -> new_state, events
- get_public_view(state, viewer) -> view
- is_terminal(state) -> bool
- score_round(state) -> scores (可选)
- serialize/deserialize (可选)
- bot_move(state, bot_id) -> action

## CABO 规则与实现细化

### 基础规则
- 玩家数 2–5；每轮每人 4 张面朝下按 2x2 摆放。
- 开局可看任意 2 张一次；开局后位置固定。
- 牌库：数值 0–13；分值=牌面数值。
- Choice Cards：7/8=Peek，9/10=Spy，11/12=Swap。
- Choice 触发仅限：从抽牌堆抽到并弃置时；从弃牌堆抽到不可触发。
- 抽牌堆耗尽：保留弃牌堆顶牌，其余洗回作为新抽牌堆。

### 动作 schema
- initial_peek {type:"initial_peek", slots:[int,int]}
- draw_deck {type:"draw_deck"}
- draw_discard {type:"draw_discard", slot:int}
- replace_card {type:"replace_card", slot:int}
- discard_drawn {type:"discard_drawn"}
- attempt_match {type:"attempt_match", slots:[int,...]}
- call_cabo {type:"call_cabo"}
- use_choice_action {type:"use_choice_action", choice_type:"peek"|"spy"|"swap",
  target:{player_id?, slot?, self_slot?}}

### 阶段与流程
- initial_peek：每人选两个不同 slot；全部完成后 phase -> turn。
- turn：当前玩家选择 draw_deck / draw_discard / call_cabo。
- drawn：持有 last_drawn，选择 replace_card / discard_drawn / attempt_match。
- choice_pending：discard_drawn 且为 Choice 时进入；执行 peek/spy/swap 后结束回合。
- round_end：结算并判断是否 game_over，否则进入下一轮。

### Matching
- 2/3/4 张同点数暗牌可尝试匹配（无需与抽到的牌同点）。
- 成功：弃置匹配牌并弃置抽到的牌，减少手牌数量。
- 失败：公开展示所选卡并放回原位；抽到的牌加入手牌（手牌数 +1），本回合结束。

### 计分与回合结束
- call_cabo 后其他玩家各再行动一次，然后翻牌结算。
- 每轮最低分者得 0，其余加各自牌面总分；若叫牌者不是最低分，额外 +5。
- 最低分平局：叫牌者在平局中则得 0；若无人叫牌，平局者都得 0。
- shooting_moon（可选）：两张 12 + 两张 13 -> 自己本轮 0，其他玩家 50。
- score_reset（可选）：总分恰好 100 时重置为 50（每人一次）。
- double_swap（可选）：Swap 允许交换两张（含不同玩家的任意两张）。
- 任一玩家总分 >= target_score 时 game_over。

## Bot 行为（MVP）
- initial_peek：随机两个 slot。
- turn：偏好 draw_deck，偶尔 draw_discard；从不 call_cabo。
- drawn：能 match 则 attempt_match；否则 replace 或 discard。
- choice_pending：随机合法目标。

## 错误处理
- 非法 action：system:error，状态不变。
- 所有合法状态变化均递增 state_version 并广播 game:state。

## 扩展与演进
- 单进程 -> 多进程：入口层按 room_id 路由到固定进程。
- 内存 -> 持久化：新增存储适配器与快照。
- 引擎与模块解耦：新增游戏仅实现模块接口即可挂载。
- Bot：策略由具体游戏模块实现，可复用通用策略组件。
