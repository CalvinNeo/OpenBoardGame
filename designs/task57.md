# 《马戏星探》（SCOUT）规则与电子版实现文档

本文把公开可获得的《马戏星探》规则整理为一份可直接用于开发电子版的说明文档。

文中分为四类信息：

- `规则`：公开规则能直接确认的内容。
- `实现建议`：为了写程序而做的建模建议。
- `工程化推定`：公开资料没有逐字写明，但根据规则上下文可以稳定推导出的实现口径。
- `缺失资源`：我目前无法直接获取、因此不能完整还原实体版表现的资源。

---

## 1. 游戏概述

《马戏星探》是一款 `2-5` 人的手牌管理与压制出牌游戏。玩家的目标是在多轮对局中累计最多分数。每轮中，玩家用手中相邻的牌组成牌组进行 `Show（演出）`，压过台面上的当前牌组；也可以通过 `Scout（挖角）` 从台面牌组两端拿走一张牌补进自己的手牌，重塑手牌结构。

这个游戏最核心的限制只有两个：

1. 手牌顺序几乎不能调整。
2. 你打出的牌必须来自手牌中的连续区间。

这两个限制决定了电子版的核心不是“出什么牌”，而是“你当前手牌的顺序与朝向是什么”。

## 2. 核心组件与可编码对象

## 2.1 实体组件

公开资料可确认实体版至少包含：

- `45` 张数字牌
- `23` 个 Scout 标记
- `30` 个得分标记
- `5` 个 Scout & Show 标记
- `1` 个起始玩家标记
- `1` 本规则书

## 2.2 电子版最小数据模型

实现时建议至少有如下对象：

```ts
type CardDef = {
  id: string;        // 例如 "1-7"
  a: number;         // 一面可见值
  b: number;         // 另一面可见值
};

type CardInHand = {
  cardId: string;
  orientation: "a" | "b";   // 当前哪一侧朝上
};

type PlayerState = {
  id: string;
  seat: number;
  hand: CardInHand[];       // 有序数组，顺序不能随意重排
  capturedCount: number;    // 本轮通过 Show 压过别人后收下的面朝下牌数量
  scoutPointCount: number;  // 3-5 人局：别人从你台面拿牌时你获得的 Scout 分数标记数
  score: number;            // 累计总分，可为有符号整数
  hasScoutAndShow: boolean; // 3-5 人局每轮 1 次
  scoutChipsLeft: number;   // 2 人局剩余可花费的 Scout 标记
};

type ActiveSet = {
  ownerPlayerId: string;
  cards: Array<{
    cardId: string;
    orientation: "a" | "b";
  }>;
  comboType: "single" | "set" | "run";
  rankValue: number;        // single/set 用数值本身；run 用最高值
};

type RoundState = {
  roundIndex: number;
  currentPlayerId: string;
  startPlayerId: string;
  activeSet: ActiveSet | null;
  players: PlayerState[];
  variant: "base_3_5" | "duel_2";
  removedCards: string[];
  reservedDeckForRound2?: CardDef[]; // 仅 2 人局需要
};
```

## 3. 牌库定义

## 3.1 数字牌的本质

`规则`：牌库共有 `45` 张牌，牌面数字来自 `1-10` 的所有组合；每张牌两端各有一个数字，只有左上角的大数字在当前朝向下生效，另一端的小数字表示翻面后的值。

`工程化推定`：最稳妥的程序做法，是把整副牌定义为 `1-10` 的所有两两组合，且同一张牌的两个数字不同。也就是：

- `1-2`
- `1-3`
- ...
- `9-10`

总数正好是 `C(10, 2) = 45`。

这套推定和公开资料中的“45 张、1-10 的所有组合”完全一致，也和 `3` 人局“移除所有包含 10 的牌共 9 张”严格对上。

## 3.2 可直接生成的完整 45 张牌 ID

## 4. 基础术语与硬约束

## 4.1 手牌顺序

`规则`：

- 发牌完成前，玩家不能提前拿牌。
- 玩家把牌拿到手上时，可以把整手牌一次性整体翻转。
- 翻转时必须整手一起翻，不能只翻部分牌。
- 在一轮进行过程中，不能重新排序手牌，也不能再整体翻转。

`实现建议`：

- `hand` 必须是服务端维护的有序数组。
- 所有出牌只能提交连续区间 `[startIndex, endIndex]`。
- 客户端绝不能直接提交一组离散牌 ID。

## 4.2 单张牌的朝向

`规则`：

- 当前朝向左上角显示的大数字才是当前有效值。
- 被 Scout 拿走的牌，插回自己手牌时可以选择任意位置，也可以选择任意朝向。

`实现建议`：

- 朝向应该是“逐牌状态”，而不是“整手共享状态”。
- 原始牌手虽然只能整手翻一次，但一旦 Scout 拿到新牌，该牌可以独立决定方向。

## 4.3 当前牌组（Active Set）

`规则`：

- 台面上任意时刻最多只有 `1` 个当前牌组。
- 当前牌组就是最近一次成功 `Show` 出来的那组牌。
- 所有玩家都在尝试压过这组牌，或者从这组牌两端挖走一张。

`实现建议`：

- `activeSet.ownerPlayerId` 必须始终保留。
- 即使 `Scout` 导致牌组缩短，拥有者也不改变。

## 4.4 连续区间限制

`规则`：无论是单张、对子、多张相同数字，还是顺子，打出的牌都必须在手牌中连续相邻。

例如：如果两个 `9` 中间夹着别的牌，就不能直接把这两个 `9` 一起打出。

| 2 | 移除 `9-10` | `11` | 每人 `3` 个 Scout 标记；不使用 Scout & Show | `2` | 第二轮使用首轮未发出的 22 张牌 |

## 5.2 起始玩家

`规则`：

- 第一轮由手中持有 `1-2` 这张牌的玩家成为起始玩家。
- 起始玩家获得起始玩家标记。
- 每轮结束后，起始玩家标记顺时针传给下一位玩家。
- 总轮数等于玩家数；当每个人都当过一次起始玩家后，游戏结束。

`实现建议`：

- 第一轮发完牌后，服务器扫描谁拥有 `1-2`。
- 后续轮次不要重新按 `1-2` 改起始玩家，而是直接传标记。

## 6. 牌型定义与比较规则

## 6.1 合法牌型

`规则`：合法 Show 只有三类。

1. `single`
   1 张牌。
2. `set`
   多张相同数字，例如 `7-7`、`4-4-4`。
3. `run`
   连续数字，例如 `3-4-5`，也可以是降序如 `5-4-3`。

注意：

- 顺子必须按你手里原本出现的顺序摆到桌上。
- 不能打出非连续数值的组合。
- 不能打出不相邻的牌。

## 6.2 比较优先级

`规则`比较顺序如下：

1. 张数多的一定压过张数少的。
2. 张数相同的情况下，`set` 压过 `run`。
3. 同类型、同张数时，比数值高低。
4. 顺子对顺子时，高数值顺子压过低数值顺子。

可直接落成程序规则：

```ts
function beats(candidate, active): boolean {
  if (!active) return true;
  if (candidate.length > active.length) return true;
  if (candidate.length < active.length) return false;

  if (candidate.comboType !== active.comboType) {
    if (candidate.comboType === "set" && active.comboType === "run") return true;
    if (candidate.comboType === "run" && active.comboType === "set") return false;
  }

  return candidate.rankValue > active.rankValue;
}
```

## 6.3 `rankValue` 的建议定义

`实现建议`：

- `single`：单牌当前值。
- `set`：重复数字的值。
- `run`：顺子的最高值。

`工程化推定`：

- 规则只说“更高的顺子压过更低的顺子”，没有再单独定义升序和降序的比较字段。
- 用“最高值”作 `run.rankValue` 是最稳定的实现口径。
- 例如：
  - `2-3-4` 的 `rankValue = 4`
  - `5-4-3` 的 `rankValue = 5`

## 6.4 单牌的处理

`工程化推定`：

- 单牌虽然从文字上也可以看作“1 张相同数字”或“长度为 1 的顺子”，但实现时应直接建模为 `single`，避免和 `set` / `run` 的同长度比较混淆。
- 单牌对单牌时，纯比数值即可。

## 7. 3-5 人局完整回合流程

## 7.1 每轮准备

1. 按人数移除对应牌。
2. 洗牌时同时随机化牌的朝向。
3. 发牌到每位玩家面前，但在所有牌发完前不允许任何人拿起。
4. 玩家拿起手牌时，可以选择是否整手翻转一次。
5. 每位玩家得到 `1` 个 `Scout & Show` 标记。
6. 确定本轮起始玩家。
7. `activeSet = null`。

## 7.2 玩家回合可选动作

在自己回合，玩家通常有两种主动作：

1. `Show`
2. `Scout`

如果还没用过本轮的 `Scout & Show` 标记，则还有第三种：

3. `Scout & Show`

没有“跳过”动作。

## 7.3 `Show` 详细规则

### 7.3.1 合法性校验

玩家提交 `Show` 时，服务器至少要校验：

1. 选中的牌是否来自手牌连续区间。
2. 这些牌在当前朝向下是否构成 `single` / `set` / `run`。
3. 若 `activeSet` 为空，则任何合法牌型都可打。
4. 若 `activeSet` 不为空，则新牌组必须压过当前牌组。

### 7.3.2 状态更新

如果 `Show` 成功：

1. 若原来有 `activeSet`，将其整组作为“被压过的牌”收入当前玩家的得分堆，面朝下保存。
2. 从当前玩家手牌中移除刚打出的连续区间。
3. 把这组新牌设为新的 `activeSet`。
4. 记录新的 `activeSet.ownerPlayerId = 当前玩家`。

### 7.3.3 台面为空时

`规则`：若台面没有牌，玩家可以打任意合法牌组。

这意味着：

- 第一位行动者一定是先 `Show`。
- 如果某个 `activeSet` 被 Scout 到空，之后下一位玩家也可以自由 `Show`。

## 7.4 `Scout` 详细规则

### 7.4.1 合法性校验

玩家提交 `Scout` 时，服务器至少要校验：

1. 当前必须存在 `activeSet`。
2. 当前牌组必须属于其他玩家。
3. 只能拿最左端或最右端那一张。
4. 目标插入位置必须是 `0..hand.length` 之间的某个位置。
5. 插入后的牌可选任意朝向。

### 7.4.2 状态更新

如果 `Scout` 成功：

1. 从 `activeSet` 的左端或右端取出 1 张。
2. 该牌按玩家指定位置和朝向插入自己的手牌。
3. `activeSet.ownerPlayerId` 获得 `1` 个 Scout 分数标记。
4. `activeSet.cards` 缩短；若缩短后仍有牌，则重新计算其 `comboType` 和 `rankValue`。
5. 若缩短后没有牌，则 `activeSet = null`。
6. 当前玩家回合结束。

### 7.4.3 `activeSet` 缩短后的意义

`工程化推定`：

- 被 Scout 掉一端之后，剩余部分依然是同一个 `activeSet`，仍属于原拥有者。
- 例如原台面是 `7-7`，被从一端拿走 1 张后，剩下的单张 `7` 仍然是台面牌组。
- 只有当最后一张也被拿走时，台面才真正变空。

## 7.5 `Scout & Show` 详细规则

### 7.5.1 使用条件

`规则`：

- 每位玩家每轮只有 `1` 个 `Scout & Show` 标记。
- 一旦使用，该标记立即弃置，本轮不能再用。

### 7.5.2 结算顺序

`Scout & Show` 的结算顺序固定为：

1. 先做一次合法的 `Scout`
2. 再立刻做一次合法的 `Show`

### 7.5.3 编码注意点

- `Scout` 插入新牌后，`Show` 必须基于更新后的整手手牌重新选区间。
- 如果 `Scout` 之后台面被拿空，那么后续的 `Show` 视作“在空台面打牌”，可打任意合法牌型。
- 使用 `Scout & Show` 时，被挖角玩家照样获得 `1` 个 Scout 分数标记。

## 7.6 回合推进

`规则`：3-5 人局中，玩家完成一次 `Show`、`Scout` 或 `Scout & Show` 后，行动权顺时针交给下一位玩家。

## 7.7 回合结束条件

`规则`：一轮在以下任一条件满足时结束：

1. 某玩家 `Show` 后手牌清空。
2. 轮到当前 `activeSet` 的拥有者再次行动，说明在此之前没有人压过他的牌组。

第 2 条可以理解为：

- 某玩家打出一组牌。
- 之后所有其他玩家都没有用 `Show` 压过这组牌，只是 `Scout` 或无牌可压。
- 当轮转一圈回到这名玩家时，该轮立即结束，他直接赢得本轮。

## 7.8 计分

`规则`：每轮结束后立刻计分。

本轮分数 =

- `+1` 每张你通过 `Show` 压过后收入得分堆的牌
- `+1` 每个你获得的 Scout 分数标记
- `-1` 每张你手中剩余的牌

例外：

- 触发本轮结束的玩家，不承受“剩余手牌 -1/张”的负分。

`实现建议`：

- 不必模拟实体得分标记的面值与找零。
- 直接把每轮净得分累计到 `player.score` 即可。

## 8. 2 人局特殊规则

2 人局不是把 3-5 人规则直接缩成两人，而是一套显式变体，必须单独实现。

## 8.1 开局

`规则`：

- 整局只进行 `2` 轮。
- 先从整副牌中移除 `9-10`。
- 剩余 `44` 张牌中，第一轮只发 `22` 张，也就是每人 `11` 张。
- 未发出的另 `22` 张牌保留到第二轮使用。
- 每位玩家获得 `3` 个 Scout 标记。
- 2 人局不使用 `Scout & Show` 标记。

`实现建议`：

- 第一轮开始时就把 `reservedDeckForRound2` 固定下来。
- 第二轮直接发这 22 张保留牌，不要再重新与第一轮已用牌混洗。

## 8.2 第一回合动作

`规则`：第一位玩家第一手必须 `Show`。

原因很简单：开局台面为空，不存在可 Scout 的对象。

## 8.3 后续动作循环

`规则`：

- 玩家回合仍然是 `Show` 或 `Scout` 二选一。
- 但当玩家选择 `Scout` 时，必须消耗自己 `1` 个 Scout 标记。
- 该标记放到中央公共区域，不给对手。
- 与 3-5 人局不同，被挖角的台面拥有者不会获得 Scout 分数标记。

## 8.4 连续行动规则

`规则`：在 2 人局中，只要玩家执行了 `Scout`，该玩家必须继续连续行动，直到发生下列两种情况之一：

1. 他执行了一次 `Show`
2. 他已经不能再 `Scout`，因为 Scout 标记用完了

进一步说：

- 同一名玩家可能连续执行多次 `Scout`。
- 玩家不能为了保留标记而“自愿不 Scout”；如果他还不能 `Show`，且还有 Scout 标记，就必须继续 Scout。

`实现建议`：

- 2 人局的“一个回合”更像一个连续行动链。
- 当行动类型是 `Scout` 时，`currentPlayerId` 不切换，直到链条以 `Show` 或“无标记且无法 Show”结束。

## 8.5 2 人局回合结束条件

`规则`：一轮在以下任一条件满足时结束：

1. 某玩家执行 `Show` 后手牌清空。
2. 某玩家轮到自己时，既不能 `Show`，又已经没有 Scout 标记，因而也不能继续 `Scout`。

## 8.6 2 人局计分

`规则`：计分方式与 3-5 人局一致，但把“通过别人挖角而获得的 Scout 分数标记”替换为“自己未花掉的 Scout 标记”：

- `+1` 每张收入得分堆的牌
- `+1` 每个本轮结束时尚未花掉的 Scout 标记
- `-1` 每张手中剩余的牌

同样：

- 触发本轮结束的玩家不承受手牌负分。

## 9. 电子版状态机建议

## 9.1 公开信息与私有信息

建议按以下口径处理可见性：

### 公开信息

- 每位玩家手牌数量
- `activeSet` 的具体牌、顺序、朝向、拥有者
- 每位玩家已获得的分数
- 3-5 人局每位玩家本轮已获得的 Scout 分数标记数
- 3-5 人局谁还保有 `Scout & Show`
- 2 人局每位玩家剩余 Scout 标记数
- 起始玩家标记位置

### 私有信息

- 玩家完整手牌顺序
- 玩家手牌中每张牌的朝向
- 玩家通过 `Scout` 把新牌插入到手牌哪个位置

`实现建议`：

- 客户端虽然看得到“某张公开牌被谁挖走了”，但不应看到该牌最终被插入手牌的哪个位置。
- 这是游戏策略信息，必须只对该玩家本人可见。

## 9.2 服务端推荐动作接口

### `show`

```json
{
  "action": "show",
  "startIndex": 2,
  "endIndex": 4
}
```

### `scout`

```json
{
  "action": "scout",
  "takeSide": "left",
  "insertIndex": 3,
  "insertOrientation": "b"
}
```

### `scout_and_show`

```json
{
  "action": "scout_and_show",
  "takeSide": "right",
  "insertIndex": 1,
  "insertOrientation": "a",
  "showStartIndex": 0,
  "showEndIndex": 2
}
```

## 9.3 推荐服务端校验顺序

### `show`

1. 当前玩家身份正确。
2. 当前状态允许 `Show`。
3. 区间合法。
4. 牌型合法。
5. 对 `activeSet` 的比较合法。
6. 扣手牌并更新台面。
7. 判断是否触发回合结束。
8. 若未结束，推进到下一玩家。

### `scout`

1. 当前玩家身份正确。
2. 当前状态允许 `Scout`。
3. `activeSet` 存在且不属于当前玩家。
4. 取牌端点合法。
5. 插入位置合法。
6. 若是 2 人局，检查 `scoutChipsLeft > 0` 并扣除。
7. 更新 `activeSet` 与玩家手牌。
8. 结算标记收益。
9. 根据人数决定是否切换玩家。
10. 判断是否触发回合结束。

## 10. 实现时建议固定的工程化推定

以下内容不是我从公开规则原文逐字看到的“句子”，但为了实现电子版，我建议固定为如下口径：

## 10.1 45 张牌按无序组合建模

- 牌 `1-7` 与 `7-1` 不应视为两张不同的牌。
- 一张牌只需要一个 `CardDef`，朝向由 `orientation` 决定。

## 10.2 `run` 的比较值用最高值

- 升序或降序不影响强度定义。
- 程序统一用 `Math.max(...values)` 即可。

## 10.3 `activeSet` 被 Scout 到只剩一部分时继续存在

- 例如 `7-7` 被拿走一张后，剩下的单张 `7` 仍是当前牌组。
- 只有当最后一张也被拿走时，台面才设为 `null`。

## 10.4 台面空时任何合法牌组都可 `Show`

- 这条不仅适用于开局，也适用于中途台面被挖空后的状态。

## 10.5 2 人局第二轮的起始玩家沿用“传起始标记”规则

- 公开资料能明确确认“第一轮由 `1-2` 持有者先手”和“每轮结束后起始玩家标记传给下一位玩家”。
- 因此第二轮应直接由另一位玩家先手，而不是重新按 `1-2` 定先手。
