# Design 12.1: Store & Load 机制

## 目标与范围
- 在房间开始游戏前提供“自动保存”开关。
- 开启自动保存后，每次游戏状态变化都落盘到 `.data/${roomId}/${state_version}.save`。
- 提供 Load 对话框，列出所有可加载的游戏：roomId、游戏类型、参与玩家。
- 选择后创建同 roomId 房间；若 roomId 已存在则报错并保持现状。

## 状态与数据模型

### Room 增量字段
- `auto_save: bool`：是否启用自动保存（默认 false）。
- `state_version: int`：保存序号，直接复用 `room.state_version`（每次游戏状态变化 +1）。

### 保存文件结构
路径：`.data/<room_id>/<state_version>.save`

建议使用 JSON，字段如下（最小可用集）：
```
{
  "room_id": "abc123",
  "game_type": "cabo",
  "room_status": "in_game",
  "state_version": 12,
  "saved_at": 1735689600,
  "players": [
    {
      "player_id": "...",
      "name": "Alice",
      "seat": 0,
      "is_bot": false,
      "ready": true,
      "reconnect_token": "..."
    }
  ],
  "game_state": { ... }
}
```
- `socket_id` / `connected` 不保存；加载后默认离线。
- `reconnect_token` 必须保存，确保玩家可以用本地缓存的凭证重连。

## 自动保存流程

### 触发点
- `room:start` 成功初始化游戏后（`state_version = 1`）立即保存一次。
- `game:action` 或 bot 行动导致 `state_version` 增加后保存。
- 若游戏进入 `game_over`，仍保存该最终状态。

### 写盘策略
- 写盘函数：`_save_room_state(room)`。
- 确保 `.data/<room_id>/` 目录存在。
- 先写入临时文件（例如 `.tmp`），再原子重命名为 `<state_version>.save`，避免半写入文件。

## Load 列表与加载流程

### 列表（客户端弹窗）
- 新事件：`room:load_list`（client -> server），返回 `room:load_list`（server -> client）。
- 服务端遍历 `.data/` 下所有 room 目录：
- 取文件名中最大的 `state_version` 作为最新快照。
  - 读取该快照中的 `room_id / game_type / players / saved_at`。
- 返回结构示例：
```
{
  "saves": [
    {
      "room_id": "abc123",
      "game_type": "cabo",
      "players": [{"name": "Alice", "is_bot": false}],
      "saved_at": 1735689600,
      "state_version": 12
    }
  ]
}
```

### 加载
- 新事件：`room:load`（client -> server），参数 `{room_id}`。
- 服务端流程：
  1. 若 `room_id` 已存在于 `ROOMS`，返回错误（例如 `room:load_result`）。
  2. 查找 `.data/<room_id>/` 的最新快照并解析 JSON。
  3. 校验 `game_type` 存在、`game_state` 可用。
  4. 构建 `Room`：
     - `room_id` 使用保存值；`game_type`/`status`/`state_version` 从保存值恢复。
     - 玩家列表按保存值恢复 `player_id / name / seat / is_bot / reconnect_token / ready`。
     - `socket_id=None`，`connected=False`。
  5. 写入 `ROOMS` 并广播 `room:list_update`。
- 返回 `room:load_result {ok, room_id, message?}`。

### 客户端行为
- 在大厅添加“Load”按钮，点击后拉取 `room:load_list` 并展示对话框。
- 对话框每条记录显示：roomId、gameType、玩家名（含 bot 标记）。
- 选择“Load”后发送 `room:load`；成功后：
  - 若本地缓存中已有该 roomId 的 `player_id` / `reconnect_token`，自动 `room:reconnect`。
  - 否则提示用户使用“Reconnect”或加入新房间（取决于玩法需求）。

## 错误处理与边界
- 同名房间冲突：直接报错，不覆盖现有房间。
- 保存文件缺失 / 解析失败：在列表中忽略或返回错误提示。
- `game_type` 不存在：加载失败并提示。
- 无保存记录：列表为空态提示。

## 兼容性与配置
- 需要在 `.gitignore` 中加入 `.data/`，避免保存文件进入版本库。
- 可选增加最大保留快照数（例如只保留最近 N 个），但 MVP 可不实现。

## 测试建议（MVP）
- 保存：触发 `room:start` 与 `game:action` 后生成对应 `state_seq` 文件。
- 列表：同一 room 多个快照时只返回最新一条。
- 加载：
  - roomId 冲突时返回错误。
  - 正常加载后 `ROOMS` 中状态、玩家信息、`state_version` 与快照一致。
