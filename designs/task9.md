# 猜狐狸 / 帕瓦仪式 (Pow Wow / Coyote) 规则说明

## 1. 游戏目标
推测场上**所有玩家**（包括你自己）头顶羽毛数值的**总和**。
* **胜利条件**：成为最后一名未被淘汰的玩家。
* **淘汰条件**：通常集齐 3 个惩罚标记（如秃鹫/弹孔）即出局。

---

## 2. 游戏流程

### 准备阶段
1.  每位玩家佩戴头带。
2.  洗混羽毛牌堆，面朝下放置。
3.  每人抽一张插在头带上。
    * **重点**：只能看别人的牌，**绝对不可看自己的牌**。

### 回合阶段（轮流行动）
按顺时针方向，轮到你时**二选一**：

**A. 报数 (Bid)**
* 报出一个数字，猜测当前场上的**总和**。
* **限制**：你报的数字必须**大于**上家报出的数字。

**B. 质疑 (Challenge / Coyote!)**
* 当你认为上家报数**超过**了实际总和，大喊“**开！**”。
* 所有人摘牌，结算数值。

### 结算阶段
计算所有牌的实际总和：
* **实际总和 < 上家报数**：质疑成功，**上家**（报数者）输，受罚。
* **实际总和 ≥ 上家报数**：质疑失败，**你**（质疑者）输，受罚。

---

## 3. 羽毛列表 (牌表)

### 基础数字牌
直接进行加减运算。

| 牌面 | 数量 | 说明 |
| :--- | :--- | :--- |
| **0** | 4 | 无数值 |
| **1 ~ 5** | 各4 | 小数字 |
| **10** | 3 | 中等数字 |
| **15** | 2 | 大数字 |
| **20** | 1 | 最大基础数字，极具干扰性 |
| **-5** | 2 | 负数 |
| **-10** | 1 | 大负数 |

### 特殊功能牌 (按顺序结算)
必须严格按照以下 **1 -> 2 -> 3** 的优先级顺序结算总和。

#### 1. 归零牌 (Max -> 0)
* **图标**：通常是一个划掉的红圈或写着 Max=0。
* **效果**：场上数值**最大**的那根数字牌变为 **0**。
* *注：仅对正数生效；若有多张最大牌，只变一张（通常效果一样）。*

#### 2. 神秘牌 (?)
* **图标**：问号。
* **效果**：从牌堆顶**再抽一张牌**，将其数值或效果加入计算。
* *注：若抽到特殊牌，继续递归结算。*

#### 3. 翻倍牌 (x2)
* **图标**：x2 或 酋长头像。
* **效果**：将上述所有步骤计算完后的总和 **乘以 2**。
* *注：若场上有两张 x2，则变为 x4。*

---

## 4. 结算示例
**场况**：玩家A(20), 玩家B(Max->0), 玩家C(5)
1.  **原始数字**：20 + 5 = 25
2.  **处理 Max->0**：最大的 20 变为 0
3.  **最终总和**：0 + 5 = **5**

*(若上家叫价 6，则上家输；若上家叫价 5，则质疑者输)*

- 提示框中需要显示“我自己的隐藏牌”。

- Bid 输入框默认填入“当前合法的最小 bid”，并提供 `+` / `-` 按钮便于调整。

## 2026-11-21 UI 与策略 AI 优化

### UI 与交互

- 主体直接使用共享 Game 面板，标题改为 Coyote。Help 与 Explain 通过 header template 按需加载，遵循 Room Control 的移动/停靠约定，不重复嵌套游戏外框。
- 暖沙色牌桌突出所有玩家的牌，自己的隐藏牌使用紫色背纹，负数使用青绿色，特殊牌使用紫色。当前报价和报价者以红色强调，当前行动者有描边。
- 桌面按玩家数量动态分成一至两排，报价位于侧边。手机将报价和加减输入置于牌桌上方，320px 使用两列，390px 使用三列，不通过缩小文字挤出三列。
- 报价默认等于当前合法最小值，严格校验正整数。发送后暂时锁定按钮，收到新状态或错误后恢复，断线禁止行动。没有报价时不能质疑。
- 质疑后进入 `round_end`，不立即重洗牌。结算明确展示报价、实际总和、受罚者、每张牌、自己的牌、问号抽牌、归零数值和最终倍数。
- 所有座位（包括已淘汰玩家）确认 `next_round` 后才发下一轮牌，Bot 自动确认，观察者无须确认。确认期间禁止报价/质疑，重复确认被拒绝。保存恢复保留确认进度与下一轮先手。
- 结算时收起失效的报价操作，避免小屏重复展示结果。下一轮把上一轮详情折叠到下方，并限制展开区高度与内部滚动。终局保留揭牌并允许座位玩家 Play Again。
- 修正旧 Help 中“只能看自己的牌”和“特殊牌均不可见”的错误。Help 提供中英切换与章节，说明引擎实际结算顺序、平价质疑失败、惩罚与全员确认。
- Explain 包括禁用按钮和动态牌面效果，解释点击不执行行动，支持 Escape。普通信息悬停或点击显示短提示，点击后 3 秒隐藏，滚动/窗口变化关闭，不在交互按钮上弹提示。
- Room Control 收起时，本人行动使用红色边框提醒。保留共享 Reconnect、日志和观察者行为，非游戏 UI 使用英文。没有引入外部或商业素材。

### AI 设计

- `game/coyote_ai.py` 的决策入口只接收 viewer-specific public view，不接触自己的真实牌、剩余牌堆或牌堆顺序。上一轮自己的牌不用于推断新洗的牌堆。
- 从 36 张固定牌池扣除所有可见的存活对手牌，按剩余副本数精确枚举自己的未知牌。若存在问号，再按不放回抽样枚举问号抽牌。
- 复用规则引擎计算归零、问号、翻倍，避免独立实现的顺序偏差。分布按可见牌缓存，不引入模型、网络调用或额外依赖。
- 对合法候选报价（最低合法值及可能总和值）逐个估值。对每种自己的牌假设，重建下一位玩家能看到的信息，估计其质疑概率，并结合该假设下真实总和分布计算被质疑的收益和损失。
- 质疑的期望值与最佳加价比较。惩罚越接近淘汰，承担自身风险的代价越高。对其他玩家的淘汰收益按对手人数折减，兼顾多人桌的生存。
- 对手质疑和后续延续价值是启发式模型，并非 Nash 均衡求解，也不宣称对真人最优。未使用跨轮学习或读取他人私有信息。
- `bot_move` 仍支持现有调度器，结算阶段自动提交一次确认，整局结束或不在合法行动时不返回行动。Select Game 通过策略 AI catalog 显示 Bot(🤖)。
