# 《迷失代码》（The Lost Code）玩法规则与电子版实现说明

> 说明
>
> - 本文对应的游戏是 `The Lost Code`，官方中文盒面名可见《迷失代码》。
> - 目标不是写“新手速读版”，而是把规则拆到足够实现电子版。
> - 文中我会区分三类信息：
>   - `官方明确`：能从官方规则书、官方页面或官方产品图直接确认。
>   - `交叉确认`：来自不同官方版本规则或官方产品图之间的互相印证。
>   - `实现推断`：为了做电子版必须明确，但公开资料没有完全写死，我给出最稳妥的落地方案。

## 一、版本范围与来源

### 1. 本文覆盖的规则范围

`官方明确`

我本次整理的是《迷失代码》标准规则，并额外覆盖：

- `Introductory version`：入门模式，去掉红色熊符号。
- `X-Race Variant`：加入 `8` 号石并翻转轮盘到 `X` 面。
- `Deadly Shortcut`：捷径扩展。
- `Curse of the Temple`：诅咒扩展。

规则书明确说：

- 支持 `2-4` 人。
- 所有日志架（log）在任意人数下都要摆上桌。
- `1` 个变体与 `2` 个扩展可以组合使用。

### 3. 两版规则里“48 石”和“54 石”的差异说明

`交叉确认`

公开资料看起来有两种写法：

- Mojito 规则书把基础组件写成 `48` 张石板，即 `6` 种符号各 `0-7`。
- Studio Giochi 页面把总组件写成 `54` 张石板，即 `6` 种符号各 `0-8`。

这两者并不矛盾，合理解释是：

- 实物总组件确实是 `54` 张。
- 标准局只用 `0-7`，所以“基础局入局组件”是 `48` 张。
- `6` 张 `8` 号石只在 `X-Race Variant` 中启用。

电子版建议也按这个边界建模：

- `standard` / `intro`：每个符号可用数字是 `0-7`
- `x_race`：每个符号可用数字是 `0-8`

## 二、游戏目标与核心机制

`官方明确`

每名玩家面前都有一条自己的“代码”，代码由若干块数字石组成，但你看不到自己这些石块上的数字，只能看到别人的。

游戏每轮掷 `3` 颗自定义骰，骰面给出 `3` 个符号。  
你要根据这 `3` 个符号，对自己对应 `3` 块石头数字之和做一个“区间猜测”。

例如骰子结果是：

- 蓝鸟
- 黄豹
- 粉人

那么你要猜的是：

`自己的蓝鸟数字 + 自己的黄豹数字 + 自己的粉人数字`

如果某个符号出现多次，就按出现次数重复计入：

- 若骰子是 `紫变色龙、紫变色龙、绿蛇`
- 你猜的是 `2 * 自己的紫变色龙数字 + 1 * 自己的绿蛇数字`

游戏前半段通过连续多轮“区间猜测”拿分并缩小自己代码的可能范围，  
游戏后半段在终局时对自己每个符号的确切数字做最终猜测。  
最终分数最高者获胜。

## 三、符号、组件与电子版必须建模的对象

### 1. 六种符号

`官方明确`

公开资料中的符号与配色对应为：

- `bird_blue`：蓝鸟
- `jaguar_yellow`：黄豹
- `chameleon_purple`：紫变色龙
- `snake_green`：绿蛇
- `human_pink`：粉人
- `bear_red`：红熊

入门模式不使用 `bear_red`。

### 2. 实体组件

`官方明确 + 交叉确认`

- `4` 个日志架（log）
- `54` 张石板总量
  - 标准局实际入局：`6 * 8 = 48`
  - `X-Race` 额外启用 `6` 张 `8` 号石
- `3` 颗自定义骰
- `7` 个双面猜测轮盘
- `4` 个玩家棋子
- `4` 个玩家屏风
- `1` 本记录纸（deduction pad）
- `6` 个 `Deadly Shortcut` 标记
- `1` 个 `Curse of the Temple` 标记
- `1` 张游戏板

### 3. 电子版建议的数据结构

下面是最稳妥的状态拆分。

```ts
type SymbolId =
  | "bird_blue"
  | "jaguar_yellow"
  | "chameleon_purple"
  | "snake_green"
  | "human_pink"
  | "bear_red";

type Stone = {
  id: string;
  symbol: SymbolId;
  value: number; // 0-7，X-Race 可到 8
};

type LogSlot = {
  symbol: SymbolId;
  stone_id: string;
};

type LogState = {
  owner_player_id: string | null; // null 表示中立日志架
  slots: LogSlot[]; // 固定按符号顺序摆放
};

type WheelState = {
  id: string;
  window_size: number;
  victory_points: number;
  x_side: boolean;
  used_this_round: boolean;
};

type PlayerState = {
  id: string;
  color: string;
  log_id: string;
  score: number;
  stack_order: number; // 同分堆叠顺序，越大表示越靠上
  shortcut_commits: Partial<Record<SymbolId, number[]>>;
  final_guesses: Partial<Record<SymbolId, number[]>>;
};

type GameState = {
  mode: "standard" | "intro" | "x_race";
  enabled_expansions: {
    deadly_shortcut: boolean;
    curse_of_the_temple: boolean;
  };
  active_symbols: SymbolId[];
  round: number;
  max_rounds: number;
  phase:
    | "roll_dice"
    | "offer_shortcut_token"
    | "modify_die"
    | "choose_wheels"
    | "resolve_guesses"
    | "exchange_stones"
    | "final_guess_submit"
    | "final_guess_resolve"
    | "game_over";
  logs: LogState[];
  symbol_draw_piles: Record<SymbolId, string[]>; // face-down piles
  out_of_game_stone_ids: Record<SymbolId, string>; // 每个符号有 1 张彻底移出游戏
  wheels: WheelState[];
  dice_symbols: SymbolId[];
  current_round_guess_order: string[]; // 本轮从后到前
  current_round_guesses: Record<
    string,
    {
      wheel_id: string;
      min: number;
      max: number;
      actual_sum: number;
      result: "correct" | "wrong_low" | "wrong_high";
    }
  >;
  deadly_shortcut_tokens: Partial<Record<SymbolId, { taken_by: string | null }>>;
  cursed_player_id: string | null;
  winner_ids: string[];
};
```

### 4. 可见性规则

`官方明确 + 实现推断`

这是电子版最关键的保密逻辑。

对任意一个“当前仍在日志架中的石头”：

- 该石头所属玩家：只能看到符号，不能看到数字。
- 其他玩家：可以看到该石头的数字和符号。

对下列信息，所有人公开：

- 中立日志架上的石头
- 已被弃掉、面朝上的旧石头
- 骰子结果
- 每名玩家本轮选了哪个轮盘、轮盘显示的区间
- 分数与棋子堆叠顺序
- 哪些扩展标记已被拿走

对下列信息，只对本人可见：

- 记录纸内容
- `Deadly Shortcut` 提前写下的终局数字
- 终局阶段正式提交前的最终猜测

## 四、准备阶段（Setup）

### 1. 选择模式

电子版开局先固定：

- 玩家数：`2-4`
- 是否启用 `intro`
- 是否启用 `x_race`
- 是否启用 `deadly_shortcut`
- 是否启用 `curse_of_the_temple`

规则允许：

- `x_race` 与两个扩展一起开
- `intro` 本质上是教学模式，通常不与其他模块混用，但规则书没有给出硬性禁令

实现时建议：

- 公开房默认只开放 `standard`
- 高级房再开放 `intro / x_race / expansions`

### 2. 符号池与数字域

`官方明确`

- `standard`：`6` 种符号，每种数字 `0-7`
- `intro`：去掉 `bear_red`，其余 `5` 种符号仍用 `0-7`
- `x_race`：`6` 种符号，每种数字 `0-8`

### 3. 摆放日志架

`官方明确`

- 每位真实玩家面前放 `1` 个日志架。
- 若少于 `4` 人，剩余日志架也照样摆上桌，当作中立日志架。
- 所有日志架都会被填入石头。

这意味着：

- `2` 人局有 `2` 个中立日志架。
- `3` 人局有 `1` 个中立日志架。
- `4` 人局没有中立日志架。

### 4. 设定起始分数与堆叠顺序

`官方明确`

- 所有人棋子都放在分数轨 `0`
- 棋子随机叠成一摞

这摞棋子的顺序不是装饰，而是规则的一部分：

- 同分时，`最上面` 的棋子视为更靠后。
- 第一轮掷骰者就是当前分数最靠后的玩家，所以开始时等于从这摞里最上面的那位开始。

电子版应在服务器端随机一个初始 `stack_order`。

### 5. 猜测轮盘的设置

`官方明确`

- 基础局把轮盘摆在“不带白色 X”的那一面朝上。
- `x_race` 模式把轮盘翻到 `X` 面。
- 每个轮盘有自己对应的板上槽位。

### 6. 石头的发放算法

`官方明确 + 实现推断`

最稳妥的电子版做法，是把每个符号独立处理。

对每个启用的符号执行：

1. 生成该符号的数字池。
   - `standard / intro`：`[0,1,2,3,4,5,6,7]`
   - `x_race`：`[0,1,2,3,4,5,6,7,8]`
2. 洗牌。
3. 按“4 个日志架固定都要填”的规则，给 `4` 个日志架各发 `1` 张。
4. 再把同符号的 `1` 张石头暗置移出本局，不再使用。
5. 剩余石头构成该符号的暗置补牌堆。

因此，标准局下每个符号的数量分布是：

- `4` 张在日志架中
- `1` 张彻底移出游戏
- `3` 张留在该符号补牌堆里

`x_race` 下则是：

- `4` 张在日志架中
- `1` 张移出游戏
- `4` 张留在补牌堆里

### 7. 日志架内部的槽位顺序

`实现推断`

规则强调日志架最好按记录纸的同一符号顺序摆。  
电子版应直接固定槽位顺序，推荐使用：

1. `bird_blue`
2. `jaguar_yellow`
3. `chameleon_purple`
4. `snake_green`
5. `human_pink`
6. `bear_red`

入门模式则只保留前 `5` 个有效槽位。

## 五、分数轨与同分判定

### 1. 一般移动规则

`官方明确`

玩家获得或失去分数时，在分数轨上前进或后退对应格数。  
若落到已有棋子的格子上，把自己的棋子放到这摞棋子的最上方。

### 2. “更靠后”的定义

`官方明确`

在需要从“落后者到领先者”排序时：

- 先按分数从低到高排
- 同分时，`堆顶` 的棋子视为更靠后

这条规则会影响：

- 本轮谁掷骰
- 本轮谁先选轮盘
- 本轮谁先得知猜测结果
- 猜错后谁先换石
- 终局猜数字时谁先结算

### 3. 最终平局规则

`官方明确`

游戏结束时若最高分并列：

- 并列那一摞里 `最底部` 的玩家获胜

也就是说：

- 平时判“谁更靠后”看堆顶
- 终局判“谁赢”看堆底

这个差异必须单独实现，不能偷懒复用同一个比较器。

## 六、每轮流程

`官方明确`

每轮固定分三步：

1. `Throw the dice`
2. `Make the guesses`
3. `Check the guesses and score points`

下面按电子版实现顺序展开。

### 1. 第一步：掷骰

#### 1.1 谁来掷

`官方明确`

当前分数最靠后的玩家掷 `3` 颗骰子。  
同分时由堆顶玩家掷。

#### 1.2 掷完后的改骰权限

`官方明确`

掷骰者看完结果后，可以：

- 直接接受结果
- 或把 `1` 颗骰子改成自己指定的任意符号

这是“改面”，不是重掷。

#### 1.3 入门模式的红熊处理

`官方明确`

入门模式没有红熊符号，因此：

- 如果掷出 `1` 个或多个红熊
- 掷骰者必须把这些红熊骰都改成任意其他有效符号

#### 1.4 本轮目标和的计算

`官方明确`

设 `count[symbol]` 表示本轮 `3` 颗骰子里该符号出现的次数。  
则任意玩家的真实目标和为：

```ts
actual_sum(player) =
  sum_over_active_symbols(
    player.log[symbol].value * count[symbol]
  );
```

标准局与入门局的理论最大和都是：

- `7 + 7 + 7 = 21`

`x_race` 的理论最大和是：

- `8 + 8 + 8 = 24`

### 2. 第二步：选择轮盘并做区间猜测

#### 2.1 选择顺序

`官方明确`

从当前分数最靠后的玩家开始，依次到最领先的玩家。

也就是：

- 掷骰者先选轮盘
- 当前最领先的人最后选轮盘

#### 2.2 轮盘使用规则

`官方明确`

- 每个轮盘一轮只能被一个玩家使用一次。
- 该轮结束后，所有轮盘回到公共区，下轮重新可用。
- 玩家要把轮盘转到自己想猜的连续区间。

#### 2.3 猜的是“区间”不是“精确值”

`官方明确`

玩家不是猜精确和，而是猜：

- 一个连续整数区间 `[min, max]`
- 并希望自己的真实目标和落在这个区间内

电子版的合法性校验应为：

```ts
is_valid_guess =
  range_is_contiguous &&
  (max - min + 1) === wheel.window_size &&
  min >= 0 &&
  max <= max_sum_for_mode;
```

#### 2.4 轮盘档位与分值

`官方明确 + 交叉确认 + 实现推断`

官方能直接确认到这些点：

- 一共 `7` 个轮盘
- 分值分布是：
  - `1` 个 `1 VP`
  - `2` 个 `2 VP`
  - `2` 个 `3 VP`
  - `1` 个 `4 VP`
  - `1` 个 `5 VP`
- 存在一个“最小轮盘”，它给分最高
- 官方示例明确：
  - `1-5` 这个区间对应的轮盘给 `2 VP`
  - 存在一个“显示 7 个数字”的轮盘
  - 存在一个“显示 10 个数字”的轮盘

基于这些官方信息，最合理且自洽的电子版落地表是：

| 轮盘 | 区间宽度 | 得分 | 依据 |
| --- | ---: | ---: | --- |
| `W1` | `1` | `5` | 最小轮盘、最高分 |
| `W2` | `2` | `4` | 分值分布 + 递进推断 |
| `W3` | `3` | `3` | 分值分布 + 递进推断 |
| `W4` | `4` | `3` | 分值分布 + 递进推断 |
| `W5` | `5` | `2` | 官方 `1-5 => 2 VP` 示例 |
| `W6` | `7` | `2` | 官方明确存在 `7` 格轮盘 |
| `W7` | `10` | `1` | 官方明确存在 `10` 格轮盘 |

这张表足以实现“规则正确”的电子版。  
但如果你要做的是“严格 1:1 复刻实体轮盘 UI”，本文末尾会说明：轮盘高清平铺图仍是缺失资源，最好以后再复核。

#### 2.5 `X-Race` 模式的轮盘

`官方明确 + 实现推断`

规则书只明确说：

- `x_race` 要把轮盘翻到 `X` 面
- 因为加入了 `8` 号石，轮盘显示值会改变

公开资料没有给出完整 `X` 面平铺图。  
电子版最稳妥的实现推断是：

- `X` 面仍使用同一套 `window_size`
- 只是把可滑动区间域从 `0-21` 扩展到 `0-24`

### 3. 第三步：核对猜测与计分

#### 3.1 结算顺序

`官方明确`

从掷骰者开始，按本轮的“从后到前”顺序逐个结算。

#### 3.2 猜对时怎么结算

`官方明确`

若玩家真实目标和位于自己选择的区间内：

- 该玩家获得该轮盘对应的胜利点
- 在记录纸右侧记录这个区间

电子版可直接记为：

```ts
if (min <= actual_sum && actual_sum <= max) {
  result = "correct";
  score_delta = wheel.victory_points;
}
```

#### 3.3 猜错时别人要反馈什么

`官方明确`

若猜错：

- 其他玩家必须告诉你，真实目标和是 `更小` 还是 `更大`
- 他们必须说真话

但有一个例外：

- 如果你选的是“最小轮盘”
- 别人不能告诉你高了还是低了
- 只能告诉你“对 / 不对”

#### 3.4 猜错时记录什么区间

`官方明确 + 实现推断`

规则书要求：

- 如果你猜错，就把“正确答案所在的大区间”写在你猜的区间上方或下方

电子版可直接换算成：

```ts
if (actual_sum < min) {
  result = "wrong_low";
  implied_range = [0, min - 1];
}

if (actual_sum > max) {
  result = "wrong_high";
  implied_range = [max + 1, max_sum_for_mode];
}
```

若使用最小轮盘猜错：

- 记录层面你只知道“不在这个单点里”
- 但服务器端当然仍知道真实是高是低
- UI 不应把“高 / 低”信息泄露给该玩家

### 4. 猜错后的换石阶段

#### 4.1 谁要换石

`官方明确`

只有本轮区间猜错的玩家要换石。

#### 4.2 换石顺序

`官方明确`

还是按本轮“从后到前”的顺序：

- 当前最后者先换
- 当前领先者最后换

#### 4.3 可以换哪一块石头

`官方明确`

猜错玩家可以从自己日志架里任选 `1` 块石头丢弃，  
但前提是该符号的补牌堆里至少还剩 `1` 张。

换言之：

- 你不能弃掉一个“已经没有同符号补牌可抽”的位置
- 如果所有符号补牌堆都空了，才可以跳过换石
- 只要还有任何一个合法位置可换，就不能跳过

#### 4.4 换石具体动作

`官方明确`

1. 从自己日志架中选 `1` 个合法槽位。
2. 把原石头面朝上丢到自己旁边。
3. 所有人都能看到这块旧石头。
4. 从同符号补牌堆抽 `1` 张新石头，暗置插回原槽位。
5. 该玩家本人不能看新石头数字，但其他玩家能看到。

电子版服务端应保证：

- 本轮所有区间判定先基于“换石前”的日志架计算。
- 换石只影响后续轮次，不反向影响本轮已结算的真假。

#### 4.5 为什么要记录被弃掉的数字

`官方明确`

实体记录纸要求玩家把被弃掉的数字彻底涂黑，并把它记到当轮骰子列上。  
原因是：

- 你知道某符号曾经在某轮与其他符号一起出现
- 而你现在知道那一轮里这个符号旧值是多少
- 于是能反推出其他符号更多信息

电子版如果不想复刻整张纸，也至少应该提供：

- 旧石头公开历史
- 每轮骰子历史
- 可选的笔记面板

### 5. 回合结束

`官方明确`

当本轮所有错误玩家都完成换石后：

- 所有轮盘回到公共区
- 进入下一轮

## 七、终局与最终猜数

### 1. 游戏何时结束常规轮次

`官方明确`

- `4` 人局：`8` 轮
- `3` 人局：`9` 轮
- `2` 人局：`10` 轮

### 2. 终局猜数阶段的目标

`官方明确`

常规轮次结束后，不再猜“区间和”，  
而是对自己日志架中的每个符号，直接猜它的确切数字。

### 3. 每个符号允许写几个答案

`官方明确`

对每个符号，你可以写：

- `1` 个答案
- `2` 个答案
- `3` 个答案
- 或者一个都不写

电子版提交结构建议就是：

```ts
final_guesses[symbol] = [];        // 0 个
final_guesses[symbol] = [n1];      // 1 个
final_guesses[symbol] = [n1, n2];  // 2 个
final_guesses[symbol] = [n1, n2, n3]; // 3 个
```

### 4. 最终猜数的结算顺序

`官方明确`

从当前分数最靠后的玩家开始，依次到最领先的玩家。

### 5. 每个符号的得分

`官方明确`

对单个符号：

- 若你只写 `1` 个数字且猜中：`+5`
- 若你写 `2` 个数字且其中一个猜中：`+2`
- 若你写 `3` 个数字且其中一个猜中：`+1`
- 若你没写，或写了但全错：`-2`

因此电子版的单符号结算可写成：

```ts
function score_final_guess(actual: number, guesses: number[]): number {
  if (guesses.length === 1) return guesses.includes(actual) ? 5 : -2;
  if (guesses.length === 2) return guesses.includes(actual) ? 2 : -2;
  if (guesses.length === 3) return guesses.includes(actual) ? 1 : -2;
  return -2;
}
```

### 6. 终局胜负

`官方明确`

把所有符号的终局猜数得分加总后，移动棋子。  
最终分数最高者获胜。

若并列最高：

- 并列那一摞中 `最底部` 的玩家获胜。

## 八、扩展与变体

## 1. 入门模式（Introductory version）

`官方明确`

作用：

- 给新手或儿童简化信息量

规则变化：

- 去掉 `bear_red` 全部石头
- 红熊不出现在有效符号池里
- 若骰子掷出红熊，掷骰者必须把该骰改成其他任意有效符号

电子版实现要点：

- `active_symbols` 只保留前 `5` 个
- 每个日志架只放 `5` 块有效石头
- 红熊列在记录纸 / UI 中隐藏或禁用

## 2. `X-Race Variant`

`官方明确`

规则变化：

- 把 `8` 号石加入游戏
- 轮盘翻到 `X` 面
- 其他规则保持不变

电子版实现要点：

- 每个启用符号的取值域变为 `0-8`
- 理论最大和改为 `24`
- 记录纸中 `8` 这一行不能被预先涂掉

## 3. `Deadly Shortcut`

### 3.1 额外组件

`官方明确`

- `6` 个符号标记，每个符号 `1` 个

### 3.2 标记触发时机

`官方明确`

当掷完骰后，如果 `3` 颗骰里有某个符号出现了 `2` 次或 `3` 次：

- 对应符号的 `Deadly Shortcut` 标记会被触发

### 3.3 标记的领取顺序

`官方明确`

从当前分数最靠后的玩家开始，依次询问是否领取。  
掷骰者作为当前最后者，拥有第一个决定权。

### 3.4 改骰与领取的先后

`官方明确`

这条很容易写错：

- 必须先完成 `Deadly Shortcut` 是否领取的流程
- 然后掷骰者才可以改 `1` 颗骰

也就是说：

- 标记只看“原始掷骰结果”
- 不看改骰后的结果

### 3.5 领取后要做什么

`官方明确`

玩家一旦领取某个符号标记，就必须立刻：

- 对这个符号提前写下终局猜测
- 写 `1-3` 个数字都可以
- 然后把标记放到自己屏风后

该符号标记本局不能再被使用。

电子版实现建议：

- 领取标记后，立即在服务器里写入 `shortcut_commits[symbol]`
- 这个字段一旦写入，不允许后续修改
- 终局正式猜数阶段，该符号输入框直接锁死

### 3.6 终局计分

`官方明确`

若这个提前提交的符号最终猜对：

- 写 `1` 个数字猜中：`+10`
- 写 `2` 个数字猜中：`+4`
- 写 `3` 个数字猜中：`+2`

若最终猜错：

- `-4`

也就是说它等于“把正常终局该符号的得分翻倍”。

### 3.7 何时移除未用标记

`官方明确`

最后 `3` 个回合不能再使用这些标记，因此：

- `2` 人局：第 `7` 轮结束后移除未用标记
- `3` 人局：第 `6` 轮结束后移除未用标记
- `4` 人局：第 `5` 轮结束后移除未用标记

## 4. `Curse of the Temple`

### 4.1 额外组件

`官方明确`

- `1` 个诅咒标记

### 4.2 谁会先拿到诅咒

`官方明确`

在某轮的区间猜测计分过程中：

- 第一个达到或超过分数轨 `7` 的玩家
- 立刻拿到诅咒标记

### 4.3 被诅咒玩家的额外收益

`官方明确`

被诅咒时，如果你本轮猜对自己的区间：

- 你照常获得该轮盘分数
- 另外，本轮每有 `1` 名其他玩家猜错，你再额外得到 `1 VP`

### 4.4 被诅咒玩家猜错时的惩罚

`官方明确`

如果你是被诅咒玩家，且你自己的区间猜错：

- 你要失去你所选轮盘的分值
- 棋子在分数轨上后退该数值
- 然后仍然照常执行“换石”

例如你选的是 `2 VP` 轮盘并猜错：

- 不是 `0`
- 而是 `-2`

### 4.5 诅咒何时移除或转移

`官方明确`

每轮区间计分完成、下一轮开始前：

1. 检查是否至少有一名玩家到达或超过 `13`
2. 如果是，诅咒标记永久移出游戏
3. 如果否，诅咒标记转交给当前分数最领先的玩家

这里的同分判定与“谁更靠后”不同。  
规则书明确写的是：

- 同分时，`堆底` 玩家获得诅咒

所以这里要用“领先比较器”，不是“落后比较器”。

### 4.6 诅咒的强制移除时点

`官方明确`

即便没人到 `13`，最后一轮开始前也要把诅咒标记移出游戏：

- `2` 人局：第 `9` 轮结束后移除
- `3` 人局：第 `8` 轮结束后移除
- `4` 人局：第 `7` 轮结束后移除

## 九、电子版实现时最容易写错的规则点

### 1. 所有人日志架都要摆满

`官方明确`

即使 `2` 人局也不是“只放 2 条代码”。  
而是始终有 `4` 条日志架，其中多出来的是公开的中立代码。

### 2. 玩家看不到自己的当前数字，但看得到自己弃掉的旧数字

`官方明确`

被替换掉的石头会面朝上弃置，因此所有人，包括该玩家自己，都会知道旧值。

### 3. 换石抽的是“同符号补牌堆”

`官方明确`

不是从公共大牌堆抽，也不是任意补。  
只能从同符号剩余堆里抽。

### 4. 改骰不是重掷

`官方明确`

掷骰者不是重新扔一颗骰，而是把某颗骰直接改成任意有效符号。

### 5. `Deadly Shortcut` 先于改骰

`官方明确`

若扩展开着，先问要不要拿标记，再决定是否改骰。

### 6. 最小轮盘猜错时，不透露高低

`官方明确`

这个例外要单独处理，不要给客户端自动生成“更高 / 更低”的提示。

### 7. 终局平分时看堆底，不是堆顶

`官方明确`

平时“谁更靠后”看堆顶，终局平手胜利却看堆底。  
两套比较规则必须分开写。

### 8. 终局猜数可以留空

`官方明确`

规则书明确把“没猜”与“猜错”一起记为 `-2`。  
因此 UI 不应强制每个符号至少填一个数字。

## 十、如果要直接做成电子版，建议固定的服务器裁定

下面这些并非实体玩家必须显式做的动作，但电子版最好服务器统一裁定。

### 1. 日志架固定槽位，不允许玩家重排

`实现推断`

实体版本来就按符号槽位摆，电子版没必要允许拖动换位。

### 2. 记录纸只做辅助 UI，不进权威状态

`实现推断`

真正权威的状态应该只有：

- 各日志架当前石头值
- 各补牌堆
- 当前骰面
- 当前轮盘选择
- 分数与堆叠
- 扩展标记归属
- 终局提交答案

记录纸、划叉、涂黑都应只是客户端笔记，不应该影响结算。

### 3. 分数允许存成普通整数

`实现推断`

规则书没有单独定义“不得低于 0”。  
服务端最好把分数存在普通整数里，再决定 UI 如何显示。

如果你不想做负分轨显示，最保守做法是：

- 内部状态允许负数
- 棋盘 UI 仍显示在 `0` 附近并额外标注数值

## 十二、结论

`结论`

如果你的目标是：

- 做一个规则正确、能完整跑完一局、支持 `2-4` 人、支持标准局和终局计分的电子版

那么本文已经足够落地实现核心逻辑。

如果你的目标是：

- 完整 1:1 复刻实体版组件与 UI

那么仍需补齐至少两类资源：

- 三颗骰子的逐面分布
- 七个轮盘两面的高清平铺图

在此之前，建议先按本文的“官方明确 + 实现推断”版本做可玩原型，再在拿到高清组件图后做一次参数复核。
