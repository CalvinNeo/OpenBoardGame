# 目标 1

你需要实现一个桌游平台，这个平台可以允许多个玩家通过联网进行对战，也可以添加 Bot。

这个平台首先需要一个足够通用的框架，然后基于这个框架，可以开发各种桌游，例如方舟动物园、CABO、Scout、你画我猜等。

这个平台应该是前端-后端架构，其中前端应该用 HTML 实现。

我们会在这个平台上实现 CABO 这个游戏，你可以通过网络搜索这个游戏的规则。

你需要向我输出你的技术选型，以及你的设计。

## CABO 策略 AI（2026-11-08）

- 以 `game/cabo_ai.py` 的纯函数策略替代随机 Bot，复用房间的 Add Bot、自动回合和下一轮确认机制；游戏目录通过已有的 🤖 标记展示策略支持。
- 策略仅接收当前玩家视角、公开牌堆配置和公开回合计数，不读取暗牌、牌库顺序或其他玩家的私有知识。根据配置牌数扣除当前可见牌，估算未知牌的分布；手牌总分使用独立抽样近似，不声称准确知道未知牌。
- 开局固定查看两个位置，后续仅对已知同值牌做匹配。比较换牌降分、保留或形成同值组合、消除手牌以及 Peek / Spy / Swap 的收益；技能没有收益时允许跳过。
- 对弃牌堆的确定收益与盲抽后的期望最优收益做比较。Peek 优先查看未知自牌，Spy 只查看未知对手牌，Swap 比较自身降分和对手增分；最后一回合不浪费行动查看无法继续利用的信息。
- 叫 CABO 时估算领先所有对手的概率、失败后的五分罚分及对手最后一次改牌的空间；零分和已完成 Shooting the Moon 时优先结束，长时间未结束时逐渐放宽阈值，24 轮座次循环后主动叫牌，避免 Bot 永久循环。
- 已经看过并换入手中的抽牌存入服务端私有记忆，失败匹配后加入的已见抽牌亦然。记忆在对应槽位被交换、替换、移除或新一轮发牌时清除；不改变真人视图原有的槽位可见性规则，也不向其他玩家公开该记忆。决策本身不修改游戏状态。
- 支持空槽位、失败匹配增加的槽位、自定义牌组、弃牌重洗、结算等待及游戏结束。补齐 `skip_choice` 动作的 schema，使主动放弃技能可通过统一动作校验。
- 验证覆盖隐藏信息不变性、动作 schema、每类技能与决策、私有记忆失效及序列化、2–5 人完整对局和策略目录元数据。本次不修改前端布局或交互资源。
