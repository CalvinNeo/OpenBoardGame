# 回答1

在此，我也要先**纠正一下我在第一份指南中的一个小口误**：关于 9 种拼块的分布，1 级和 2 级各 1 种形状，**3 级是 2 种形状**（直线、小拐角），**4 级是 5 种形状**（直线、大L、T型、方形、Z/S型），加起来刚好 9 种。

以下是针对你提出的疑点的逐一确认与详细解答：

### 1. 拼图卡的完整数据与牌库构成
由于版权和篇幅限制，我无法直接为你列出全部 52 张拼图卡的完整矩阵，但可以明确牌库的构成和数据结构标准：
* **白牌库 (White Deck)**：共 **32** 张。分数低（通常 0-2 分），奖励多为 1-3 级拼块，网格较小。
* **黑牌库 (Black Deck)**：共 **20** 张。分数高（通常 3-5 分），奖励多为 3-4 级拼块，网格较大且复杂。

**建议的数据结构 (JSON 示例)：**
```json
{
  "card_id": "W01", 
  "deck_type": "white", 
  "points": 1, 
  "reward_piece_id": "L3_V", 
  "grid_matrix": [
    [1, 1, 1],
    [1, 0, 0]
  ] 
}
```

### 2. 9 种拼块的 ID 与形状矩阵 (Shape Matrix)
为了方便旋转和碰撞检测，建议使用包裹形状的最小二维数组，`1` 代表实体，`0` 代表留空。

* **1级 (1种)**
    * `L1_I` (黄): `[[1]]`
* **2级 (1种)**
    * `L2_I` (绿): `[[1, 1]]`
* **3级 (2种)**
    * `L3_I` (橙-3格直线): `[[1, 1, 1]]`
    * `L3_V` (蓝-小拐角): `[[1, 1], [1, 0]]`
* **4级 (5种)**
    * `L4_I` (粉-4格直线): `[[1, 1, 1, 1]]`
    * `L4_O` (青-2x2方形): `[[1, 1], [1, 1]]`
    * `L4_T` (薄荷-T型): `[[1, 1, 1], [0, 1, 0]]`
    * `L4_L` (紫-大L型): `[[1, 1, 1], [1, 0, 0]]`
    * `L4_Z` (橄榄-Z/S型): `[[1, 1, 0], [0, 1, 1]]` *(注：Z型翻转即为S型，电子版只需存一个基础矩阵，通过矩阵翻转算法实现另一种形态)*

### 3. 供应堆的库存限制
* **规则确认**：在实体桌游中，规则书明确指出**拼块数量是无限的**。如果某种实体拼块耗尽，玩家可以使用替代物。
* **开发建议**：在电子版中，直接将公共供应堆设置为**无限量 (Infinite)**。这样可以省去处理“库存耗尽无法 Take/Upgrade”的复杂逻辑。

### 4. 牌库抽空与市场补牌
* **空位处理**：如果对应牌库已空，市场被拿走的空位**保持为空**，不再补充。
* **盲抽限制**：如果牌库已空，玩家**无法**再执行“从该牌库盲抽”的行动。

### 5. “盲抽”的公开性
* **规则确认**：桌游《L计划》中**没有任何隐藏信息**。
* **执行方式**：玩家盲抽一张拼图卡后，必须立刻将其面朝上放入自己的 `active_puzzles` 区，对所有玩家公开。

### 6. 1 级 / 2 级的升级限制 (Upgrade)
* **规则确认**：Upgrade 的规则是“换取一个高 1 级的拼块” 或 “换取一个同级但**不同形状**的拼块”。
* **执行方式**：因为 1 级和 2 级都只有唯一形状，所以它们**只能向上升级**（1级变2级，2级变任意3级）。不允许用 1 级换 1 级，或 2 级换 2 级。

### 7. 大师行动 (Master Action) 的结算顺序
* **规则确认**：大师行动在概念上是“同时放置”。
* **关键点**：你**不能**利用在当前大师行动中刚刚完成某张拼图所获得的“奖励拼块”，去放置到另一张拼图上。执行大师行动时，你必须已经拥有所有你打算放置的拼块。
* **开发建议**：
    1. 冻结当前 Inventory 状态。
    2. 玩家在 UI 上为多张拼图分配准备放置的拼块。
    3. 点击“确认/执行”后，一次性扣除这些拼块，验证合法性，然后统一结算所有完成的拼图并分发奖励。

### 8. 拼图完成时的拼块去向
* **规则确认**：**是的，始终回到玩家的 Inventory**。
* 没有任何情况会导致玩家永久失去拼图上的拼块。即使是在游戏结束后的“修饰阶段 (Finishing Touches)”完成的拼图，拼块也会乖乖回到玩家手中。

### 9. 修饰阶段 (Finishing Touches) 的扣分机制
* **规则确认**：扣分是基于**“放置动作 (Placements)”**的数量。
* **执行方式**：玩家在此阶段每往拼图里塞进 1 个拼块，最终得分就 **-1**。哪怕这个拼块放进去之后刚好拼满了拼图，导致拼图完成、拼块又回到了玩家手里，这 **-1 分也依然生效**。
* *举例：玩家在修饰阶段放了 2 个拼块完成了一张 3 分的拼图。他获得 3 分，扣除 2 分，净赚 1 分，且这两个拼块最终回到他手里。*

### 10. 终局平局判定中的 Inventory 统计
* **规则确认**：计算的是**游戏彻底结束时，玩家手头拥有的全部拼块**。
* **执行方式**：包含之前未放置的拼块，**也包含**在修饰阶段完成拼图后回收的拼块（如果你在修饰阶段没拼满，留在废弃拼图里的拼块则不算在内，因为未完成的拼图上的拼块不会回收）。

### 3. 奖励拼块的使用时机（普通放置后）

**规则确认：完全可以，且这是游戏的核心策略之一。**

* **逻辑流转**：当玩家花费 1 AP 执行“普通放置”并刚好填满拼图时，拼图会立即结算。被回收的拼块和**新获得的奖励拼块**会立刻进入玩家的 `inventory`。
* **后续行动**：只要玩家在该回合还有剩余的 AP，这个新获得的奖励拼块就可以立即被用于后续行动（例如：花费 1 AP 将其放置到另一张拼图上，或者花费 1 AP 把它升级掉）。
* **与“大师行动”的区别**：这也正是普通放置（逐个放，可触发连锁反应：完成A -> 拿到奖励 -> 放进B）和大师行动（同时放，无法在同一次行动内形成连锁）在策略上的核心区别。电子版的状态机必须能够在中途打断当前行动流去结算拼图，更新 Inventory，然后再允许玩家消耗下一个 AP。

### 4. 终局修饰阶段（Finishing Touches）的流程

**规则确认：是的，完全可以同时进行，不需要严格的回合顺序。**

* **独立结算**：在修饰阶段，游戏公共区域（市场、牌库、公共供应堆）已经完全锁定。玩家只能使用自己 `inventory` 中现有的拼块，去填补自己 `active_puzzles` 中的空缺。
* **无干涉性**：因为玩家的操作仅限于自己的面板，玩家之间没有任何资源竞争或互动，所以实体桌游规则允许大家**同时进行**，以加快游戏节奏。
* **电子版实现建议**：
    * 将此阶段设计为**全员同步的异步提交阶段**。
    * UI 上解锁玩家的剩余拼块，允许自由拖拽放置。
    * 每次放置一个拼块，在 UI 上明确提示“该动作将导致最终得分 `-1`”。
    * 玩家可以随时撤销（Undo），直到他们点击 **“结束修饰 / 提交 (Finish/Submit)”** 按钮。
    * 只有当所有玩家都点击提交后，系统才统一进行最终的计分结算。
