# OpenBoardGame 设计草案（design.1）

## 目标
构建一个可扩展的桌游平台，支持多人联网对战与 Bot，对接不同游戏模块；首个落地游戏为 CABO。

## 技术选型
- 后端：Python + FastAPI + python-socketio（ASGI 模式）
- 前端：HTML + CSS + 原生 JavaScript（Socket.IO 客户端）
- 数据：纯内存（不持久化）
- 部署：单进程运行（后续可按房间分片到多进程）

## 总体架构
- Lobby/Rooms：房间创建、加入、离开、准备、开始
- Game Engine：通用对局框架（服务器权威状态机）
- Game Modules：具体游戏实现（CABO 作为首个模块）
- Bot Service：Bot 调度与执行（策略由具体游戏模块提供）

## 服务器权威状态机
- 客户端只发送 Action；服务器校验合法性并更新状态
- 服务器生成事件流（events）并广播状态差异
- 状态版本号（stateVersion）用于客户端同步与防止乱序
- events 既包括用户行动的结果，也包括系统触发的事件（如超时、回合结束、自动结算）

### 事件模型（events）
- 通用事件 + 游戏自定义事件并存：平台提供统一封装，游戏模块决定具体内容。
- 事件封装建议字段：event_id、type、payload、visibility（public/private）、caused_by（action_id）、state_version。
- 通用事件（平台级/房间级）：system:error、system:info、room:player_joined、room:player_left、room:ready_changed、game:state_sync、game:state_delta、game:turn_changed、game:phase_changed、game:round_end、game:score_update。
- 游戏自定义事件（由模块定义）：例如 cabo:peek、cabo:spy、cabo:swap、cabo:match_success；方舟动物园可有 ark:build_enclosure、ark:gain_conservation 等。
- 可见性：public 对所有玩家广播；private 只发给受影响玩家（如 Peek/Spy 的翻牌结果）。

## 通用游戏模块接口（示意）
- 目标：兼容不同类型游戏（如 CABO、方舟动物园），接口泛型化而非固定结构。
- GameDefinition 元数据：game_id、name、min_players/max_players、turn_mode（当前默认轮流，预留同时/自由扩展）、action_schema（JSON Schema）、config_schema（JSON Schema）。
- turn_mode 扩展预留：由游戏模块定义阶段/冲突解决策略；平台层只提供基础动作广播与时序容器。
- init_game(config, players) -> state（state 为游戏自定义结构）
- get_legal_actions(state, actor) -> actions（用于 UI 提示与服务端校验）
- apply_action(state, action, actor) -> new_state, events（action 为游戏自定义结构）
- get_public_view(state, viewer) -> view（viewer 可为玩家/旁观者）
- is_terminal(state) -> bool
- score_round(state) -> scores（可选：用于回合结算）
- serialize/deserialize（后续扩展用）
- bot_move(state, bot_id) -> action（每个游戏自定义策略）

## 状态模型（通用）
- Room：
  - room_id
  - players（seat、昵称、连接状态）
  - game_type
  - game_state
  - state_version
- Session：
  - socket_id
  - player_id
  - room_id

## 通信协议（Socket.IO 事件）
- room:create / room:join / room:leave
- room:ready / room:start
- game:action（客户端发送）
- game:state（服务器广播）
- system:error / system:info

## CABO 实现细化

### 规则依据
- https://www.cabogame.com/how-to-play（官方 Standard Rules）
- https://en.wikipedia.org/wiki/Cabo_(game)（Choice Cards 对应关系）

### 基础规则
- 玩家数 2–5；每轮每人 4 张面朝下按 2x2 摆放；开局可看任意 2 张一次；开局后位置固定。
- 牌库为专用牌，数值 0–13；分值=牌面数值；部分牌标注 Peek/Spy/Swap（Choice Cards）。
- Choice Cards（默认映射）：7/8 = Peek（看自己一张），9/10 = Spy（看别人一张），11/12 = Swap（交换自己一张与他人一张，均不看）；仅在从抽牌堆抽到并弃置时可触发，弃牌堆抽到不可触发。
- 回合动作三选一：
- 抽牌堆：看牌后 (a) 替换自己一张面朝下牌；(b) 若是 Choice，弃置并执行行动；(c) 直接弃置不用。
- 抽弃牌堆：替换自己一张面朝下牌，回合结束。
- Call Cabo：不抽牌，宣告结束本轮，其他玩家各再行动一次。
- Matching：若手中有 2/3/4 张同点数暗牌，可尝试匹配（无需与抽到的牌同点）；成功则弃置匹配牌并弃置抽到的牌，减少手牌数量。若尝试失败，需公开展示后放回原位，抽到的牌加入手牌（手牌数 +1），本回合结束。
- 抽牌堆耗尽：保留弃牌堆顶牌，其余洗回作为新抽牌堆。

### 计分与回合结束
- Cabo 被叫后，其他玩家各再走一回合，然后全部翻开结算。
- 每轮计算手牌点数总和；最低分者得 0 分，其余玩家记本手牌总分。
- 如果 Cabo 叫牌者不是最低分，额外 +5 分。
- 最低分平局：叫牌者在平局中则得 0；若无人叫牌，平局者都得 0。
- 默认目标分数 100（可配置）；超过 100 时最低总分获胜。

### 可选规则（配置开关）
- Shooting the Moon：手牌为两张 12 与两张 13 时，自己本轮 0 分，其余玩家 50 分。
- Score Reset：总分恰好 100 时重置为 50（每人一次）。
- Double Swap：Swap 牌允许交换两张（含不同玩家的任意两张）。

### 状态与动作设计（建议）
- 状态：deck、discard、players[{hand_slots(固定 4 位置，可为空), known_cards(仅本人可见), score}]、current_turn、round_phase、last_drawn_card、config
- 动作：draw_deck、draw_discard、replace_card、discard_drawn、use_choice_action{type,targets}、attempt_match{slots}、call_cabo、end_turn

## 扩展与演进
- 单进程 -> 多进程：入口层按 room_id 路由到固定进程
- 内存 -> 可选持久化：新增存储适配器与快照
- 引擎与模块解耦：新增游戏仅实现模块接口
- Bot：可复用通用策略组件，但最终策略由具体游戏模块实现

## 安全与一致性
- 所有 Action 做服务端校验
- 防作弊：仅广播 public view
- 重连：基于 session 恢复（进程存活期内有效）
