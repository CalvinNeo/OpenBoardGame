# 《花火 (Hanabi)》 规则细节与开发建议书

## 1. 失败计分 (Scoring on Failure)
* **规则确认**: 在标准规则中，当第 3 个引信（怒火/雷）标记被触发时，游戏立即结束，全员**判负，得分为 0 分**。
* **变体情况**: 很多线下休闲局会采用“突然死亡但保留当前分”的房规（House Rule），但在正规电子版或竞技规则中，3 雷就是 0 分。
* **开发建议**:
    * **默认**: 0 分（显示 "GAME OVER / DEFEAT"）。
    * **配置项**: 可以加一个 `Allow Score on Defeat` (允许失败计分) 的开关，勾选后则结算当前牌面分，适合新手模式。

## 2. 弃牌限制 (Discard Rules)
* **规则确认**: **严格禁止**。当线索标记（蓝币/提示）达到上限（通常为 8 个）时，玩家**不能**执行弃牌行动。
    * *逻辑*: 弃牌动作的唯一定义是“弃一张牌以换回一个线索”。如果没有线索可换（池满），则动作非法。
* **开发建议**:
    * 在 UI 上，当 `Clues == 8` 时，禁用（置灰）弃牌按钮，并给出提示 Tooltip：“线索已满，无法弃牌，必须打出或提示”。
    * 这会迫使玩家在满线索时必须进行提示（消耗线索）或尝试打出牌，是游戏策略的重要一环（防烧牌）。

## 3. 线索信息记录 (Note Taking / Inference)
这是电子版《花火》体验好坏的分水岭。

* **否定信息 (Negative Info)**: **必须自动记录**。
    * *逻辑*: 如果某人指着你的第 1 张牌说“这是红色”，这意味着你的第 2, 3, 4, 5 张牌**绝对不是红色**。
    * *实现*: 系统应自动为第 2-5 张牌打上 `NOT RED` 的标记。
* **推断逻辑 (Inference)**: 
    * **基础推断 (必做)**: 记录直接的“是”和“否”。
    * **高级推断 (可选/慎做)**: 例如“这张牌不是红/黄/蓝/绿，所以它一定是白”。这种建议让玩家自己悟，或者作为一个 `Smart Assistant` 辅助功能的开关。
* **开发建议**: 
    * 默认开启“自动记录否定信息”。这是现代电子版《花火》（如 BGA, Hanabi Live）的标配，否则玩家会因为记忆负担过重而感到疲惫。

## 4. UI/UX 优先级分级 (Feature Priorities)

| 功能 | 优先级 | 理由 |
| :--- | :--- | :--- |
| **弃牌堆统计 (Discard Stats)** | **P0 (必做)** | 核心功能。玩家必须随时知道“红 3 还有几张”。**不要**只显示一堆废牌，要直接显示统计表（如：红[1,1,1,0,0] 表示红4红5还没出）。 |
| **操作日志 (Game Log)** | **P0 (必做)** | 合作游戏节奏慢，玩家需要看回放：“刚才谁提示了我的第3张牌是黄色？” |
| **防误触 (Anti-Misclick)** | **P0 (必做)** | 这种游戏点错一张就是全盘皆输。打出/弃牌必须有“二次确认”弹窗，或者支持“撤销”（仅限于未翻开牌面、未产生随机结果前）。 |
| **手动笔记 (Manual Notes)** | **P1 (推荐)** | 允许玩家右键点击自己的牌，手动标记“我认为这是 5”。这是高玩必备功能。 |
| **自动推断 (Auto-Logic)** | **P2 (可选)** | 如前所述，自动推导“非A非B即C”可以作为辅助功能，但非必须。 |

## 5. 起始玩家 (First Player)
* **规则确认**: 标准规则是**随机决定**起始玩家。
* **开发建议**: 
    * 随机选择。
    * *UI 细节*: 在开局时，务必清晰高亮**谁是当前回合**（Current Turn），因为所有人手牌都是背对自己的，很难一眼看出轮到谁了。

## 6. 其他电子版特有细节 (Extra Tips)
* **盲区提示**: 玩家看不到自己的牌。在 UI 设计上，自己的手牌区域应该是“卡背朝自己”，或者显示为“未知 (?)”。
* **队友视角**: 玩家必须能清晰地看到**队友的手牌**（正面）以及**队友手牌上已获得的信息标记**。
    * *例如*: 队友手里的红 5，如果已经被提示过“红色”，卡牌上方应悬浮一个红色图标；如果被提示过“5”，悬浮一个数字 5。
* **最后行动 (End Game)**: 当牌库摸空后，每人还有**最后 1 个回合**（包括摸到最后一张牌的人），然后游戏才结束。这一点容易在开发时被漏掉。
