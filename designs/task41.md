# 猜字解底

## 游戏规则

1. 游戏配件与设置

《猜字解底》的配件包含180张题目卡、6本文字手册、6块玩家屏风、记号笔、提示卡、作答卡以及计分板。游戏开始前，每位玩家领取一套同色配件，并将屏风立起以保密。所有玩家的得分标记在计分板上归零，准备工作便已完成。

2. 核心玩法流程

游戏共进行五轮，每轮分为猜测和验证两个阶段。首先，抽取一张背面朝上的题目卡置于桌面中央。玩家根据卡背的数字（如 24）在自己的文字手册中查到对应的隐藏字，并私下写在提示卡背面。

> 在实现电子版的时候，可以略去查看文字手册的环节，改为系统直接随机抽一张题目卡，并把对应的隐藏字派发给对应的玩家。

随后，玩家需为自己的隐藏字编写两个提示字写在提示卡正面，这两个提示字必须能分别与隐藏字组成词语。

所有人完成后，同时亮出提示字，并根据他人的提示猜测其隐藏字，将答案写在作答卡上。随后，每个玩家还需要根据当前的已知线索，猜测题目卡上的底字是什么。

等待所有玩家都猜测玩隐藏字和底字后，揭开所有玩家的隐藏字和底字，进入计分环节。

3. 积分策略解析

计分环节是游戏的关键。被他人猜对自己隐藏字的玩家，和猜对他人隐藏字的玩家，均可各得1分。例如，A的隐藏字被B和C猜对，则A得2分，B和C各得1分。

题目卡上的中心字（X字），它能与所有玩家的隐藏字（A, B, C…）组成词语，相当于“双层加密”，难度更高。因此，猜中X字的玩家可直接获得3分，分数获取效率远超猜测单个隐藏字。

在计分环节后，进入新的一轮。

## 生成规则

需要生成的项目包括：
- 题目卡，即底字
- 对一个题目卡，生成 6 个隐藏字

生成规则：
- 底字和隐藏字不是生僻字，并且一定不互相重复
- 六个隐藏字都能和底字组成一个两字词，但是顺序不限。例如隐藏字+底字，或者底字+隐藏字这样都是可以的。
- 组成的两字词，一定得是常用词。

你可以先生成 6 个底字，以及对应的 6x6 个隐藏字给我看一下。

## 手机输入法与提交（2026-11-22）

- 原因：猜测草稿在输入后 500ms 自动同步，服务端回传状态时，前端清空并重建全部猜测输入框。正在使用中文输入法的输入框因此被移除，导致失焦、键盘收起或拼音尚未选字就被同步。
- 猜测行按玩家 ID 复用 DOM，普通状态回包不替换输入框、不重新设置相同的值，保留焦点与光标。
- 两个提示、底字与其他玩家猜测均监听 `compositionstart` / `compositionend`。组词时暂停草稿同步与提交，状态刷新不覆盖组词内容；选字完成后再更新按钮并同步最终文字。
- 阶段切换、新回合与清空游戏时清理组词状态，继续保留原有的空白猜测提交规则。
- 浏览器回归覆盖手机触控与桌面、草稿回包及其他玩家状态更新、中文选字、提交内容、阶段切换与新回合。自动化组词事件不能替代 iOS / Android 真机键盘验证。
- 验证记录：`tests/word_decode.browser.cjs` 在 320 / 390 / 1024 / 1440px 通过输入交互、焦点与光标保留、提交和重置检查，提示与猜测两个阶段的截图未发现横向溢出或控件重叠；前端样式及 Help 合约共 13 项、JS 语法、脚本初始化和 diff 检查通过。
- 验收限制：原有 Help / Explain 弹窗不响应 Escape（Close 可用），本次未改动；通用 `tests/game_assets.browser.cjs` 因首页已加载 `shared_effects.js` / `shared_help.js`、但原断言仅允许 `shared.js` 而在初始断言失败。加上尚未完成的真机输入法验证，本次不能声明完整通过 `DEV_GUIDE.md` 验收。
