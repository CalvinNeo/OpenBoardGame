## 已完成的修复

### 1. 创建房间并 Start 后游戏区域空白

**现象**

- 房间能够建立，服务器也已经开始游戏，但点击 `Start Game` 后没有出现 Ark Nova 游戏界面。
- 渲染失败时没有清楚的前端反馈，看起来像按钮无效。

**修复**

- 补齐 Ark Nova 的游戏注册、前端脚本加载和主分发器分支。
- 确保 `ark_nova.js` 在主状态分发代码前加载，并公开 `renderArkNovaGameState`、`showArkNovaHeaderActions` 和清理入口。
- 收到 `game:state` 后会挂载并显示 Ark Nova 面板，不再停留在空壳区域。
- 渲染发生异常时显示“视图暂不可用”的错误状态，同时保留服务器已经确认的游戏状态，不再静默白屏。
- 增加房间级集成测试，验证开始游戏后会收到包含展示区、私人起手牌和 Map 0 定义的可渲染私有视图。

### 2. Map 0 区域过小、重复信息过多

**现象**

- Map 0 右侧长期显示大段说明，占用地图面积。
- 地图下方重复显示行动槽位，而行动卡已经在独立区域提供。
- `X-TOKEN STORAGE` 占据了不合理的位置。

**修复**

- 移除地图内常驻的大段说明和重复行动槽位，让地图成为该区域的主体。
- 把规则说明收进 `ⓘ Map info` 按钮；只有玩家主动点击时才弹出完整说明、地形图例、放置奖励、Build II 格和完成地图奖励。
- 将 X-token 存储改为地图标题栏中的紧凑状态胶囊，同时继续在玩家资源摘要中保留数量。
- 调整 Map 0 SVG、容器比例和响应式尺寸，使桌面端与手机端都能获得更大的可操作地图。

### 3. 手牌点击行为与详情弹窗不符合预期

**现象**

- 点击手牌主体会直接打开详情，容易和“选择这张牌执行行动”混淆。
- 只想查看或选择卡牌时，交互结果不稳定。

**修复**

- 非选择状态下，手牌主体不再打开详情。
- 右下角独立的 `i` 按钮成为查看完整卡牌说明的唯一入口。
- 在开局选牌、动物/赞助商行动或待处理选择中，点击牌面主体只负责选择/取消选择。
- 给按钮补充可访问名称，明确提示需要使用信息按钮查看详情。

### 4. `Discard N card(s)` 与手牌分离

**现象**

- 弃牌待处理界面另列一套选项，玩家需要在弹出区域和 `Your cards` 之间来回对应。

**修复**

- 当服务器发出 `discard_cards` 待处理选择时，可弃的牌直接在 `Your cards` 中变为可选。
- 手牌上方显示目标数量、当前已选数量和 `Discard selected` 按钮。
- 选择结果继续使用服务器提供的候选索引提交，未绕过服务器校验。
- `i` 按钮仍只查看详情，不会误选或误弃卡牌。

### 5. 保护项目没有显示三次支持机会及奖励

**现象**

- 保护项目卡只显示描述，玩家看不到三个支持档位分别要求什么、奖励什么。
- 选择支持项目时，也不容易判断某档是否已经被占用或被人数规则封锁。

**修复**

- 每张保护项目卡和详情弹窗都显示完整三档支持行。
- 每档分别显示：档位、需求数值/类型、箭头、保育/声望/金钱等实际奖励。
- 标出 `Eligible now`、`Requirement not met`、`Taken` 和 `Blocked` 状态。
- 新保护项目的额外奖励单独显示。
- Association 的支持档位下拉项同步显示需求、奖励和占用状态。

### 6. 无法查看其他玩家的动物园

**现象**

- 玩家只能看到自己的 Map 0，无法检查对手的公开动物园信息。

**修复**

- 每个玩家摘要增加 `View zoo` 按钮，并明确高亮当前正在查看的玩家。
- 可切换查看任意玩家的 Map 0、已建建筑、建筑内动物、已打出的动物/赞助商、合作动物园和大学等公开信息。
- 查看别人动物园时禁止地图放置；开始自己的 Build 或遇到地图待处理选择时会自动返回自己的动物园。
- 私人手牌和最终计分卡仍不会泄露，后端 public view 测试覆盖了该隐私边界。

### 7. `{Money-1}` 等内部占位符直接暴露

**现象**

- 卡牌说明会出现 `{Money-1}`、`{Appeal-2}`、`{ConservationPoint-1}` 等数据占位符，不像玩家界面。

**修复**

- 增加卡牌富文本 token 渲染器，把已知占位符转换为紧凑的 Emoji/数值胶囊，例如 `💰1`、`🎟2`、`🌿1`、`🎓1`、`✕1`。
- 行动卡、围栏尺寸、倍率标记等也使用一致图标。
- 未识别的 token 保留原文，避免错误吞掉卡牌内容。

### 8. 建造时可以任意拼出尺寸，未使用实体固定形状

**现象**

- 原实现让玩家逐格自由选择 1–5 个相连六角格，会产生实体游戏中不存在的围栏形状。

**修复**

- 为普通围栏尺寸 1–5、亭子、售货亭、萌宠动物园、爬行馆和大型鸟类馆定义固定 polyhex footprint。
- 玩家只需选择一个锚点，系统自动展示完整建筑形状；不能镜像，只能按规则进行 60° 旋转。
- 旋转时自动跳过越界、地形不符或与建筑重叠的方向。
- 客户端只负责预览，服务端继续验证固定形状、占用、邻接、地形、费用和升级要求。
- 增加固定形状匹配测试，防止重新退化成任意连通格。

### 9. 手机版 Rotate 按钮离地图太远

**现象**

- 手机屏幕上选择完建筑锚点后，需要离开地图区域寻找 `Rotate`，反复试放很不方便。

**修复**

- 手机端在 Map 0 右下角显示上下文悬浮 `↻ Rotate` 按钮。
- 只有正在自己的地图放置多格建筑且已有有效预览时出现。
- 放置完成、取消、切换行动或没有可旋转建筑时自动隐藏。
- 手机端隐藏远处的重复 Rotate 控件；桌面端仍保留规划区按钮。

### 10. 手牌悬浮与真正选中的视觉状态混淆

**现象**

- 鼠标仅仅悬浮在手牌上，也会产生接近选中状态的底色变化。

**修复**

- 悬浮/键盘聚焦只增加亮色边框，不改变卡牌底色。
- 只有实际点击选中的牌才使用橙色描边、暖色底色和抬升阴影。
- `aria-pressed` 与视觉选中状态同步。

### 11. 桌面端 Your cards 被 Event Log 挤占

**现象**

- 大屏幕上 `Your cards` 和 `Event Log` 并排，手牌横向空间不足。

**修复**

- 桌面端改为 `Your cards` 独占一整行。
- `Event Log` 移到手牌区域下方，避免挤压卡牌。

### 12. 卡牌 Requirement、Reward 和标签混在一起

**现象**

- 费用、行动强度、围栏、前置图标和即时奖励挤在同一区域，难以判断哪些是“打出要求”、哪些是“获得奖励”。
- Sponsor 强度曾错误读取了与二级行动条件相关的字段。

**修复**

- 参照实体卡的信息层级，把卡牌信息拆为蓝色 `Requirements` 和绿色 `Rewards` 两块。
- Requirements 统一展示费用、Sponsor 强度、围栏、固定建筑占地、水/岩石/边界邻接、标签数量、合作动物园、行动升级和轨道阈值。
- Rewards 单独展示吸引力、保育和声望等印刷奖励。
- Sponsor 强度改为读取 `play.strength_required`。
- 详情弹窗把需求/奖励移到大图之前，打开后无需先滚过图片才能看到关键规则。

界面层级参考了官方规则书中的卡牌结构说明，但没有复制规则书版式或商业牌面素材：`https://capstone-games.com/cdn/shop/files/Ark-Nova-Rulebook.pdf?v=15269496103518830006`。

### 13. 未标出动物可进入特殊场馆

**现象**

- 能入住爬行馆或大型鸟类馆的动物，只显示普通围栏尺寸，玩家无法从牌面判断替代入住方式。

**修复**

- 直接读取卡牌的 `enclosure_options`。
- 以 `普通围栏 OR 特殊场馆` 形式显示每种允许方式及其实际占用容量。
- 覆盖普通围栏、萌宠动物园、爬行馆和大型鸟类馆；例如可显示 `⬡2 Std or 🦎1 Reptile`。

### 14. 大洲 Emoji 与原版视觉语义不一致

**现象**

- 非洲、美洲、亚洲、澳洲和欧洲使用地球、袋鼠、城堡等 Emoji，既不统一也不符合实体牌的颜色识别方式。

**修复**

- 大洲不再显示 Emoji，只显示文字。
- 使用统一的原版语义色底：非洲黄、美洲橙、亚洲绿、澳洲红、欧洲蓝。
- 同一套文字色块用于卡牌标签、卡牌前置条件、保护项目需求和玩家合作动物园。
- “任意/不同大洲”使用五色渐变，仍不使用大洲 Emoji。

### 15. 拿大学时无法选择，也看不到剩余供应

**现象**

- Association 选择“拿大学”后没有清楚的大学选择步骤。
- 玩家不知道三种大学分别提供什么，也不知道当前还能拿哪些。
- 旧前端在可用数组为空时会回退到完整列表，存在把已不可用项重新显示为可用的风险。

**修复**

- 后端为三种大学补齐稳定名称和奖励数据：
  - Research university：`🔬×2`
  - Reputation university：`🔬×1`、`🎓+1`
  - Hand-limit university：`🔬×1`、手牌上限 `5`
- public view 为每种大学返回 `available`、`owned_by_you`、`remaining` 和 `total`。
- 按四人上限为每种大学维护 4 枚供应，并在领取时进行服务端库存校验。
- 前端改为三张可选择的单选卡，而不是没有解释的普通下拉框。
- 每张选项显示奖励、`N / 4 tokens left`、不可用或“你已拿取”状态；不可用项禁选。
- 选中的大学会保持高亮，并以可读名称进入 Association 任务队列。

### 16. 卡牌太窄，文字与信息块拥挤甚至重叠

**现象**

- 新增 Requirements、Rewards、图标和插画后，原 138px 卡宽无法容纳内容。
- 手机端 132px 卡宽也会导致信息块互相挤压。

**修复**

- 桌面端普通卡宽提高到 176px，保护项目卡提高到 218px。
- 手机端普通卡最大 156px，保护项目卡最大 210px，并保留横向滚动和吸附。
- 同步增加卡高、标题字号、内容留白和奖励列最小宽度。
- 插画宽度跟随卡面，不再受旧的固定最大宽度限制。
- 已打出的卡牌也同步放大，避免缩略区再次出现重叠。

### 17. 二级动物/赞助商卡没有明显标识

**现象**

- 需要升级后的 Animals 或 Sponsors 行动才能打出的卡，顶部仍只写 `Animal` / `Sponsor`。

**修复**

- 根据 `play.minimum_action_level_from_card_condition` 和 `play.conditions` 中的 `action_upgrade` 判断卡牌等级。
- 二级动物在类型栏和详情标题显示 `ANIMAL (II)`。
- 二级赞助商在类型栏和详情标题显示 `SPONSOR (II)`。
- 当前牌库数据中已识别 12 张二级动物和 6 张二级赞助商。

### 18. 卡牌图片重复、缺失时界面表现不稳定

**现象**

- 早期多张卡共用分类图，难以快速识别；单张图片缺失时可能显示破图。

**修复**

- 235 张动物、赞助商、保护项目和最终计分卡均接入独立 WebP 文件路径。
- 单张资源加载失败时自动退回对应类别的兜底图。
- 测试会核对牌库 ID 与插画文件集合完全一致，并检查文件不是重复占位内容。

### 浏览器实际流程

已在本地浏览器完成以下操作：

1. 创建 Ark Nova 双人房间并开始游戏；
2. 从 8 张起手牌中保留 4 张；
3. 选择 Association 行动；
4. 切换到 Take university；
5. 确认三种大学均显示奖励和 `4 / 4 tokens left`；
6. 选择 Reputation university，加入任务队列并确认行动；
7. 确认领取后界面显示 `Already taken by you`；
8. 在 390×844 手机视口检查大学选项与加宽后的手牌，未观察到卡牌重叠。

### 全仓库测试基线

运行完整 `python3 -m unittest` 时共执行 537 个测试，其中 Ark Nova 专项测试全部通过，但仓库已有 4 个 Halli Galli 测试失败：

- `test_flip_wait_allows_flip_after_ready`
- `test_flip_wait_blocks_flip`
- `test_ring_false_when_no_fruit_total_is_five`
- `test_ring_success_when_fruit_total_is_five`

这些失败不涉及 Ark Nova 文件，也不是本轮改动引入的 Ark Nova 回归。浏览器控制台另有一条来自 `things_in_rings.js` 的既有 `currentGameType is not defined` 错误，同样不属于 Ark Nova。

## 当前结论

本轮用户反馈的 Ark Nova 显示、Map 0、手牌、弃牌、保护项目、公开动物园、建筑形状、手机版旋转、卡牌层级、大洲样式、大学选择、卡牌尺寸和二级卡标识问题均已落地，并有 Ark Nova 专项自动化测试覆盖。后续如果继续进行规则精度审计，应另行按卡牌 ID 检查具体效果结算，而不是把该工作混入本 UI/交互修复记录。
