# 《森森不息》（Forest Shuffle）基础版规则与电子版实现说明

> 说明
>
> - 本文只覆盖《森森不息 / Forest Shuffle》基础版，不包含 `Alpine`、`Woodland Edge`、`Exploration`、`Dartmoor` 等扩展。
> - 我将“能从公开资料稳定确认的官方规则”与“为了落地电子版必须补上的实现约定”分开写。
> - 规则主依据是官方中文规则书、官方英文规则书、Lookout 官方 FAQ 页面，以及一个把基础版附录整理成 HTML 的玩家辅助页。
> - 我在 `2026-03-28` 访问 Lookout 官方 FAQ 时，看到一个与 2023 规则书冲突的点：起手无树是否允许换手。本文会单独标明。

---

## 1. 游戏概述

《森森不息》是一款 2 到 5 人的卡牌构筑/个人森林拼接游戏。每位玩家都在自己面前建设一片“森林”：

- 先打出树木，形成可放置卡牌的 4 个边位。
- 再把动物、植物、蘑菇等“森林居民”贴到树的上、下、左、右四侧。
- 通过卡牌之间的生态联动、额外行动、补牌和终局计分组合，尽量在第三张冬季卡出现前拿到最高分。

胜利条件非常直接：

- 当第三张冬季卡被翻出时，游戏立即结束。
- 所有玩家结算自己森林中**所有可见卡牌**的分数，再加上洞穴下方牌的数量。
- 分数最高者获胜；平局则共享胜利。

## 2. 基础版组件与牌堆构成

根据官方规则书，基础版组件至少包含：

- `1` 张中央空地/游戏板（clearing）
- `14` 张帮助卡（reference cards）
- `5` 张洞穴卡（cave cards）
- `1` 本记分纸
- `180` 张卡牌

这 `180` 张卡牌可以拆成：

- `66` 张树木牌
- `48` 张上下分割牌（top/bottom split cards）
- `44` 张左右分割牌（left/right split cards）
- `3` 张冬季卡（winter cards）
- `5` 张洞穴卡
- `14` 张帮助卡

也就是说，真正会进入主牌库的，是：

- `158` 张基础游戏牌（树木 + 分割牌）
- `3` 张冬季卡

合计主牌库物理张数为 `161`。

不同人数下，开局会先从 **158 张基础游戏牌** 中暗弃若干，再把 3 张冬季卡按规则埋入：

- `2` 人：移出 `30` 张，最终主牌库 `131` 张
- `3` 人：移出 `20` 张，最终主牌库 `141` 张
- `4` 人：移出 `10` 张，最终主牌库 `151` 张
- `5` 人：不移出，最终主牌库 `161` 张

## 3. 电子版必须建模的核心概念

### 3.1 树、树位与森林

每位玩家面前都有自己独立的森林（`forest`）。

森林中的核心节点是“树”：

- 普通树木牌
- 树苗（tree sapling）

每棵树都有 4 个边位：

- `top`
- `bottom`
- `left`
- `right`

大多数情况下，每个边位最多只能有 1 张可见牌；但基础版有 2 个明确例外：

- `Common Toad`：最多 2 张共享同一个底边位
- `European Hare`：任意数量可共享同一个左/右边位

因此，电子版不要把树边位建模成“单卡槽位”，而应该建成“卡牌栈 / slot stack”。

建议数据结构：

```ts
type Side = "top" | "bottom" | "left" | "right";

interface ForestState {
  trees: TreeNode[];
  caveCards: string[];
}

interface TreeNode {
  id: string;
  kind: "tree" | "sapling";
  treeSpecies?: TreeSpecies;
  printedCardId: string;
  slots: Record<Side, SlotStack>;
}

interface SlotStack {
  cards: PlacedCard[];
}

interface PlacedCard {
  instanceId: string;
  speciesId: string;
  side: Side;
  sourceCardId: string;
}
```

### 3.2 分割牌

除树木牌外，其他牌都是“二合一”分割牌：

- 上下分割：可选择打出上半或下半
- 左右分割：可选择打出左半或右半

当你打出其中一半时：

- 只有**露在外面的那一半**算作森林中的牌
- 被塞到树下的另一半从此对本局逻辑**没有任何作用**

电子版里应把“物理卡牌”和“打出的可见半张”分开：

```ts
interface CardInstance {
  id: string;
  cardDefId: string;
}

interface SplitCardPlayChoice {
  instanceId: string;
  visibleHalf: "top" | "bottom" | "left" | "right";
}
```

### 3.3 卡牌颜色 / 树符号

本游戏里有两个很容易混淆的概念：

1. `treeSpecies`
   - 树本身属于哪一种树种，例如 `Beech`、`Oak`、`Sycamore`
2. `cardColorSymbol`
   - 这张卡“属于哪种树色/树符号”
   - 主要用于判定奖励（bonus）是否被触发
   - 某些牌还会根据“与自己相同的树符号”来计分，例如 `Roe Deer`

这两个字段对树木牌通常一致，但对很多分割牌并不等同于“它放在什么树旁边”。

电子版必须显式保存：

```ts
interface CardDef {
  id: string;
  speciesId: string;
  orientation: "tree" | "top_bottom" | "left_right";
  copies: number;
  printedCost: number;
  cardColorSymbol?: TreeSpecies | "generic_tree";
  types: CardTag[];
  effectSpec?: EffectSpec;
  bonusSpec?: BonusSpec;
  scoringSpec: ScoringSpec;
}
```

### 3.4 洞穴（Cave）

每位玩家面前有 1 张洞穴卡。

洞穴的核心规则只有 1 条：

- 洞穴下每压 1 张牌，终局就多 `1` 分

基础版的 5 张洞穴卡在规则层面可以视为等价，不是异能洞穴。

### 3.5 空地（Clearing）

中央空地是公共的明置区域：

- 玩家支付费用时，把牌面朝上丢进空地
- 树木被打出时，会从牌库翻 1 张牌到空地
- 进行“抽两张牌”行动时，可以从空地拿牌

基础版里，空地不是弃牌堆：

- 当空地达到 `10` 张或更多时，**整片空地直接移出游戏，放回盒中**
- 基础版没有官方“弃牌堆循环再洗回”的规则

这点非常重要，因为后续扩展引入了真正的弃牌堆逻辑，不能和基础版混用。

### 3.6 冬季卡（Winter Cards）

冬季卡不属于任何玩家。

它们只承担 2 个功能：

- 把游戏时长限制在牌库后 1/3 左右
- 第三张出现时立刻触发终局

## 4. 开局流程（Setup）

### 4.1 标准开局

1. 把空地板放在中央。
2. 把 14 张帮助卡放在一旁。
3. 每位玩家拿 1 张洞穴卡。
4. 将 3 张冬季卡单独拿出。
5. 将其余基础游戏牌洗混后，按照人数移出若干张不看内容：
   - 2 人移出 30 张
   - 3 人移出 20 张
   - 4 人移出 10 张
   - 5 人不移出
6. 把剩余基础游戏牌分成 3 叠数量接近的牌堆。
7. 将其中 `2` 张冬季卡洗入其中一叠。
8. 把第 `3` 张冬季卡直接放到这叠牌的最顶端。
9. 把另外两叠牌叠到它上面，使这叠带冬季卡的牌堆位于最下方，形成完整主牌库。
10. 每位玩家抽 `6` 张起始手牌。
11. 选定起始玩家。

### 4.2 起手无树的规则冲突

这里有一个版本冲突，电子版必须明确选择：

- `2023` 年官方中/英文规则书：如果你起手 6 张里没有树，可以把这 6 张移出游戏，重新抽 6 张；每人最多 1 次。
- Lookout 官方 FAQ（我于 `2026-03-28` 查看）：这条建议后来被移除了。

电子版建议：

- 提供房规开关 `opening_mulligan_if_no_tree`
- 默认值建议设为 `false`，对齐当前 FAQ
- 如要完全复刻早期纸规，可开启 `true`

### 4.3 起始玩家

纸规写的是“最后一次去森林散步的人先手”。

电子版建议直接支持：

- 随机先手
- 房主指定先手

## 5. 合法摆放规则

### 5.1 打树

树木牌可以直接打到自己森林中，不要求和已有树相邻。

每次打出树木牌后：

- 立刻从牌库翻 1 张牌到空地
- 这一步是强制的
- 如果翻出冬季卡，按冬季规则立即处理

### 5.2 树苗（Tree Sapling）

你可以把任意 1 张手牌盖放成树苗。

树苗规则：

- 视为一棵可承载 4 个边位的“通用树”
- 不是 8 种树种中的任何一种
- 也不算一个新的树种
- 终局本身不计分

为了电子版能稳定实现，我建议把树苗视为：

- `kind = "sapling"`
- `treeSpecies = null`
- `countsAsTreeCard = true`
- `countsAsTreeSpecies = false`
- `score = 0`

关于树苗费用，公开可验证资料没有给出特别复杂的例外；通行理解是：

- 树苗是一个独立的“替代打树”动作
- 建议实现为 `0` 费用

如果你想做得更稳妥，可以把它也做成房规开关，但默认应当是免费。

### 5.3 打分割牌

打分割牌时，必须满足全部条件：

1. 你已拥有至少 1 棵树或树苗。
2. 目标树/树苗的对应边位可以放这张牌。
3. 该半张的朝向与边位匹配：
   - 左半只能放 `left`
   - 右半只能放 `right`
   - 上半只能放 `top`
   - 下半只能放 `bottom`
4. 该边位没有被普通规则占满。

放置后：

- 被塞入树下的另一半立刻失去游戏意义
- 只保留可见半张参与类型、效果、奖励、计分

### 5.4 特殊共享边位

基础版只有两个共享边位例外：

- `Common Toad`
  - 只能共享同一棵树的同一个底边位
  - 最多 2 张
- `European Hare`
  - 只能与其他 `European Hare` 共享同一棵树的同一个左/右边位
  - 数量不限

除了这两种情况，其余卡都不能共享同一边位。

### 5.5 “树已占满”的定义

一棵树只要四个方向 `top / bottom / left / right` 都至少有 1 张可见牌，就算“已完全占满（fully occupied）”。

注意：

- 同一边位叠了多张 `European Hare` 或两张 `Common Toad`，仍然只算“这个边位被占”
- 但这些额外叠放的牌在某些计分中仍然会被逐张计算，例如 `Silver Fir`

## 6. 回合流程与时序

游戏按顺时针轮流进行。

轮到某位玩家时，必须二选一：

- `A`：抽两张牌
- `B`：打出一张牌并检查空地

### 6.1 行动 A：抽两张牌

抽牌是逐张执行的，不是一次拿两张。

对每一张要抽的牌，玩家都可以单独选择来源：

- 从牌库顶抽 1 张暗牌
- 从空地拿 1 张明牌

手牌上限：

- 手牌上限是 `10`
- 若你回合开始时有 `9` 张手牌，则本次行动最多只能拿 `1` 张
- 若你已经有 `10` 张手牌，电子版应禁止你选择“抽两张牌”行动

#### 冬季卡处理

只要你“从牌库抽牌”而翻到冬季卡，就执行：

1. 把该冬季卡面朝上放到空地旁边
2. 立刻再从牌库抽 1 张替代牌
3. 如果这是第 `3` 张冬季卡，则游戏立即结束，替代抽牌也不再继续

### 6.2 行动 B：打出一张牌并检查空地

建议电子版采用以下精确顺序：

1. 选择要打出的手牌
2. 选择打出模式
   - 作为树木
   - 作为树苗
   - 作为分割牌的某一半
3. 检查该放置是否合法
4. 支付费用
   - 费用用“其他手牌”支付
   - 所支付的牌全部面朝上放进空地
5. 将牌放入森林
6. 若打出的是树木牌，则执行“翻 1 张牌到空地”的强制步骤
7. 若此时出现第 3 张冬季卡，则游戏立即结束，后续步骤全部取消
8. 结算**已存在**的永久蘑菇效果（如果该次放牌触发了它们）
9. 结算这张刚打出的牌的 `effect`
10. 若奖励条件满足，则结算这张牌的 `bonus`
11. 回合结束时检查空地
12. 若本回合获得额外回合，则继续执行额外回合；否则轮到下一位玩家

若第 8 步同时触发多个已存在蘑菇：

- 建议由当前玩家决定这些蘑菇触发的结算顺序
- 每个蘑菇触发本身都是“可用可不用”
- 只要其中任一步翻出第 3 张冬季卡，后续全部中断

### 6.3 奖励（Bonus）触发条件

有些牌右下角有奖励箭头。

奖励触发条件是：

- 你用于支付这张牌费用的**全部**卡牌，都带有与这张牌相同的 `cardColorSymbol`

只要有 1 张支付牌颜色不匹配，奖励就完全不触发。

支付牌若是分割牌：

- 只要该牌本身带有匹配的树符号即可
- 不要求你打出的那一半恰好是那个树符号

### 6.4 永久蘑菇效果的时序

基础版蘑菇属于永久效果，但有一个非常重要的限制：

- 它们从**你的下一个回合开始**才生效

这意味着：

- 你本回合刚打出的蘑菇，不能对本回合后续打出的牌生效
- 但你上一个回合之前已存在的蘑菇，可以在本回合照常触发
- 如果你本回合获得一个“额外回合”，那已经算“下一个回合”，先前打出的蘑菇此时应视为可用

建议电子版统一成：

- `active_from_turn = owner.turn_index + 1`

### 6.5 空地检查

在你的整个回合完全结束后，若空地中有 `10` 张或更多牌：

- 把空地所有牌移出游戏，放回盒中
- 基础版不建立弃牌堆

注意：

- `Brown Bear` 之类会先把空地牌拿走，所以最终空地可能不足 10
- 若第 3 张冬季卡已经触发终局，则不会再做空地清理

### 6.6 额外回合

若本回合获得一个或多个额外回合：

- 先完成本回合的所有后续步骤
- 再立刻执行额外回合
- 多个额外回合按获得顺序排队即可

若在任何额外回合中翻出第 3 张冬季卡：

- 游戏立刻结束
- 尚未执行的额外回合全部作废

### 6.7 `Mole` 的特殊连打规则

`Mole` 是基础版里最复杂的牌，建议单独写状态机。

当 `Mole` 的效果开始结算时：

1. 先确认你当前手里有哪些牌要通过 `Mole` 额外打出。
2. 一次性支付这些牌的总印刷费用。
3. 把这些牌按正常规则放进森林。
4. 对每一张通过 `Mole` 打出的牌，按当前玩家选择的顺序逐张结算：
   - 已存在蘑菇的触发
   - 该牌自身 `effect`
   - 该牌自身 `bonus`
5. 若这些牌带来额外回合，则把额外回合排到当前回合之后。

电子版里最关键的两个细节：

- `Mole` 期间抽到的新牌，**不能**再加入这次 `Mole` 的待打出列表，也不能回过头作为这次连打的支付牌。
- 若你通过第一个 `Mole` 又打出了第二个 `Mole`，那么当轮到第二个 `Mole` 结算时，应先把第二个 `Mole` 完整跑完，再回到第一个 `Mole` 尚未结算完的牌。
- 若通过 `Mole` 打出树木，则这张树自己的“翻 1 张到空地”强制步骤仍然照常发生；若因此翻出第 3 张冬季卡，整局立刻结束。

另外，`Mole` 的支付不是“只看总费用”就够了；为了判定各张被连打牌能否触发自己的奖励，电子版必须支持：

- 把支付牌**分配**给具体的目标牌
- 否则无法判断每一张被 `Mole` 打出的牌是否满足其 bonus 颜色条件

---

## 7. 游戏结束与总计分

只要第 `3` 张冬季卡被翻出：

- 游戏立即结束
- 当前玩家**不完成剩余步骤**
- 不补完当前回合
- 不再清空空地
- 不再执行未完成效果或未执行额外回合

终局总分：

1. 计算玩家森林中**所有可见牌**的分数
2. 再加上洞穴下压住的牌数
3. 面朝下作为树苗的牌本身记 `0` 分

平局：

- 共享胜利

## 8. 基础版卡牌数据库设计建议

要做成电子版，建议不要把每张卡硬编码成独立函数，而是把卡牌效果拆成“模板 + 参数”。

推荐字段：

```ts
type CardTag =
  | "tree"
  | "bird"
  | "butterfly"
  | "mushroom"
  | "deer"
  | "hoofed"
  | "pawed"
  | "plant"
  | "insect"
  | "amphibian"
  | "bat";

interface CardDef {
  speciesId: string;
  displayNameEn: string;
  displayNameZh?: string;
  placement: "tree" | "top" | "bottom" | "left_right";
  copies: number;
  printedCost: number;
  cardColorSymbol?: TreeSpecies | "generic_tree";
  tags: CardTag[];
  effectSpec?: EffectSpec;
  bonusSpec?: BonusSpec;
  scoringSpec: ScoringSpec;
  variantData?: Record<string, unknown>;
}
```

推荐的 `EffectSpec / BonusSpec` 原语：

- `draw_fixed(n)`
- `draw_equal_to_tag_count(tag)`
- `extra_turn`
- `place_free_from_hand(tag)`
- `place_any_number_free_from_hand(tag)`
- `move_all_clearing_to_cave`
- `move_any_hand_cards_to_cave_and_redraw_same_count`
- `mole_combo_play`
- `modify_tree_species_count`

推荐的 `ScoringSpec` 原语：

- `flat_each(points)`
- `threshold_each(threshold, points)`
- `multiply_by_tag_count(pointsPerTarget, tag, includeSelf?)`
- `multiply_by_same_color_symbol(pointsPerTarget)`
- `set_table_total(table)`
- `hare_square_total`
- `conditional_each(predicate, points)`
- `count_cards_in_own_slots(pointsPerCard)`
- `count_forest_feature(pointsPerFeature, feature)`
- `compare_against_other_players(metric, tieCountsAsWin)`

## 9. 基础版完整卡群摘要

下面这一节的目标不是“给玩家速读”，而是给程序员做基础版牌表。

### 9.1 树木牌（8 种）

| 物种 | 张数 | 费用 | 规则摘要 |
| --- | ---: | ---: | --- |
| `Beech` | 10 | 1 | `effect: draw 1`；若经 `Violet Carpenter Bee` 修正后的山毛榉数量 `< 4`，所有 `Beech` 均为 `0` 分；否则每张 `5` 分。 |
| `Birch` | 10 | 0 | `effect: draw 1`；每张 `1` 分。 |
| `Douglas Fir` | 7 | 2 | `bonus: extra turn`；每张 `5` 分。 |
| `Horse Chestnut` | 11 | 1 | 全部 `Horse Chestnut` 作为一组计总分：`1/4/9/16/25/36/49`（对应 1/2/3/4/5/6/7+ 张）；`Violet Carpenter Bee` 可增加“计算用数量”。 |
| `Linden Tree` | 9 | 1 | 默认每张 `1` 分；若本玩家在全场“菩提树数量”上为最多或并列最多，则每张 `3` 分；`Violet Carpenter Bee` 可帮助比较数量。 |
| `Oak` | 7 | 2 | `bonus: extra turn`；基础版中，若你的森林拥有全部 `8` 种树种，则每张 `10` 分，否则 `0` 分。 |

| `Sycamore` | 6 | 2 | 每张 `Sycamore` 按你森林中的“树牌总数”计分，包含树苗；若你有 `n` 张 `Sycamore`、总树数为 `t`，则这部分总分是 `n * t`。 |

补充：

- 基础版所有树木牌在打出后都会强制从牌库翻 `1` 张牌到空地。
- 树苗不是树种，但对 `Sycamore`、`Great Spotted Woodpecker`、`Moss`、`Red Deer` 等“泛树牌计数”有效。

### 9.2 蝙蝠组（4 种，左右位）

这 4 种牌规则完全同模板：

- `Barbastelle Bat`：3 张，费用 1
- `Bechstein's Bat`：3 张，费用 1
- `Brown Long-Eared Bat`：3 张，费用 1
- `Greater Horseshoe Bat`：3 张，费用 1

共同计分逻辑：

- 若你的森林中至少有 `3` 种不同的蝙蝠物种，则你森林中**每一张蝙蝠**都值 `5` 分
- 若不足 `3` 种，则所有蝙蝠都值 `0` 分

基础版蝙蝠组总分可以直接写成：

```ts
if (distinctBatSpecies >= 3) {
  totalBatPoints = totalBatCards * 5;
} else {
  totalBatPoints = 0;
}
```

### 9.3 蝴蝶组（5 种，上位）

这 5 种牌规则也共用同一个计分模板：

- `Camberwell Beauty`：4 张，费用 0
- `Large Tortoiseshell`：4 张，费用 0
- `Peacock Butterfly`：4 张，费用 0
- `Purple Emperor`：4 张，费用 0
- `Silver-Washed Fritillary`：4 张，费用 0

计分逻辑：

- 不同物种的蝴蝶组成一组
- 1/2/3/4/5 个不同物种一组，分别得 `0 / 3 / 6 / 12 / 20`
- 每张蝴蝶卡只能属于 1 组

推荐算法：

1. 统计每个蝴蝶物种数量
2. 反复“每种取 1 张”组成集合
3. 每一组按大小查表计分

例如：

- 计分表 `butterflySetScore = [0, 0, 3, 6, 12, 20]`
- 若物种计数是 `[2, 2, 1, 0, 0]`
- 可组成 `3` 张一组和 `2` 张一组
- 总分 `6 + 3 = 9`

## 10. 电子版实现时最容易写错的点

### 10.1 “可见卡”才存在

分割牌只有露在外面的半张才算：

- 类型
- 效果
- 奖励
- 分数
- 是否占位

被塞进树下的另一半必须彻底退出逻辑。

### 10.2 基础版没有弃牌堆

空地满 `10+` 后是**移出游戏**，不是弃牌堆。

如果后面要兼容扩展，建议从一开始就把：

- `clearing`
- `removedFromGame`
- `discardPile`

建成三个不同区域，哪怕基础版只用前两个。

### 10.3 树苗不是树种

树苗：

- 是树牌
- 能承载四边位
- 自身 0 分
- 不属于任一具体树种

因此：

- 能帮助 `Sycamore` / `Moss` / `Great Spotted Woodpecker` / `Red Deer`
- 不能帮助 `Oak` / `Wild Strawberries` 凑“8 种树种”

### 10.4 `Violet Carpenter Bee` 只影响 5 类逻辑

它不是“万能把自己当树”。

基础版里，只应该影响：

- `Beech`
- `Horse Chestnut`
- `Linden Tree`
- `Great Spotted Woodpecker`
- `Moss`

其余地方都不要偷懒写成“挂在哪棵树上就视为那种树”。

### 10.5 `Mole` 不是“免费连打”

`Mole` 仍然要求你：

- 支付所有被连打牌的总费用
- 逐张检查放置合法性
- 逐张结算蘑菇触发、效果、奖励
- 逐张记录额外回合

而且被 `Mole` 抽到的新牌不能回流进这次 `Mole`。

### 10.6 额外回合不是“回合内继续”

额外回合是一个新的完整回合，不是当前回合里再追加一个动作。

所以：

- 新回合前要先做完当前回合的空地检查
- 永久蘑菇“从你的下一个回合开始有效”时，额外回合应被视为合法的“下一个回合”

### 10.7 第三张冬季卡会中断任何事情

只要第三张冬季卡出现，当前流程立刻终止：

- 不继续结算未跑完的 effect / bonus
- 不继续清理空地
- 不继续执行额外回合
- 不补完“本回合剩余动作”

## 12. 需要实现约定的规则模糊点

这些不是“资源缺失”，而是我在本次可访问资料里看到存在版本差异、或文本不够精确的地方。电子版实现时最好显式选边站。

### 12.1 起手无树是否允许换手

- 早期规则书：允许 1 次
- 官方 FAQ（`2026-03-28` 查阅）：说这条已从官方规则移除

建议：

- 做成房规开关
- 默认关闭，兼容开关可开

### 12.2 树苗费用

可访问资料一致倾向于“树苗免费”，但我本次拿到的官方 PDF OCR 文本不足以把这句话逐字抠得特别漂亮。

建议：

- 默认实现为 `0` 费用

### 12.3 树的强制翻牌与蘑菇触发的精确先后

我建议电子版采用：

1. 支付
2. 放牌
3. 若是树，则先翻 1 张到空地
4. 若未终局，再结算已存在蘑菇触发
5. 再结算本牌 effect
6. 最后结算本牌 bonus

这样最稳定，也最符合“第三张冬季卡立即截断整局”的精神。

### 12.4 手牌上限的适用范围

基础版公开文本清楚写到：

- 抽两张行动受 10 手牌上限约束
- 很多“从牌库抽牌”的图示也默认应受上限约束

但“是否所有进入手牌的来源都一律受限”在基础版公开文本里没有被单独、细粒度地表成一条总规则。

建议：

- 所有“从牌库抽牌”都遵守 10 手牌上限
- 基础版里基本足够，因为基础版几乎没有“从空地拿进手牌”的效果牌

## 13. 建议的实现切分

如果要在本仓库里做电子版，建议至少切成 4 层：

### 13.1 规则内核

- 牌库与冬季卡埋设
- 森林树结构与边位合法性
- 主回合状态机
- 效果/奖励/永久效果时序
- 终局与计分

### 13.2 牌表数据层

- 57 个基础版物种定义
- 每种牌的张数、费用、位置、标签、效果模板、计分模板
- 后续若补齐官方素材，再补 `cardColorSymbol`、中文名、图片等字段

### 13.3 客户端交互层

- 树和边位的可视化
- 分割牌“选半张”的交互
- `Mole` 的多牌连打与支付分配 UI
- 洞穴、空地、冬季卡展示
- 终局计分明细展示

### 13.4 调试/回放层

建议强制保留完整日志，至少记录：

- 谁在何时选择了什么行动
- 从哪里抽了什么牌
- 支付了哪些牌
- 哪张牌以什么方式被打出
- 触发了哪些 effect / bonus / mushroom triggers
- 空地何时被清空
- 冬季卡何时出现
- 最终每张牌如何计分
