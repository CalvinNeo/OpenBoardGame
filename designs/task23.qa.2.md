# 《纸牌帮》电子版最终定案确认书 (Final Design Decisions)

收到。针对剩余的“可选项”，为了保证开发进度和逻辑闭环，现做出以下**最终定拍 (Final Decisions)**。请按此逻辑直接编写代码。

## 1. 超时处理 (Timeout Handling)

* **决策**：**超时自动锁定当前状态 (Auto-Lock Current State)**。
* **逻辑描述**：
    * 倒计时归零瞬间，系统强制触发“确认”操作。
    * 此时玩家摆成什么样，就按什么样结算。
    * *理由*：相比“直接判负”，这给了玩家最后一丝“瞎蒙蒙对”的机会，体验更公平；相比“随机锁定”，这尊重了玩家已有的操作成果。

## 2. 代币获取概率 (Token Drop Rate)

* **决策**：**可配置变量，默认值 50%**。
* **实现建议**：
    * 请在全局配置或常量文件中定义 `TOKEN_DROP_RATE = 0.5`。
    * 在结算逻辑中：
        ```python
        if is_perfect_win:
            if random.random() < TOKEN_DROP_RATE:
                team_resources.add_token(1)
        ```

## 3. 生命回复触发条件 (Health Regen)

* **决策**：**固定每通过 5 关回复 1 点 (Fixed Interval)**。
* **逻辑描述**：
    * 取消“Boss关卡”概念，简化开发。
    * 判定公式：`if (current_level_number % 5 == 0) then lives = min(lives + 1, max_lives)`。
    * *注意*：是“通过第5/10/15关后”触发，不是“进入第5关时”触发。

## 4. “完美通关”判定标准 (Perfect Clear Definition)

* **决策**：**严格判定 (Strict)**。必须同时满足以下 **3** 个条件：
    1.  **绝对排序正确**：玩家提交的排序与系统计算的 `Correct Rank List` 完全一致（在 Novice 模式下，不能依赖 ±1 的容错范围，必须精准命中）。
    2.  **未使用代币**：本关卡内未消耗任何“重置”或“窥视”代币（使用了代币算“辅助通关”，不产出新代币）。
    3.  **未使用容错生命**：(若未来有复活机制) 未发生过重试。
