# 《斯凯岛》（Isle of Skye: From Chieftain to King）基础版规则与电子版实现说明

> 说明
>
> - 本文只覆盖《斯凯岛》基础版，不包含 `Journeyman`、`Druids`、`Big Box` 新模块、Promo 地块、Tunnel/Themed Tiles。
> - 目标不是写一份“玩家速读版”，而是把规则拆到足以落地电子版的程度。
> - 我把内容分成三层：
>   - `规则已确认`：可由官方规则书或高可信辅助规则稳定确认。
>   - `实现推断`：规则书公开文本没有明确写死，但为了做电子版必须补上的实现约定。
>   - `缺失资源`：我这次没有拿到、因此不能负责任写死的数据或素材。
> - 主要依据：
>   - Lookout Games 官方产品页与官方英文规则书。
>   - Lookout `Big Box` 英文规则书中的基础版页。
>   - 一个玩家整理的 `Plain and Simple` 规则摘要，用来补足少量边界说明。
>   - UltraBoardGames 的基础版规则/计分页，用于交叉核对。

## 1. 游戏概述

《斯凯岛》是一款 `2` 到 `5` 人的私有领地拼图 + 定价/购买游戏。

每位玩家都扮演一个苏格兰氏族首领，在自己面前扩张一片独立的领地。每轮所有玩家都会：

1. 拿收入。
2. 从袋子里抽 `3` 块地形板块。
3. 秘密决定其中 `1` 块要丢弃，另外 `2` 块分别标价。
4. 按顺时针顺序，每人可从别的玩家那里买 `1` 块。
5. 把本轮得到的板块都拼进自己的领地。
6. 按当前回合激活的计分板块结算分数。

终局后还会进行一次“卷轴 + 金币”的最终计分。总分最高者获胜；若平分，则比较剩余金币。

这款游戏的核心不是“公共地图抢地”，而是：

- 私有地图拼接。
- 对自己板块的秘密定价。
- 猜别人会不会买、自己买不买得起。
- 根据本局抽到的 `4` 张计分板块，动态调整发展方向。

## 2. 基础版组件与范围

### 2.1 规则层真正重要的组件

基础版至少包含这些与规则相关的对象：

- `1` 个双面游戏板
  - 正面：`2` 到 `4` 人局
  - 背面：`5` 人局
- `16` 张计分板块
- `78` 张地形板块
  - 其中 `73` 张普通地形板块进入布袋
  - 其中 `5` 张城堡起始板块按玩家颜色分配，不进布袋
- `1` 个布袋
- 每位玩家各 `1` 个屏风
- 每位玩家各 `1` 个弃置标记
- 每位玩家各 `1` 个分数标记
- `1` 个回合标记
- `1` 个起始玩家标记
- 一批金币

### 2.2 电子版可忽略的物理差异

不同英文版本公开资料里，金币枚数有差异：

- 2015 基础版产品页写的是 `73` 枚金币。
- 2022 `Big Box` 基础版页里展示的是更多金币。

这不影响规则逻辑。电子版直接把金币建模为整数即可，不需要受物理币面额和总枚数限制。

### 2.3 本文默认的实现范围

本文按“基础版完整规则”来写，但有一个重要例外：

- `2-4` 人局：我拿到了足够清晰的回合轨信息，可以写死。
- `5` 人局：官方只明确写了“使用背面棋盘，并且总共 `5` 轮”，但我这次没有拿到背面棋盘的清晰回合轨扫描，因此无法可靠写死每轮激活的字母组合和补偿金币值。

所以如果你要立刻做电子版：

- `2-4` 人局可以直接照本文实现。
- `5` 人局建议在补齐背面棋盘数据之前先不开放。

## 3. 电子版必须建模的核心概念

### 3.1 领地坐标系

每位玩家有一张独立的“氏族领地”网格。每块地形板块占据一个整数坐标格。

建议以起始城堡板块为原点：

- 城堡板块坐标固定为 `(0, 0)`。
- 其正上方是 `(0, -1)`。
- 其正下方是 `(0, 1)`。
- 其正左方是 `(-1, 0)`。
- 其正右方是 `(1, 0)`。

这个坐标系非常重要，因为有一个计分板块要求计算“竖直方向连续列”，而官方说明是“竖直方向相对于起始城堡而言”。

### 3.2 地形类型与道路

基础地形边只有三种：

- `pasture` 草地
- `mountain` 山地
- `water` 水域

道路不是第四种边地形，而是叠加在地形上的连接结构。它影响：

- 金币收入
- 若干计分板块
- 与城堡连通的判定

但它不影响地块拼接合法性以外的地形闭合规则：

- 道路不需要续接。
- 道路不会像《卡卡颂》那样把区域切开。
- 卷轴和威士忌桶图标也不会阻断道路。

### 3.3 区域

电子版至少要维护两类连通结构：

1. `terrain area`
   - 同类地形通过边相连形成的区域
   - 用于“完成区域”“山地区域”“水域”等判定
2. `road network`
   - 道路通过边相连形成的网络
   - 用于“与城堡相连”的判定

`terrain area` 与 `road network` 必须分开建模，不能混为一谈。

### 3.4 完成区域（completed area）

官方规则里，完成区域的定义是：

- 一个地形区域被其它不同地形完全包围。
- 不能有边界直接暴露到空格。
- 道路不参与围合，也不分割区域。

实现上可写成：

- 对某个地形连通分量，检查它所有外边界。
- 只要有任意一条边通向“没有地块的空格”，它就未完成。
- 只要所有外边界都与已有地块接壤，且相邻边地形不同，则该区域已完成。

### 3.5 图标与归属

地块上会出现这些规则相关图标：

- `castle` 城堡
- `whisky` 威士忌桶
- `sheep` 绵羊
- `cattle` 牛
- `ship` 船
- `broch` 白色圆塔
- `farm` 农场
- `lighthouse` 灯塔
- `scroll` 卷轴

其中有些图标只按“图标数量”计分，有些按“所在 tile 数”计分，有些还要求知道它附着在哪个地形区域上。

例如：

- 威士忌收入按“与城堡道路连通的、带威士忌桶的地块数”算，不按桶图标数算。
- “最多威士忌”计分板块也按“带威士忌桶的地块数”算。
- 灯塔必须知道它邻接的是哪个水域。
- 卷轴必须知道它位于哪个地形区域中，才能判断是否因“处于完成区域”而翻倍。

### 3.6 隐藏信息

实体规则里，真正需要隐藏的是：

- 本轮屏风后的弃置选择
- 本轮两个地块的定价
- 玩家手里剩余、未分配出去的金币数量

电子版建议：

- `gold_total` 对玩家本人可见，对其他玩家默认隐藏。
- 本轮揭示后，两个公开售价变为公共信息。
- 玩家实际还能买得起什么，允许部分保持不透明，这更接近实体游戏。

## 4. 建议的数据结构

下面不是唯一方案，但已经足够支持基础版所有规则。

```ts
type Terrain = "pasture" | "mountain" | "water";
type Edge = "N" | "E" | "S" | "W";

type IconType =
  | "castle"
  | "whisky"
  | "sheep"
  | "cattle"
  | "ship"
  | "broch"
  | "farm"
  | "lighthouse"
  | "scroll";

type ScrollType =
  | "per_2_sheep"
  | "per_2_whisky_tiles"
  | "per_2_ships"
  | "per_cattle"
  | "per_broch"
  | "per_farm"
  | "per_lighthouse";

interface TileDef {
  id: string;
  kind: "start_castle" | "landscape";
  edges: Record<Edge, Terrain>;
  terrainRegions: TerrainRegionDef[];
  roadGraph: RoadNodeDef[];
  icons: IconDef[];
}

interface TerrainRegionDef {
  id: string;
  terrain: Terrain;
  touchesEdges: Edge[];
}

interface RoadNodeDef {
  id: string;
  exits: Edge[];
  connectedNodeIds: string[];
}

interface IconDef {
  id: string;
  type: IconType;
  terrainRegionId?: string;
  roadNodeId?: string;
  scrollType?: ScrollType;
}

interface TileInstance {
  instanceId: string;
  defId: string;
  rotation: 0 | 90 | 180 | 270;
}

interface PlacedTile {
  tile: TileInstance;
  x: number;
  y: number;
}

interface PlayerState {
  playerId: string;
  score: number;
  goldPrivate: number;
  territory: PlacedTile[];
  pricingArea?: PricingState;
}

interface PricingState {
  drawnTileIds: string[]; // 本轮抽到的3块
  discardTileId: string;  // 本轮准备丢弃的1块
  prices: Record<string, number>; // 另2块的售价
}

interface GameState {
  playerCount: 2 | 3 | 4 | 5;
  phase:
    | "setup"
    | "income"
    | "price_secret"
    | "price_reveal"
    | "discard"
    | "buy"
    | "build"
    | "round_scoring"
    | "final_scoring"
    | "ended";
  round: number;
  startPlayerIndex: number;
  scoringTiles: {
    A: string;
    B: string;
    C: string;
    D: string;
  };
  bagTileIds: string[];
  players: PlayerState[];
}
```

## 5. 开局流程

### 5.1 标准开局

1. 把游戏板放到桌面中央。
   - `2-4` 人使用正面。
   - `5` 人使用背面。
2. 洗混 `16` 张计分板块。
3. 随机抽 `4` 张，分别正面朝上放到 `A`、`B`、`C`、`D` 四个位置。
4. 其余 `12` 张计分板块放回盒中，本局不使用。
5. 回合标记放到回合轨的第一个位置。
6. 金币放到公共供应区。
7. 每位玩家选择一种颜色，并拿取：
   - `1` 个屏风
   - `1` 个城堡起始板块
   - `1` 个分数标记
   - `1` 个弃置标记
8. 每位玩家把自己的分数标记放到分数轨 `0` 分位置。
9. 每位玩家把自己的城堡起始板块正面朝上放到自己面前；这是其领地第一块。
10. 最年轻的玩家拿起始玩家标记并先手。
11. 将 `73` 张普通地形板块放入布袋并洗匀。

### 5.2 电子版实现建议

实体规则用“最年轻玩家先手”。电子版通常没有年龄信息，建议改为：

- 随机选起始玩家；或
- 由房主开始，然后每轮顺时针传递。

只要所有玩家都知道起始规则即可。

## 6. 回合结构

### 6.1 总轮数

- `2-4` 人局：共 `6` 轮
- `5` 人局：共 `5` 轮

每轮固定依序执行 `6` 个阶段：

1. `Income`
2. `Draw Tiles and Set Prices`
3. `Discard a Tile`
4. `Buy a Tile`
5. `Build`
6. `End of Round and Scoring`

最后一轮结束后，再做一次 `Final Scoring`。

### 6.2 第 1 阶段：收入

每位玩家本阶段收入为：

- 固定 `5` 金：来自城堡
- 额外收入：每个“通过道路与城堡连通”的威士忌地块 `+1` 金
- 从第 `3` 轮开始的落后补偿金：
  - 看当前回合轨上写的数字
  - 乘以“比分领先于你的其他玩家人数”

例如：

- 你当前落后于 `2` 名玩家
- 本轮回合轨写的是 `3`
- 你就额外获得 `2 x 3 = 6` 金

#### 2-4 人局已确认的回合轨

下表是我从官方基础规则书正面棋盘清晰图里确认出来的：

| 轮次 | 本轮计分字母 | 每个领先玩家给你的补偿金 |
| --- | --- | --- |
| 1 | `A` | `0` |
| 2 | `B` | `0` |
| 3 | `A + C` | `1` |
| 4 | `B + D` | `2` |
| 5 | `A + C + D` | `3` |
| 6 | `B + C + D` | `4` |

#### 5 人局现状

官方规则只明确：

- 使用背面棋盘
- 总共 `5` 轮

但我没拿到背面回合轨清晰图，所以目前不能负责任地写死：

- 每轮激活哪些字母
- 每轮补偿金币写多少

这属于本文最后“缺失资源”里的第一项。

### 6.3 第 2 阶段：抽地块并定价

每位玩家同时进行：

1. 从布袋中抽 `3` 块普通地形板块。
2. 将它们正面朝上排在自己屏风前。
3. 在屏风后秘密做两件事：
   - 把弃置标记放到其中 `1` 块上
   - 给剩余 `2` 块分别放上金币，作为售价

规则限制：

- 准备出售的这 `2` 块，每块至少要标 `1` 金。
- 没有分配出去的剩余金币继续由玩家自己保留，并且应当隐藏。
- 等所有玩家都做好后，同时移开屏风。

### 6.4 第 3 阶段：弃置 1 块

每位玩家把被自己弃置标记标记的那块板块放回布袋，然后重新洗匀布袋。

重要：

- 基础版没有“公共弃牌堆”。
- 被弃置的板块是回到袋中，不是永久离场。

### 6.5 第 4 阶段：购买 1 块

从起始玩家开始，按顺时针顺序，每位玩家轮到自己时可以：

- 从别的玩家那里的公开待售地块中买 `1` 块；或
- 选择 `pass`

购买规则：

- 只能买“别的玩家”的地块，不能买自己的。
- 购买价等于卖家先前在该地块上放的金币数。
- 买家用自己剩余的私有金币支付。
- 卖家会得到两部分金币：
  - 买家付来的钱
  - 自己原先压在该地块上的定价金币

买到的地块先放到自己一旁，等到建造阶段再统一拼进领地。

如果某位玩家选择 `pass`：

- 该玩家本轮失去购买机会，不能之后再补买。
- 但他仍然可以继续被后续玩家购买他的待售地块。

当所有玩家都已完成“买 `1` 块或放弃”后：

- 每位玩家自动获得自己面前仍未被买走的待售地块。
- 但是这些地块上自己压的定价金币全部失去，退回公共供应区。

也就是说，未卖出的地块相当于“你以自己定的价格买下了它们”。

### 6.6 第 5 阶段：建造

所有玩家把本轮得到的所有地块都加入自己的领地。

放置规则：

1. 每块新地块必须至少与自己领地中已有的 `1` 条边相邻。
2. 这个“已有地块”可以是你更早回合放下的，也可以是你本建造阶段刚放下的。
3. 若两块地块边对边相邻，则对应边的地形类型必须一致：
   - 草地对草地
   - 山地对山地
   - 水域对水域
4. 道路不要求续接。
5. 卷轴和威士忌图标不阻断道路。
6. 若某块地块无论如何都不能合法放置，则它直接回到布袋，且不会退钱。

如果一位玩家本轮要放多块地块：

- 可以自己决定放置顺序。
- 这个顺序可能影响后续地块是否能被合法接上，因此必须交给玩家选择。

### 6.7 第 6 阶段：回合结算

本轮根据回合轨当前碗位下面的彩带，结算对应字母的计分板块。

规则要点：

- 若本轮有多张计分板块生效，它们彼此独立结算。
- 玩家按所得分数前进分数标记。
- 多数类计分若要拿分，玩家至少要有 `1` 个对应要素。
- 若计分后未结束游戏，则：
  - 起始玩家标记顺时针传给下一位
  - 新起始玩家把回合标记前移 `1` 格

## 7. 地块放置与图结构实现细则

### 7.1 地块旋转

`实现推断`

公开可检索的官方文本里，我这次没有找到一句明确写成“地块可旋转、不可翻面”。但数字版公开介绍和实际玩法描述都默认存在旋转。

电子版建议固定为：

- 允许 `0 / 90 / 180 / 270` 四种旋转
- 不允许镜像翻转

如果后续拿到更明确的官方句子，可以把这条从“实现推断”升级为“规则已确认”。

### 7.2 城堡道路连通

“与城堡连通”不是指“地块跟城堡相邻”，而是指：

- 存在一条道路网络
- 从城堡所在道路节点出发
- 经过连续续接的道路边
- 抵达目标图标所在 tile 或目标 tile 本身

因为道路不要求在拼图时必须接上，所以会经常出现：

- 地块拼法合法
- 但道路其实在某个边界断掉
- 因而不算与城堡连通

### 7.3 完成区域与道路的关系

道路不参与“完成区域”的围合，也不切断区域。

这意味着在判定：

- 完成山地
- 完成水域
- 完成任意地形区域

时，都只看地形边界，不看道路走向。

### 7.4 图标的计数单位

实现时必须区分以下三种不同的计数单位：

1. `图标数`
   - 如羊、牛、船、broch、farm、lighthouse
2. `含该图标的地块数`
   - 如威士忌收入、威士忌多数
3. `区域数 / 区域面积 / 列数 / 2x2 方块数`
   - 如完成区域、最大水域、竖列、四宫格

不能把“带威士忌桶的地块数”误写成“威士忌桶图标数”。

## 8. 16 张基础计分板块的可实现定义

以下都按“单张计分板块各自独立结算”理解。

### 8.1 `2` 分每个 `2x2` 方块

效果：

- 每形成一个由 `4` 块地块组成的正方形，得 `2` 分。

实现：

- 在玩家坐标网格中，枚举所有可能左上角 `(x, y)`。
- 若 `(x, y)`、`(x+1, y)`、`(x, y+1)`、`(x+1, y+1)` 四格都有 tile，则记 `1` 个方块。
- 总分 = 方块数 `x 2`。

边界：

- 同一块地块可以同时属于多个 `2x2` 方块。

### 8.2 `1` 分每个完成区域

效果：

- 每个完成的地形区域得 `1` 分。

实现：

- 统计完成的 `pasture`、`mountain`、`water` 连通区域总数。

### 8.3 `1` 分每只羊

效果：

- 领地中每个羊图标 `+1` 分。

### 8.4 `3` 分每个至少 `3` 块地块的完成区域

效果：

- 每个“已完成且覆盖至少 `3` 块地块”的地形区域得 `3` 分。

实现：

- 先找完成区域。
- 再看该区域跨越了多少个不同 tile。
- 若 `>= 3`，该区域记 `3` 分。

### 8.5 山地区域中的 broch 计分

效果：

- 每个山地区域按其中 broch 数量得分：
  - `1` 个 broch：`1` 分
  - `2` 个 broch：`3` 分
  - `3` 个及以上 broch：`6` 分

实现：

- 对每个 `mountain area` 统计其中 broch 图标数。
- `>= 3` 一律按 `6` 分，不再继续增加。

### 8.6 `5` 分每组 `broch + farm + lighthouse`

效果：

- 每凑齐一组 `broch`、`farm`、`lighthouse`，得 `5` 分。

实现：

- 分别统计三种建筑图标总数。
- 组数 = `min(brochCount, farmCount, lighthouseCount)`
- 总分 = 组数 `x 5`

边界：

- 每个建筑图标最多参与一组。

### 8.7 威士忌多数

效果：

- “拥有最多带威士忌桶地块”的玩家得 `5` 分。
- 第二多得 `2` 分。

实现：

- 统计每位玩家“含至少 `1` 个威士忌桶图标的地块数量”。
- 不是统计桶图标个数。

平局规则：

- 并列第一：所有并列第一都得 `5` 分，`2` 分不发。
- 并列第二：所有并列第二都得 `2` 分。
- 若玩家一个威士忌地块都没有，则没有资格拿这张计分板块的分。

### 8.8 船只多数

效果：

- 船最多的玩家得 `5` 分。
- 第二多得 `2` 分。

实现：

- 按船图标总数比较。

平局规则与资格要求同上：

- 并列第一都得 `5` 分，`2` 分不发。
- 并列第二都得 `2` 分。
- 至少要有 `1` 艘船才有资格得分。

### 8.9 农场邻近动物计分

效果：

- 每只与某个农场正交或对角相邻的羊/牛 `+1` 分。
- 位于“含农场图标的地块”上的羊/牛也 `+1` 分。

已确认的关键边界：

- 动物不必与农场处于同一地形类型。
- 每只羊/牛最多只得 `1` 分。
- 即使它同时在农场地块上、又邻接多个农场，也仍然只得 `1` 分。

实现：

- 对每个羊/牛图标，只计算一个布尔值：
  - `onFarmTile` 或 `adjacentToAnyFarm`
- 若为真，则该动物贡献 `1` 分。

### 8.10 金币多数

效果：

- 本轮结算时金币最多的玩家得 `5` 分。
- 第二多得 `2` 分。

实现：

- 比较本轮结束计分时玩家手里的当前金币数。
- 不是终局金币，不是历史总收入。

平局规则：

- 并列第一：都得 `5` 分，`2` 分不发。
- 并列第二：都得 `2` 分。
- 至少要有 `1` 金才有资格得分。

### 8.11 与城堡道路连通的牛

效果：

- 每只“其所在地块被城堡道路网络穿过”的牛得 `2` 分。

已确认边界：

- 道路必须真正经过牛所在地块。

实现：

- 先求出从城堡出发的道路连通 tile 集合。
- 对集合中的每个 tile，统计其中牛图标数量。
- 总分 = 牛图标数 `x 2`

### 8.12 带船且带灯塔邻接的水域

效果：

- 每个满足以下条件的水域得 `3` 分：
  - 该水域中至少有 `1` 艘船
  - 该水域至少邻接 `1` 个灯塔

已确认边界：

- 同一个水域即使同时有多个船/多个灯塔，也只计 `1` 次。
- 灯塔在规则语义上位于该水域岸边。

实现：

- 对每个 `water area`：
  - `hasShip = true/false`
  - `hasAdjacentLighthouse = true/false`
- 若都为真，该区域得 `3` 分。

### 8.13 与城堡道路连通的地块

效果：

- 每块与城堡通过道路连通的地块得 `1` 分。

已确认边界：

- 道路必须穿过该地块，才能算这块地块被连接到城堡。

`实现推断`

- 我建议把起始城堡地块也算作“与城堡连通的地块”，因为道路网络起点就在此地块中。
- 如果你后续拿到官方 FAQ，可以把它做成房规开关；但在没有反例时，我会这样实现。

### 8.14 竖直连续列

效果：

- 每条“至少 `3` 块连续地块组成的竖直列”得 `3` 分。

已确认边界：

- “竖直”是相对于起始城堡方向而言。
- 每一列最多只计 `1` 次分。

实现：

- 以 `x` 坐标为“列”。
- 对每个固定的 `x`，检查该列中是否存在长度 `>= 3` 的连续 `y` 段。
- 若存在，该列得 `3` 分。
- 同一列即便有两段符合条件，也只得一次 `3` 分。

### 8.15 最大完成水域

效果：

- 你最大的完成水域中，每块地块得 `2` 分。

实现：

- 找到所有完成的 `water area`
- 求它们覆盖的 tile 数
- 取最大值 `maxSize`
- 得分 = `maxSize x 2`

`实现推断`

- 官方公开文本没有给出“若有多个并列最大完成水域，是否全部计分”的补充说明。
- 我建议按“只取一个最大尺寸值”处理，也就是只用 `maxSize` 乘一次，而不是把多个并列最大区域相加。

### 8.16 完成山地区域

效果：

- 每个完成的山地区域得 `2` 分。

实现：

- 统计所有完成的 `mountain area`
- 总分 = 完成山地区域数 `x 2`

## 9. 终局与卷轴计分

最后一轮结算完毕后，立即进行最终计分。

### 9.1 卷轴板块

所有带卷轴图标的地块，按卷轴类型得分。

基础版公开可确认的卷轴共有 `7` 类：

1. 每 `2` 只羊 `1` 分
2. 每 `2` 块带威士忌桶的地块 `1` 分
3. 每 `2` 艘船 `1` 分
4. 每 `1` 只牛 `1` 分
5. 每 `1` 个 broch `1` 分
6. 每 `1` 个 farm `1` 分
7. 每 `1` 个 lighthouse `1` 分

实现规则：

- 同类卷轴会叠加，各算各的。
- `每2个` 类型都应向下取整。
  - 例如 `5` 只羊，只得 `2` 分，不是 `2.5` 分。

### 9.2 卷轴翻倍

如果某个卷轴图标位于一个完成区域中，则该卷轴本身的得分翻倍。

重要：

- 是“这个卷轴的分数翻倍”，不是整局分数翻倍。
- 电子版必须知道该卷轴附着在哪个地形区域上，所以 tile 数据里要记录 scroll 所属 region。

### 9.3 金币换分

最终每 `5` 金换 `1` 分，向下取整。

例如：

- `14` 金 = `2` 分，剩 `4` 金

### 9.4 胜负

- 分数最高者获胜。
- 若平分，则比较金币换分后剩余的金币数。

## 10. 电子版状态机建议

建议把游戏流程拆成下面的离散状态：

```ts
setup
-> income
-> price_secret
-> price_reveal
-> discard
-> buy
-> build
-> round_scoring
-> (next round -> income) | (if last round -> final_scoring)
-> ended
```

### 10.1 `price_secret`

玩家并行操作：

- 抽到的 `3` 块已经公开可见
- 但弃置选择和两个售价对别人不可见

### 10.2 `price_reveal`

所有人同时翻开：

- 哪块要丢
- 哪两块卖多少钱

### 10.3 `buy`

这是顺序阶段，必须按顺时针 one-by-one 执行：

- 当前行动玩家可以选“买哪块”或“pass”
- 系统实时更新可售池
- 被买走的地块立刻从卖家前方消失

### 10.4 `build`

可以设计成：

- 所有人同时本地预摆，然后一起提交；或
- 逐个确认放置

但要注意：

- 若本轮玩家有多块要放，顺序会影响可放性
- 所以前端至少要允许玩家逐块确认

## 11. 容易写错的点

1. 道路不要求续接，但“与城堡道路连通”仍然要真的连得上。
2. 被弃置的地块回布袋，不是弃牌堆。
3. 未卖出的地块会回到你手上，但你压在上面的金币要失去。
4. 合法拼图只检查边地形，不检查道路。
5. 卷轴和威士忌桶不会阻断道路。
6. 威士忌收入与威士忌多数，都是按“带桶的地块数”而不是桶图标数。
7. 农场邻近动物计分时，每只动物最多只拿 `1` 分。
8. 同一水域即使有多个船和多个灯塔，也只按该水域记 `1` 次。
9. 竖直列计分时，每列最多只记一次。
10. 卷轴翻倍只翻该卷轴本身，不翻金币换分，也不翻其它卷轴。
